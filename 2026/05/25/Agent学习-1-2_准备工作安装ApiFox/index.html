1-2_准备工作安装ApiFox

|浏览量:

摘要

整集只做一件事：把”后端接口的脚手架”搭起来，给后面所有要跟 Java 后端对话的章节留一个稳定入口。读完你应该掌握的是 ApiFox 的心智模型——团队/项目/接口的三层组织，再叠一个正交的”环境”维度，而不是某几个按钮在哪里。

  • 取舍出现在 §2：放弃按视频的”先建项目再讲环境”顺序，改成”先把环境心智立住，再创建接口”，因为前者会让第一次选环境时是空下拉，留下卡点。
  • 加工增量在 §3 与 §5：把”环境”和”接口路径”的关系画成拼接示意图（understanding 里只有文字描述），并把 GET/POST 的参数落点从一句话扩成”为什么 UI 强迫分两个 tab”的解释。

§1 一句话定位

ApiFox 是把 Postman + Swagger + Mock + JMeter 揉成一个面板的接口协作平台，本集是为后续后端章节准备的”调用入口”。

§2 主体讲解

2.1 为什么不是 Postman

如果你已经在用 Postman，那你应该把 ApiFox 看成”Postman 的功能 + Swagger 那一份接口文档 + Mock 数据生成 + 一点点压测”的合体。这意味着同一个项目里，接口文档、调试请求、Mock 返回值、自动化测试用例是共用同一份接口定义的——你不需要在 Swagger 里看一遍、再在 Postman 里抄一遍、再在 Mockoon 里造一份数据。本集只用它最浅的一层：调试接口。

2.2 先把”环境”立成心智

这是本集最重要、也最反直觉的概念，必须在创建任何接口之前就理解：

一个环境 = 一组”服务前置 URL” + 一组环境变量。

ApiFox 默认给你 6 个环境：开发 / 测试 / 正式 / 本地 Mock / 云端 Mock / 自托管 Mock。它们不是标签，而是 6 个独立的配置面板，每个里面都有自己的”前置 URL”。选环境，本质是切换前缀。

如果不先理解这一层，后面创建接口时那个”选择环境”的下拉框对你是空的，你会很自然地想去把完整 URL 写进接口路径——这是最大的坑。

课程的开发环境设置成 127.0.0.1:8888。记住这个端口号，后面写 Spring 后端时它必须对得上。

2.3 三层组织：团队 → 项目 → 接口

理解了环境之后，三层组织就只是 CRUD：

  • 团队：顶层组织单位，本课叫 Imooc。
  • 项目：团队下的工程，类型选 HTTP（另有 gRPC Beta / Dubbo Beta，本课不用），本课项目名 行程规划智能体。
  • 接口：项目下的最小单位。

2.4 接口与环境绑定的关键瞬间

新建接口时，接口路径只写 /test-imooc 这一段相对路径，绝对不要写 http://...。前面那段 http://127.0.0.1:8888 是由当前选中的环境注入的。

验证方式很简单：保存接口后点”运行”，地址栏里会出现完整 URL http://127.0.0.1:8888/test-imooc——这就是”前置 URL + 接口路径”被拼起来的现场证据。这一步是把抽象落地的唯一机制证据，请你亲自点一遍。

2.5 GET 与 POST 的参数落在哪

切换请求方法只是改方法名，参数应该填在哪个 tab，得看是 GET 还是 POST：

  • GET → Params 标签，参数被拼到 query string，例如 ?id=1。
  • POST → Body 标签，再从 form-data / x-www-form-urlencoded / json / xml / raw / binary / GraphQL / msgpack 里挑一种 content-type。

这其实就是 HTTP 的常识，但 ApiFox 用两个 tab 把它强制分开了——如果你下意识把 POST 的 JSON 体填到了 Params，请求会发出去，但后端永远收不到你以为的那份数据。Header / Cookie / Auth / 设置各自有独立 tab，不要塞错位置。

§3 我一开始没 get 的点

  1. “环境”不是标签，是一组独立面板。如果你把它当成 Postman 里某个下拉的字面值，会得到错的结果——你以为切了环境，其实只是改了显示名字，但前置 URL 没跟着切。正确心智是”6 个面板，每个里面独立填前置 URL，选环境=切前缀”。
  2. 接口路径写完整 URL 是最高频坑。如果你写 http://127.0.0.1:8888/test-imooc 进接口路径，环境注入会再拼一遍前缀，得到 http://127.0.0.1:8888http://127.0.0.1:8888/test-imooc 这种荒谬地址，或者直接报错。
  3. POST 的参数不在 Params。如果你 POST 时把 JSON 放进 Params，它会作为 query string 发出去，body 是空的，后端 @RequestBody 收到的就是 null——这种 bug 排查起来最费时间。
  4. ApiFox 是后端开发自己用，不是甩给测试。它打通了”写接口文档 → 自测 → Mock 给前端 → 跑自动化”全链路，所以本课让后端开发先把它装好，是为后面”我自己写完接口、自己点一下就知道通不通”的工作流铺路。

§6 自测题

Q1（概念回忆） ApiFox 用一个等式自我介绍，这个等式是什么？
A1：ApiFox = Postman + Swagger + Mock + JMeter。在 §2.1 / 图 f001。

Q2（概念辨析） “环境”在 ApiFox 里到底是什么？它和 Postman 的 environment 有什么对应关系？
A2：一个环境是一组”服务前置 URL + 环境变量”的容器，预置 6 个面板（开发/测试/正式/本地 Mock/云端 Mock/自托管 Mock），切环境的本质是切换前置 URL 前缀。它对应 Postman 的 environment 概念，是同物异名。在 §2.2 / understanding.md 第一遍卡在哪。

Q3（反直觉陷阱） 你创建了一个接口，接口路径填的是 http://127.0.0.1:8888/test-imooc，选了开发环境，点运行报错或地址重复。原因是什么？正确做法？
A3：环境会自动注入前置 URL，接口路径只应写相对部分 /test-imooc，让运行时拼成完整 URL。在 §2.4 / §3 第 2 条 / 图 f030 / 图 f035。

Q4（跨集连接） 本集为什么把开发环境的端口钉成 8888？后续哪一类章节会和它对上？
A4：8888 是与后续 Spring 后端的 server.port 形成的契约。后面 5-3 行程规划经理、11-x A2A、12-x Skills 等涉及打 HTTP 接口验证的章节，会从 ApiFox 直接调 8888 端口的本地后端。在 §4 下启。

Q5（应用推广） 同一个接口要在本地 Mock、本地真服务、远端正式三个地方都验一遍，怎么用 ApiFox 的概念最省事？
A5：接口只写一份（路径用相对路径），分别在”本地 Mock / 开发 / 正式”三个环境里配各自的前置 URL，切环境就能切目标，不需要复制三份接口。在 §2.2 + §5 知识地图（这是基于环境正交维度的推广，understanding.md 中未直接展开）。
