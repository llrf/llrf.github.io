1-6_仿Manus能自主决策的框架Jmanus

发表于2026-05-25|更新于2026-05-25|Agent学习第01章 AI 正式进入多 Agent 协作和自主决策的时代
|浏览量:

摘要

JManus = 阿里把”多 Agent 自主决策”塞进 Spring Boot 给你跑的 Java 版 OpenManus。本集只做一件事：跑通它，然后从日志里抓到”两个 agent 是 LLM 临时决定要派的”这条证据。取舍出现在 §2（原始顺序是百炼回顾 → Manus 故事 → 谱系 → 跑通；我打散重排成：谱系 → 跑通 → 回头补 API Key 来源，把”自主决策的物证”留在最重的位置）；加工增量在 §3（”用户目录 vs inner_storage” 这条 prompt 与落盘的语义错位，是 understanding.md 没强调但一年后必定迷糊的点）。

§1 一句话定位

JManus 是阿里基于 OpenManus 思路、用 Java 重写的”多 Agent 自主决策”开发框架。

§2 主体讲解：从谱系到闭环，再到那条关键日志

2.1 先把谱系搞清，不然你会以为是阿里原创

你看到”JManus”第一反应大概率是”Java + Manus”。这没错，但中间漏了一环。真实链路是三段式：

为什么要从 Manus 讲起？因为 Manus 之所以炸圈，不是因为”多 Agent”这个词新鲜——而是因为它能自己决定要派几个 agent、派哪几个去干活。你说”帮我买东西”，它会自动拉起”挖偏好的 + 比价的 + 下单付款的”三个 agent。这就是”自主决策”四个字的意思。本集你跑的 demo 就是这个能力的最小可见版。

2.2 仓库结构：spring-ai-alibaba 是 monorepo，不是单一项目

打开 alibaba/spring-ai-alibaba 的 GitHub 页，你会看到一长串 spring-ai-alibaba-* 子目录：-bom / -core / -deepresearch / -graph-core / -jmanus / -mcp / -nl2sql / -prompt / -spring-boot-starters / -studio……一个仓库塞了十几个独立工程。这是 monorepo 风格——SAA（spring-ai-alibaba 的简称）是阿里把所有”Spring AI 周边”都丢一块的伞。

你只关心 jmanus，所以下载整个 zip 解压之后，把其它子目录全删掉，只留 spring-ai-alibaba-jmanus 一个文件夹。这一步占了本集 80% 的”操作”内容，代码层面零改动。

2.3 跑通最小闭环（这才是本集的”灵魂操作”）

把 spring-ai-alibaba-jmanus 用 IDEA 当成项目导入：

  • File → New → Project From Existing Sources，JDK 显式选 17（这是硬要求，不是建议）
  • 等 Maven 把依赖拉完
  • 找到 src/main/java/com/alibaba/cloud/ai/example/manus/OpenManusSpringBootApplication，run

反直觉的命名：启动类不叫 JManusApplication，叫 OpenManusSpringBootApplication。 名字本身就暴露了”我是 OpenManus 的 Java 复刻”这件事——阿里没改名字。

启动日志里会看到这两条关键信息：

第一条告诉你它自带 web 界面（端口 18080，不是常见的 8080）。第二条告诉你 API Key 不放在 yaml 里，走 web 初始化页配——浏览器打开后是两步向导：

  1. 选语言（简体中文）
  2. 选模型（阿里云百炼）+ 填 API Key

API Key 哪来？1-5 集申请的那把，直接复用。本集第一步反复念叨”百炼平台 / API Key 申请”其实是 1-5 的回顾，跳过即可。

2.4 工作台 + 一个 prompt

配完 Key 进工作台，你会看到 5 个示例卡片：

注意每个卡片右下角有两种标签：message 和 plan-act。视频里没展开这两个的区别，但这就是 JManus 的两种执行模式——直接对话 vs 先规划再执行（PLAN-ACT 计划模式）。本集要跑的属于 plan-act 流派（页面底下默认选项也是它），对应的就是 8-6 / 8-7 要讲的 Plan-and-Execute 架构。

跑这条 prompt：

通过百度查询阿里巴巴最新股价，将结果保存到用户目录本地文件

回车，等几十秒，UI 上会冒出两段 “completed” 块。这两段就是本集要看的全部成果。

2.5 关键证据：日志里 Create new BaseAgent

UI 的步骤面板告诉你结果，但**”自主决策”的证据藏在日志里**。把 IDEA Run 控制台的 infoLog 复制出来，搜关键词 Create new：

你会刚好搜到两条：

这两行就是”自主决策”的全部物证。你没在任何配置里写”用 2 个 agent”，也没指定要用 BROWSER 和 DEFAULT——是 LLM 看完你的 prompt 后，决定拉这两个出来干活。换一个 prompt，可能就是 1 个、3 个、或者别的组合。

每个 agent 启动时还会打一串 Registering tool: xxx，告诉你这个 agent 拿了哪些工具：

  • BROWSER_AGENT：browser_use（开浏览器抓页面）
  • DEFAULT_AGENT：text_file_operator / bash / terminate / inner_storage_content_tool / file_merge_tool / form_input ... 一打子，是个万金油

UI 里看结果就一目了然了：

第 0 步 BROWSER_AGENT 去百度搜出股价，第 1 步 DEFAULT_AGENT 把结果挑出来写进文件。两个 agent 一前一后，中间靠 planId 串起来——这就是”多 Agent 协作”的最小可观察形态。

§3 我一开始没 get 的点 / 容易踩的坑

1. “用户目录”不是你的 C:\Users\xxx，是 extensions/inner_storage/。
prompt 写”保存到用户目录本地文件”，你以为会落到桌面或者家目录，结果它去了 spring-ai-alibaba-jmanus/extensions/inner_storage/ 下，文件名 alibaba_stock_price.txt。这是 DEFAULT_AGENT 的 text_file_operator 工具有沙箱根——prompt 说”用户目录”它也只能写在沙箱里，JManus 不会真把你的 LLM 放出来乱写盘。这条 understanding.md 里没强调，但是个一年后看回来必定迷糊的点。

2. “Open” 是开源的 Open，不是”Manus 的开放版”。
OpenManus 是社区项目，跟 Manus 公司没关系。阿里基于 OpenManus 的思路用 Java 重写出 JManus，所以 JManus 的爹是 OpenManus 不是 Manus 本尊。这层关系一旦倒着想就会觉得”阿里凭啥用人家名字”——其实没用，OpenManus 本身就是开源 Python 项目。

3. JDK 必须 17，不是 11，不是 21。
IDEA 导入时容易顺手用默认 JDK，跑不起来。导入向导那一步显式选 JDK 17。

4. 端口是 18080 不是 8080，且会自动开浏览器。
启动完别去敲 localhost:8080，看日志拉到最下面找 http://localhost:18080/ui/index.html。理论上启动结束会自动弹浏览器；如果没弹，自己复制粘贴。

§4 跟其他集的连接

上承

  • 1-5 阿里百炼平台 / API Key 申请——本集第一步就把那把 Key 填进 JManus 的 web 初始化页（选”阿里云百炼”模型）。1-5 集那把 Key 不是用了一次就过期的”考试用品”，整个第 1 章、第 3 章、第 4 章都靠它。
  • 3-11 / 3-12（在 INDEX 里已经记过）——3-11 给了”主流多 Agent 框架”全景图，把 Manus / OpenManus / JManus 三个名字摆在一起；3-12 给了”多 Agent 五步骨架”。本集是把那两集的抽象用一个能跑的 demo 实体化。

下启

  • 本集最后留了一句”在後面的課程中，我們將對 JManus 這個開發框架進行深度的學習”。这条线索对应 INDEX 里的：
    • 8-9 JManus 文件架构 + Prompt 提交入口——告诉你 web 里那个发送按钮背后调的是 ManusController.executeQuery。
    • 8-10 计划协调器——把本集 UI 上看到的”步骤执行详情”拆开来看是哪个 Java 类在调度。
    • 8-11 PlanCreator——回答本集留下的”为什么这次派 2 个 agent 而不是 1 个或 3 个”——是 LLM 直接出 JSON 计划。
  • 3-6 / 4-8——给本集这个裸跑的 JManus 挂 MCP 服务，把工具池从默认的几个扩到几十个。

横向

  • 8-5 Manus 是自主决策的 AI Agent——8-5 讲的”两个自循环”（外层 plan 自循环 + 内层 agent 自循环），本集 demo 里 BROWSER_AGENT + DEFAULT_AGENT 协作就是它的最小可见表现。
  • 3-12 多 Agent 五步骨架——本集示例是那张骨架图的一个实例：plan 创建（PlanCreator）→ 派 agent（BROWSER_AGENT）→ 收结果 → 再派 agent（DEFAULT_AGENT）→ 汇总 → 完成。

§5 知识地图

§6 自测题（5 张 Q-A 卡）

Q1. JManus、OpenManus、Manus 三者的关系是？
A1. Manus 是闭源商品（”帮我买东西”那个），OpenManus 是社区用 Python 开源复刻它的多 Agent 思路，JManus 是阿里基于 OpenManus 用 Java 重写、住在 spring-ai-alibaba 仓库 spring-ai-alibaba-jmanus 子目录里的版本。”Open” 指开源，不是 Manus 出的开放版。

Q2. 怎么证明 JManus 是”自主决策”而不是”配置好的固定流程”？
A2. 把 IDEA 控制台日志拷出来搜关键词 Create new BaseAgent。本集示例搜到两条 BROWSER_AGENT + DEFAULT_AGENT，且都属于同一个 planId。这两个 agent 不是配置里写死的，是 LLM 看完 prompt 后临时拉起来的——换 prompt 数量和类型都会变。

Q3. 跑 JManus 之前要踩哪三个坑？
A3. ① JDK 必须显式选 17；② 端口 18080 不是 8080；③ API Key 走 web 初始化页配，不是 yaml。

Q4. prompt 写”保存到用户目录本地文件”，文件实际落到哪里？为什么？
A4. 落到 spring-ai-alibaba-jmanus/extensions/inner_storage/ 下（如 alibaba_stock_price.txt），不是用户家目录。因为 DEFAULT_AGENT 的 text_file_operator 工具有沙箱根——LLM 不会真被放出来乱写盘。

Q5. spring-ai-alibaba 仓库为什么要”下载整包再删剩 jmanus 一个目录”？
A5. SAA 是 monorepo，一个 GitHub 仓库里塞了十几个独立子工程（-bom / -core / -mcp / -nl2sql / -graph-core / -studio / -jmanus / ...）。GitHub 不支持只下载某个子目录，所以你只能下整包，留下你要的那个。
