1-7_具备ReAct核心能力的框架AgentScope

发表于2026-05-25|更新于2026-05-25|Agent学习第01章 AI 正式进入多 Agent 协作和自主决策的时代
|浏览量:

摘要：本集是第 1 章地图收尾——给 Agentic 那条分支配上一个真正能用的 Java 框架。取舍出现在 §2（把官方四亮点重排成”为什么选它”的两段论），加工增量在 §2.2（JManus vs AgentScope 的差异表是 understanding.md 里没有的列式对照）和 §4.3。

1. 一句话定位

Agentic 分支的 Java 落地框架，把 ReAct + 人可介入打包好了。

2. 主体讲解

2.1 先把 ReAct 想清楚，再看框架

绕开框架名先问自己：智能体要”自主”完成一个任务，最少要循环哪几步？

思考 → 行动 → 验证 → 不对就重新思考。这四步循环一直跑到结果跟你预设目标对齐为止，就是 ReAct（Reason and Action）。

注意 transcript 里反复出现的 “weat” 是 ASR 把 “ReAct” 听岔的，看到当 ReAct 读就行。这个范式不是 AgentScope 发明的，1-6 讲的 JManus 也是 ReAct——所以 ReAct 不是 AgentScope 的差异点，而是它的入场券。

这张脑图是整个第 1 章的总目录。你只要记住右半边那条分支：Agentic 为核心 → AgentScope（SpringAI Alibaba 生态）→ 旅游规划项目。左半边的 JManus 是 1-6 的主角，右半边的 AgentScope 就是本集的主角。两者并列在”自主代理设计思想”下，本集要做的事就是把右边这个分支具体化。

2.2 AgentScope 凭什么是 JManus 的”升级版”

官方文档只丢了一句”AgentScope 比 JManus 优秀”，但没把对比说清楚。你需要自己列张表才能消化（加工增量）：

维度 JManus（1-6） AgentScope（1-7）
推理范式 ReAct ReAct
出身 Manus 的 Java 复刻 阿里同义实验室 + Spring AI Alibaba 1.1
出现时间 早 晚
人能否中途插手 不能，全自动 能，安全中断 / 优雅取消 / Hook
工程化 异曲同工 Project Reactor 响应式 + GraalVM 200ms 冷启动 + Runtime 安全沙箱
多 Agent 协同 内部协同 A2A 协议注册到 Nacos

记住中间那两行就够了——“人能不能插手” + “工业化程度” 是你选 AgentScope 而不是 JManus 的真正理由。”它更新更优秀”是废话，”它让人能在任意推理步骤插一个 Hook 改主意”才是答案。

2.3 文档自报的四个亮点，按重要度重排

官方排序是：智能体自主可控 / 内置工具 / 无缝集成 / 生产级。这个顺序对市场友好，对学习不友好。我按”理解深度”重排：

① 自主 + 可控（核心矛盾）
“自主”和”可控”本来是冲突的——智能体越自主，你越没法干预。AgentScope 的答案是三件套：

  • 安全中断：在任意时刻 pause Agent 执行，保留完整上下文 + 工具状态，可无损恢复
  • 优雅取消：kill 掉一个跑飞的工具调用，但不毁掉 Agent 状态，可立即重定向
  • 人机协作 Hook：在任何推理步骤注入修正、补上下文、给指导

这三件套是 AgentScope 的唯一卖点。后面 11 章旅游规划项目能让人在 Agent 跑到一半改路线，就是靠 Hook。

② 生产级（工业化护城河）
这块的内容很硬：

  • Project Reactor 响应式架构 → 非阻塞执行
  • GraalVM 原生镜像编译 → 200ms 冷启动 → 适合 Serverless / 自动扩缩容
  • AgentScope Runtime 安全沙箱 → 单 Agent 隔离执行，一个挂了不传染整个工作流

第三条和 JManus 的容错”异曲同工”，但 GraalVM 那条是 JManus 没有的。

③ 内置工具（先点名，后续展开）
本集只是把名字念了一遍，你记住四个钩子就行，后面章节会一个个回来：

  • PlanNotebook —— 把复杂目标拆成有序、可追踪、可暂停可恢复的步骤
  • 结构化输出 —— 自纠错解析器，LLM 输出偏格式时自动检测并引导重出，直接映射到 Java POJO
  • 长期记忆 —— 跨会话持久化 + 语义搜索 + 多租户隔离
  • RAG —— 自托管 embedding 检索，或对接阿里云百炼

④ 无缝集成

  • MCP 协议：接任何 MCP 兼容服务器（文件系统、数据库、浏览器、代码解释器）
  • A2A 协议：分布式多 Agent 协作，AgentCard 注册到 Nacos，Agent 之间像调微服务一样互相发现

2.4 落地动作：两条 pom 依赖就够了

本集真正动手的部分极其轻量。新建一个 Maven 项目，pom 里只塞两条：

两件事要记：

  1. JDK 17 起步——不是 11，是 17。
  2. AgentScope 用 SLF4J 接口写日志，自己不带实现——所以 logback-classic 不是可选项，是配套义务。你也可以换 Log4j2，但必须给 SLF4J 配个实现，否则启动报 NOP logger。

注意此处没有 Spring Boot。AgentScope 1.0.7 是”裸 Java + JDK 17”就能跑的库；Spring Boot starter 整合要等到 9-3（升级到 1.0.8）。

3. 我一开始没 get 的点

  1. “weat” 不是新名词——ASR 把 ReAct 听成 weat。一年后翻 transcript 别被骗。
  2. AgentScope 和 JManus 不是”两种思想”——它们都是 ReAct，差异在”可控性”和”工程化”，不在推理范式。
  3. “生产级”不是营销词——指的是 Project Reactor + GraalVM + Runtime 沙箱三件硬料，可以量化。
  4. 本集没有 Spring Boot——别看到”基于 Spring AI Alibaba 生态”就以为要装 Boot。1.0.7 是普通 Java 库；starter 模式留给 9-3。

5. 知识地图

6. 自测题

Q1：AgentScope 和 JManus 都用 ReAct，那”选 AgentScope 而不是 JManus”的真正理由是什么？

A：两点——① 人能在任意推理步骤插手（安全中断 / 优雅取消 / Hook 三件套），JManus 全自动不可介入；② 工程化更硬（Project Reactor 响应式 + GraalVM 200ms 冷启动 + Runtime 沙箱），适合生产环境。

Q2：ReAct 循环的四步是什么？什么时候停？

A：思考 → 行动 → 验证 → 不符预设则重新思考。停止条件：验证结果与预设目标一致。

Q3：AgentScope 的三件可控机制分别保留 / 销毁了什么？

A：安全中断 = pause Agent，保留上下文 + 工具状态，可无损恢复；优雅取消 = kill 工具调用，保留 Agent 状态，可立即重定向；Hook = 在任意推理步骤注入人类修正，不打断执行。

Q4：本集 pom.xml 为什么必须同时引 logback-classic？

A：AgentScope 的日志走 SLF4J 接口，自己不带实现。logback-classic 是 SLF4J 的实现方，不引就报 NOP logger。

Q5：AgentScope 1.0.7 需要 Spring Boot 吗？什么时候才需要？

A：1.0.7 不需要，裸 Java + JDK 17 就能跑。Spring Boot starter 整合要等到 9-3（AgentScope 1.0.8 + Boot 4）。
