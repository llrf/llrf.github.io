1-3_准备工作配置阿里大模型广场的ApiKey

1. 一句话定位

选阿里云百炼不是因为它最好，是因为后续要用 Spring AI Alibaba。

摘要：取舍出现在 §2.4（”三家广场对比”被压成一张表，没有逐家演示）；加工增量在 §2.5（DashScope / SAA 与 .env 的去向链路是 understanding.md 与原视频都未明说的推断）。

2. 主体讲解

2.1 你为什么需要”广场”

假设你想同时用 DeepSeek、Kimi、通义千问三个模型，按”直觉路径”你要：

  1. 去 deepseek.com 注册 → 申请一个 key
  2. 去 moonshot.cn 注册 → 再申请一个 key
  3. 去 dashscope.aliyun.com 注册 → 再申请一个 key

三家平台、三套账号、三个 key、三套余额管理、三份发票。这就是大模型广场要解决的问题——它把”逐家申请”折叠成”一处申请、多处调用”，本质是一个模型路由代理层：你拿一个 key，背后它替你转发到不同的供应商。

国内做这件事的就三家（也只能是三家，因为下面会看到的原因）：阿里云”百炼”、百度”千帆 ModelBuilder”、字节”火山方舟”。

2.2 百炼是什么样的

百炼的域名是 bailian.console.aliyun.com。你需要记住三件事：

  • 首页顶部红条：免费额度用完后自动转为按量付费。这是默认行为，不是同意才扣——学完课程务必去后台关掉付费或设上限，否则可能被薅。
  • 新人福利：限时千万 tokens 免费。对学习者来说，跑完这门课绰绰有余。
  • 模型广场里有 202 个模型：通义全家桶 + DeepSeek + Kimi + 百川 + Meta（Llama）+ MiniMax + 一堆图像/语音模型。不是只能用阿里自家的。

2.3 互斥规则（这条最反直觉）

你可能以为”既然是聚合平台，那三家收的模型应该差不多”。不是。规则是：

平台 自家 第三方开源（DeepSeek / Kimi） 友商自研
阿里百炼 通义千问全系 收 不收文心、豆包
百度千帆 文心 ERNIE 系列 收 不收通义、豆包
字节方舟 豆包 Doubao 系列 收 不收通义、文心


为什么？商业竞争。自家平台不会替对手引流。但 DeepSeek 和 Kimi 这种”中立的第三方开源模型”是三家都抢着收的——它们是吸引开发者的卖点，谁不收谁就少一个理由让你来。

记住这条规则后，反推就成立了：你想用谁的自研模型，就只能上谁的广场。想用文心就只能上千帆，想用豆包就只能上方舟。


2.4 那为什么本课程选百炼

不是技术选型，是依赖锁死：本课程后面要用的 Spring AI Alibaba（SAA）是阿里出的 Spring 集成包，它只认百炼的 key。它的配置项叫 spring.ai.dashscope.*——DashScope 是百炼底层的 API 协议名，下一两集应该会见到。

所以判定流程其实是反过来的：选了 SAA → 锁定百炼 → 申请百炼 key。如果你换 LangChain4j 或别的框架，可能就不需要走这条路。

2.5 key 申请按钮在哪、申请完了去哪

入口路径：bailian.console.aliyun.com → 左侧菜单最底下 系统管理 → API-Key。点进去之后的表单本集没展开，大概率会要求实名认证 + 短信验证（阿里云控制台的通用流程）。

3. 我一开始没 get 的点

  1. 如果你以为”国内大模型广场谁都收谁”，会得到错的预算。三家收录范围互斥（除了 DeepSeek / Kimi 这种中立棋子），你不能拿”百炼一个 key 调遍天下”做承诺，只能调它收录的那批。
  2. 如果你以为”申请 key 之前先选最强模型”，会卡在第一步。顺序反了：先确定要用的 Java SDK / 框架（本课程是 SAA）→ 框架决定平台 → 再到平台申请 key。模型选型是 key 申请完之后的事。
  3. 如果你忽略首页红条直接申请，免费 tokens 用完那一刻账户会自动开始扣费，且这是默认行为，不是”二次确认”。学完务必去关。
  4. 如果你听到口播里的”BeamAI 阿里巴巴”直接去搜，搜不到。那是 Spring AI Alibaba 的口误，缩写记成 SAA。

5. 知识地图

6. 自测题

Q1（概念回忆）：什么是”大模型广场”？它解决了什么问题？

展开答案

聚合多家供应商模型的代理层，提供统一的 API Key 和接入方式，解决了”逐家供应商单独注册、单独申请 key、单独管理余额”的麻烦。一处申请、多处调用。出处：§2.1 + understanding.md 关键概念表。

Q2（概念辨析）：百炼、千帆、方舟三家广场都收 DeepSeek 和 Kimi，但互不收对方的自研模型，原因是什么？

展开答案

商业竞争。自家平台不会替对手引流。DeepSeek / Kimi 属于中立的第三方开源模型，对三家来说都是”拉开发者过来”的卖点，不收反而少一个理由；但收文心就等于替百度做广告，收豆包就等于替字节做广告。出处：§2.3 表格 + 图 f004 / f011 / f021。

Q3（反直觉陷阱）：你拿到百炼 key 后想立刻调通义千问，发现首页顶部一直挂着一条红色提示。它说什么？为什么必须现在就处理？

展开答案

“免费额度用完后将自动转为按量付费”。必须现在处理是因为这是默认行为——免费 tokens 烧完那一秒账户会无声地切到付费模式，不会弹窗、不会二次确认。学完课程务必去后台关闭付费或设置上限。出处：§2.2 + §3 第 3 条 + 图 f002。

Q4（跨集连接）：本集申请的 key 不会贴进代码里。它的最终归宿是什么文件？由谁加载？

展开答案

最终归宿是项目根目录的 .env 文件（13-1 教的方案），通过 Spring Boot 的 spring.config.import=optional:file:.env[.properties] 加载，然后在 application.yml 里以 ${DASHSCOPE_API_KEY} 形式被 spring.ai.dashscope.api-key 引用，最后由 SAA 在每次调模型时自动塞进请求头。出处：§2.5 链路图 + understanding.md 与 13-1 的连接。

Q5（应用推广）：假设你的下一个项目不用 SAA，改用 LangChain4j，且需要调用豆包。你应该去哪个广场申请 key？为什么不能继续用百炼的 key？

展开答案

去字节火山方舟（console.volcengine.com/ark）。因为豆包是字节自研模型，百炼基于商业竞争不会收录豆包，所以百炼的 key 即使能调，也调不到豆包。框架换了不等于平台必须换，但模型选择会反向决定平台——这是 §2.3 互斥规则的应用。出处：§2.3 + §2.4 推理过程。
