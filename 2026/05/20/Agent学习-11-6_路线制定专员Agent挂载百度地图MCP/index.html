路线制定专员Agent挂载百度地图MCP

一句话定位

把上集临时 main 里跑通的”百度地图 MCP 客户端 + 工具列表”搬进 @Bean getRouteMakingAgent()，用 ToolUtils.getToolkit(...) 的重载版本把 client 装进 toolkit、再用 .toolkit(toolkit) 喂给 ReActAgent.Builder，最后两个不踩就空的小坑：stream().forEach 和 .block()。

主体

1. 从 main 搬到 @Bean，是”测试代码”升级成”生产位置”

上集你在 RouteMakingAgentApplication.main 里干了三件事：new BaiduMapMCP()、mcp.getBaiduMapMcP()、mcp.initBaiduMapMcP()，最后一行返回 McpClientWrapper。但 main 只是临时跑通用，真正要让”路线制定专员”用上百度地图，得把它写到 RouteMakingAgent.getRouteMakingAgent() 这个 @Bean 方法里——这个 Bean 是 5-2 那集就立好的骨架，本集只是给它补”工具”那一段。

2. getToolkit(...) 的两种重载——同名不同入参

之前你写智能体的工具，用的是 toolUtils.getToolkit(someTool)，里面走的是 toolkit.registerTool(tool)。现在你想把”MCP 客户端”塞进去，直觉是再调一次同样的方法——但参数类型是 McpClientWrapper，不是 Object，编译不过。

帧 f017 / f019 给了 IDEA 弹的 Choose Declaration 候选框，明确告诉你 ToolUtils 里已经写了两份同名方法：

调用方写法 入参类型 内部实现
getToolkit(someTool) Object tool toolkit.registerTool(tool)
getToolkit(mcpClient) McpClientWrapper mcp toolkit.registerMcpClient(mcp)

加工增量：讲师把这俩并排，是为了说明”对调用方零负担”——Toolkit toolkit = toolUtils.getToolkit(...) 这一行从语法上看完全不变，重载帮你做了分流。但代价藏在第二份里，下面就要踩到。

3. registerMcpClient 是异步的，挂的不是 client，是 client 背后的 server 工具列表

讲师原话：”它挂载的其实不是这个 MCP 客户端，它挂载的是这个 MCP 客户端所拥有的 MCP 服务端的工具列表。”

这句是本集最该记住的一句。new BaiduMapMCP() 只是包壳，initBaiduMapMcP() 才回了一个 McpClientWrapper，而 registerMcpClient(mcp) 里面做的事是：

验证有没有挂上，调 toolkit.getToolNames()，返回 Set<String>。讲师说这是”渣瓦的基础知识”——Set 没有”for (x : set) { ... }“ 这种字面遍历的简洁糖形态适配 lambda 打印（指他想要的 集合.forEach(打印) 这种写法），所以要：

5. 跑通后日志的三段叙事

帧 f018 / 末尾段把日志拆给你看了三段：

  1. client 自己的日志：先打印”百度地图 MCP 客户端已创建 / 初始化成功 / 拿到 server 工具列表（一长串）”。
  2. registerMcpClient 的日志：一条一条往 toolkit 里塞，这就是为什么要 block()——能直观看到耗时正比于 server 工具数。
  3. 你自己的 getToolNames 打印：和 server 列表数量对齐，证明挂载成功。

没 get 到的点

  • ToolUtils 内部 Toolkit 字段是 new 在构造里、还是每次 getToolkit 都 new？OCR 帧只看到 Toolkit toolkit = toolUtils.getToolkit(...) 调用方写法，没看到 ToolUtils 字段声明那一段。这影响多次调用会不会拿到同一个 toolkit（共享 / 隔离）。
  • registerMcpClient(mcp).block() 写在工具类里，是不是浪费 Reactor 线程？业务侧能不能改 .subscribe() + Agent 启动预热？讲师没展开。
  • 多个子 Agent（路线制定 + 行程规划）都挂百度地图 MCP，是各自 new BaiduMapMCP() 起多份 client，还是共享一个？帧 f001 的架构图把两个 Agent 画成”各自挂载”，但代码层没回答。
  • Set 返回是不是 LinkedHashSet？日志看着是顺序对齐 server 列表的，但 Set 一般无序。

  • 上承 11-5：刚做完 BaiduMapMCP 客户端创建 + initBaiduMapMcP() 拿 McpClientWrapper + 打印 server 工具列表。本集第一步就是把那段代码搬位置。
  • 再往前 5-2 团队成员路线制定专员Agent：给出了 @Component + @Bean public ReActAgent getRouteMakingAgent() 的骨架。本集只补 .toolkit(toolkit) 那一行。
  • 横向 5-6 百度地图MCP提供的工具体系全景：5-6 是”server 暴露了哪些工具”，11-6 是”client 怎么把那串挂到 Agent”。前后呼应。
  • 横向 6-11 MCP客户端连接MCP服务端：6-11 跑通协议握手；本集多走一步——把握手成果接到 Agent 的 toolkit。
  • 横向 4-13 SpringAi 1.1 A2A的服务注册：里面的 ReactAgent.builder().tools(...) 是同一个 builder，本集换成 .toolkit(...)，从散装工具升级成工具包。
  • 镜像 4-6 将MCP工具注册到MCP服务：4-6 是 server 侧 @Tool 注册到 MCP 服务；本集是 client 侧把 server 上的注册结果”再注册一遍”到自己的 toolkit。一头一尾。
  • 下启：路线制定 Agent 现在有工具了，下一步要么真问”从北京到上海怎么走”验 ReAct；要么把同一套模板复用到 tripPlanner_agent；最终汇入主管 Agent（架构图：旅游规划 → 主管 → 路线/行程/费用三子 Agent）。
