7-12 基于 Graph 搭建旅游规划工作流

1. 一句话定位

把前面 5-1～5-5 画在白板上的”主 Agent + 4 个专科 Agent”那张工作流图，用 SAA 1.1 的 Graph DSL（addNode / addEdge / addConditionalEdges）翻译成 Java 代码——这一集只搭骨架，节点里都是空壳。

2. 主体

2.1 先把图刻在脑子里

记住这张图（f001）：从左到右共 5 个节点 + 1 个条件分支。

  • 入口：任务分发节点 TaskAssignmentNode（START 连到它）
  • 中段两条并行支线：路线制定节点 RouteMakingNode、行程规划节点 TripPlannerNode
  • 汇流：两条支线都连到 费用统筹节点 BudgetNode
  • 分叉点：BudgetNode 出来挂一个条件边，看总费用
    • 小于 1000 → 汇总节点 AggregationNode → END
    • 超过 1000 → 跳回 TripPlannerNode 重新规划

为什么超过 1000 只回 TripPlanner 而不回 RouteMaking？因为路线一旦定了里程是固定的，能压的只有住宿/餐饮/门票——这些归行程规划管。这是业务取舍，不是技术约束。

2.2 五步法搭一个 Graph（加工后的顺序）

视频里讲解顺序是”先讲完全部节点 → 再讲全部边”，但你真正动手写代码时应该按下面这个顺序，因为后一步依赖前一步的产物：

Step 1 · 写 5 个节点类（沿用 1.0 写法，零变化）

每个节点 implements NodeAction 放在 node/ 目录下，重写 apply(OverAllState state)。在 apply 里通过 state.value("xxx") 拿全局状态。

2.3 五个反直觉点（学习者增量加工）

视频本身按代码行讲，没把”为什么这样设计”挑明。下面是我整理出来的几条钉子：

钉子 1：边也是一个类

第一反应肯定是写 lambda。错。条件边和节点是同等公民——节点 implements NodeAction，边 implements AsyncEdgeAction，两边都重写 apply。SAA 1.1 没给 lambda 糖。

钉子 2：addConditionalEdges 的第三个 Map 是”白名单”不是”分支映射”

Map.of("AggregationNode", "TripPlannerNode") 表面像一个 if/else 的 k→v 映射，但其实只是借 Map 当集合用——SAA 框架要检查”你 apply 返回的下一节点 ID 必须在这个 Map 的 values（或 keys）里”，否则编排时找不到目的地直接报错。

这一条视频没说透，老师只说”它最后会有两个选择，所以传这两个 ID 进来”。但 key/value 谁是谁的语义视频里没解释——猜测 1.1 RC2 只检查”返回值是否出现在 Map 的某一边”。

钉子 3：state.value 返回的是 Optional 且要传 Class

state.value("TotalBudget") 默认返回的是 Optional<?>——一个类型擦除的 Optional，你拿出来不能直接和数字比较。必须用重载 state.value("TotalBudget", Integer.class) 把泛型钉死，再 .get() 解包出 Integer。

钉子 4：返回类型是 CompletableFuture

apply 反馈下一节点 ID，但要套一层 CompletableFuture.completedFuture("AggregationNode")——因为接口是 Async 的。即便你判断逻辑是同步的，外壳也必须异步。

钉子 5：BudgetNode 不直接连两个节点，而是先连到边

直觉是”BudgetNode 出来分两条线”，但 SAA 的设计是：BudgetNode → TotalBudgetEdge（条件边作为”虚拟中转节点”）→ 真目标节点。条件边本身有 ID，可被普通边连过来。

3. 没 get 的点

  • addConditionalEdges 第三个 Map 的 key/value 各有什么用？只是集合化的需要？还是用来打印 PlantUML 时做别名？需要翻 1.1 RC2 源码确认。
  • 第二个参数 Class 重载只演示了 Integer。如果 value 是 List、自定义 POJO 怎么取？是不是要走 getValue(key, TypeReference) 之类的重载？
  • 重入语义：超过 1000 跳回 TripPlannerNode 再下来到 BudgetNode 时，旧的 TotalBudget 会被 Replace 覆盖；但如果 TripPlanner 这次忘了更新这个 key，旧值会卡死循环吗？SAA 有没有最大循环次数兜底？
  • TaskAssignmentNode “路线相关 / 行程相关” 的分发视频里没写——它显然也是一条 addConditionalEdges，但下一集才会补上。

5. 知识地图

6. 自测题（5 卡）

Q1：addNode 第二个参数为什么不是直接 new RouteMakingNode()，而要套一层 AsyncNodeAction.node_async(...)？

答SAA 1.1 的 Graph 引擎在内部按异步调度节点，要求注册的是 `AsyncNodeAction`。`NodeAction` 是同步接口，`node_async` 静态方法负责把同步节点包成异步——这是适配层，写法和 1.0 完全相同。

Q2：在条件边里写 state.value("TotalBudget").get() < 1000 会怎样？怎么改对？

答编译失败或运行时类型不对。`state.value(key)` 返回的是 `Optional`，`.get()` 拿到的是 Object，不能和 1000 比大小。要用重载 `state.value("TotalBudget", Integer.class).get()`，第二个参数 Class 用来钉死 Optional 的泛型。

Q3：stateGraph.addConditionalEdges("TotalBudgetEdge", new TotalBudgetEdge(), Map.of("AggregationNode", "TripPlannerNode")) 第三个参数的作用是什么？如果 apply 返回了一个不在 Map 里的字符串会发生什么？

答第三个 Map 是"可达节点白名单"——SAA 框架用它来校验 apply 返回的下一节点 ID 是否合法。如果返回值不在这个 Map 里，编排器找不到目的地，会抛异常。Map 的 key/value 谁是谁没有 if/else 语义，只是借 Map 当集合用。

Q4：BudgetNode 出来是两个分支（汇总 / 重规划），为什么不直接写 addEdge("BudgetNode", "AggregationNode") 和 addEdge("BudgetNode", "TripPlannerNode") 各一条？

答普通 `addEdge` 是无条件跳转，写两条相当于"两条线都走"，但实际只能走一条且要看条件。条件边的设计是：BudgetNode → 条件边（TotalBudgetEdge，本身也是一个 ID）→ 由 Edge.apply 内部判断后返回真正的下一节点。条件边相当于一个虚拟中转节点。

Q5：注册 TotalBudget 这个 key 时为什么必须绑定一个 ReplaceStrategy？不绑会怎样？

答OverAllState 是节点间共享的状态包，多个节点会写同一个 key（RouteMakingNode 写费用、TripPlannerNode 写费用、BudgetNode 读费用）。框架需要知道"后写的覆盖前写的"还是"追加成 List"。不绑策略框架不知道怎么合并，注册时就会报错。本集只有一个 key + Replace 策略——意味着每次只看最新值。

7. 关键词表（≤8）

术语 一句话
StateGraph SAA 1.1 工作流的中心对象，承载所有 addNode / addEdge / addConditionalEdges 调用
AsyncNodeAction.node_async 静态方法，把同步的 NodeAction 包成异步节点供 addNode 注册
addConditionalEdges 条件分支三件套：边 ID + Edge 对象 + 可达节点白名单 Map
AsyncEdgeAction 条件边的接口，apply 返回 CompletableFuture，String 是下一节点 ID
OverAllState 跨节点共享的状态包，是节点间唯一信使
KeyStrategyFactory / ReplaceStrategy 注册全局状态键时必须绑定合并策略，Replace 是覆盖，Append 是追加
state.value(key, Class) OverAllState 取值的重载，第二个参数 Class 用来钉死 Optional 的泛型
CompletableFuture.completedFuture 同步路由场景下”立刻把下一节点 ID 异步包出去”的标准写法
