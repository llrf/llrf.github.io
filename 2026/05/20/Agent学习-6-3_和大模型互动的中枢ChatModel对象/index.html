6-03 和大模型互动的中枢：ChatModel对象

发表于2026-05-20|更新于2026-05-20|Agent学习第06章 多 Agent + ReAct架构，SpringAi迈入Agent新时代

1. 一句话定位

你拿到一个由 starter 在容器里白送的 ChatModel，把字符串包成 UserMessage、塞进 Prompt、调 call()、再从 ChatResponse 里剥三层取出文本——这一集就是把这条糖葫芦串完整。

2. 主体

2.1 为什么必须先看一眼报错

上一集（6-2）启动时炸过一次：DashScope API key must be set. Use the connection property: spring.ai.dashscope.api-key。这条报错不是噪音，它把这一集要做的事提前剧透了——starter 已经准备好往容器里塞 Bean，只是缺 key 没法初始化。本集就是补上这个 key、并真正去用那个 Bean。

starter 叫 spring-ai-alibaba-starter-dashscope，但配置前缀是 spring.ai.dashscope.*，不是 spring.ai.alibaba.*。这点很坑，第一次写很容易输错。

2.6 跑通验证

启动应用，浏览器或 ApiFox 打 http://127.0.0.1:端口/simple/chat，能看到模型对”在咖啡馆里，想要杯星巴克”的回答即闭环成功。

3. 没 get 的点（待查）

  • Prompt 还能装哪些消息类型？SystemMessage 怎么塞角色设定？多轮对话历史是 new Prompt(List<Message>) 堆，还是要靠下一集的 ChatClient 记忆机制？
  • 本集 yml 只写了 api-key，没写 chat.options.model——这种情况走的默认模型是哪个？写错模型名会启动时炸还是 call 时炸？（加工增量：我猜默认 qwen-plus，但 transcript 没证实。）
  • getResult() vs getResults()：什么场景才会出现多个 Generation？是 n 采样还是流式？
  • 想切非百炼模型（OpenAI / 火山）必须换 starter 吗？多 ChatModel 共存（A/B 比较）怎么写 @Qualifier？

4. 跟其他集连接

  • 上承 4-1：4-1 教 BOM + spring-ai-alibaba-starter-dashscope 的导入。本集就是”导入完之后 starter 白送了什么 Bean”的答案——ChatModel。
  • 上承 6-2：6-2 启动报错 DashScope API key must be set 留的尾巴，本集第一件事就是把这个 key 补上。
  • 下启 6-4（推测）：文档把 ChatModel 和 ChatClient 并列写”两个实例”。ChatModel 是底层 call(Prompt) 接口，ChatClient 大概率是更高层的 fluent API（prompt().user().call().content()）——下一集应该揭晓。
  • 横向 5-5（主管+专科+汇总 Agent）：那一集说”LLM 是 Agent 的大脑”，本集就是这个大脑在 Spring 里的具体握把。
  • 横向 4-13（ReactAgent.builder()）：1.1 版 ReactAgent 的构造参数要传 ChatModel，正是本集这个对象。本集是 1.0.0.2 入门，4-13 是 1.1 把它包了一层 Agent 抽象。
  • 横向 3-2/3-3（Function Calling）：FC 也要走 Prompt → 大模型 → 响应，本集的 Prompt 未来塞 tools 列表就在这一层叠加。

6. 自测题

  1. 为什么 Controller 里写 private final ChatModel chatModel; 而不是 new XxxChatModel(...)？这背后依赖哪个机制？
  2. 一次 chatModel.call(prompt) 之后，想拿到模型回答的纯文本，要连续点几层方法？为什么要判空？
  3. starter 的 artifactId 是 spring-ai-alibaba-starter-dashscope，那 yml 的配置前缀是什么？这俩为什么不对称？
  4. Prompt 的构造参数除了一个 UserMessage，还能塞什么？（提示：以后做角色设定 / 多轮 / 工具调用要用）
  5. 如果想让 dashscope 走到非阿里的模型（例如 OpenAI 的 gpt-4o），最小改动是改 yml 还是要换 starter？为什么？

7. 关键词表

术语 一句话定义
ChatModel SAA 自动装配出来的”和大模型对话的握把”接口，方法 call(Prompt) 返回 ChatResponse。
UserMessage 用户输入的 Java 化封装，构造参数是字符串，属于 org.springframework.ai.chat.messages。
Prompt 提示词聚合对象，可装一条或多条 Message（User / System / Assistant），本集只塞一条 user。
ChatResponse 大模型返回的聚合对象，三层取文本：getResult().getOutput().getText()。
自动装配 引入 starter 后 Spring Boot 启动阶段就把 ChatModel / ChatClient 实例化好塞容器，开发者只伸手接。
构造方法注入 private final ChatModel chatModel; + 构造方法赋值；比字段注入更利测试、避免空指针。
dashscope 配置 namespace spring.ai.dashscope.api-key（不是 spring.ai.alibaba.*），starter 名和配置前缀不对称。
三层判空 取 getResult() / getOutput() 任一层都可能 null，超时/限流时要先判再取 getText()。
