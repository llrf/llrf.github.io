9-2_分布式Agent自主旅游规划的架构思路

发表于2026-05-20|更新于2026-05-20|Agent学习第9章 Docker 部署分布式 Agent 搞定旅游规划
|浏览量:

1. 一句话定位

这一集把整个项目的总图一次性铺开给你看：一个 HTTP 入口、一张注册表、两条 A2A 派单线、一个内部 ReAct 循环、一支异步子 Agent，再加一段 MCP 调工具——所有前面学过的概念在同一张图里各管一段，不重叠。

2. 主体

2.1 入口：用户只管发 prompt

用户走 HTTP 把 prompt 扔进来。这个 Web 接口看起来像是独立的一层 Controller，但它不是——这是第一处反直觉：Web 接口是主管 Agent 自己暴露的。Agent 即 Controller，没有中间层。第一遍看图你会下意识在主管 Agent 上面再加一格”接入层”，那是错的，省掉它。

2.2 主管 Agent：一人三役

主管节点接到 prompt 后做两件”自主”的事：

  • 自主任务分解：把”帮我规划一趟旅游”拆成更细的子任务（路线 / 行程 / …）。
  • 自主任务分发：把子任务派给对应的远程 Agent。

加上 2.1 的暴露接口，它其实是三合一：HTTP 入口 + 任务规划器 + 调度器。

加工增量：口播没说”怎么自主”，只说”自主”。我猜机制是把主管自己也做成 ReactAgent，把”路线 Agent / 行程 Agent”打包成它的 tool 列表，让 LLM 在 ReAct 循环里自主决定调谁、传什么——这样”自主分解 + 自主分发”就统一成 ReAct 的 Thought→Action 两步，不需要额外的 plan 数据结构。后面集如果给的是另一种实现（比如先 plan 一个 JSON 数组再依次派单），再回来修这条。

2.3 找人 = A2A + Nacos，注册/发现两步走

这是图里最容易看混的地方：三个箭头都贴着”A2A 协议”。其实 A2A 在这里用了两次，方向相反：

阶段 方向 谁动 干嘛
注册 子节点 → Nacos 路线 Agent / 行程 Agent 把自己的 AgentCard 写进注册表
发现+派单 Nacos → 主管，主管 → 子节点 主管 Agent 先查通讯录，再按地址打电话

Nacos 在这里只做通讯录——它存的就是 4-15 里那种 AgentCard 元数据，不参与派单决策、不做负载均衡逻辑（至少这一集没讲）。把它当”配置中心”或者”服务网格”会想歪。

2.4 远程 Agent 内部：ReAct 主干 + Skills 异步分支

以行程规划 Agent 这一支为例（路线制定那一支图里没展开，可能是简化）：

  • 主干跑 ReAct 循环：思考 → 执行 → 反思，再回去思考。这是同步的，就是 6-6 / 7-x 学过的那个 ReactAgent。
  • 主干在某一步碰到”单点任务”（粒度很细、可以独立完成的小活），不自己干，而是fork 一个子 Agent异步去做。异步这一点是性能上的反直觉：主干不阻塞、继续往下推进，子 Agent 的结果以后某个时刻回流。
  • 子 Agent 进入后按 Skills 专业流程执行。Skills ≠ Tool——这是消化稿强调过的一句信息密度极高的话：Skills 是整套 workflow（专业流程），Tool 才是流程里被调用的单个动作。
  • Skills 流程在某些步骤需要工具时，通过 MCP 协议调远端 MCP Server 节点。MCP Server 也是独立部署的节点。

2.5 三种协议，各管一段

把整张图拆成协议视角，会发现三层完全不重叠：

协议 谁 ↔ 谁 干什么
HTTP 用户 ↔ 主管 Agent 入口
A2A 主管 Agent ↔ 子节点 Agent，子节点 ↔ Nacos 找人、派活
MCP 子 Agent（Skills 内） ↔ MCP Server 用工具

记忆口诀：A2A 找人、ReAct 想事、Skills 走流程、MCP 用工具。

2.6 不要从上往下念图，按”调用因果”重排

视频里讲师是按图上的空间位置从上到下念的。别这么学——按”因果时序”念才记得住：

  1. 用户 → HTTP → 主管 Agent。
  2. 路线 / 行程 Agent 先把 AgentCard 注册到 Nacos（系统启动时就完成）。
  3. 主管接到 prompt → 自主拆解 → 从 Nacos 发现对应 Agent。
  4. 主管沿 A2A 派单到对应远程 Agent。
  5. 远程 Agent 跑 ReAct 主干；遇到单点任务 → fork 子 Agent（异步）。
  6. 子 Agent 按 Skills 走流程；流程中需要工具 → MCP → MCP Server。
  7. 结果回流（这一段图上没画，下一集大概率会补）。

3. 还没 get 的点

5. 知识地图

6. 自测题（5 张卡）

Q1：用户访问的 Web API 是哪个组件暴露的？为什么不是单独的 Controller 层？
A1：主管 Agent 节点自己暴露。这里去中间化了——Agent 就是 Controller，没有独立接入层。

Q2：图上三条都贴着 “A2A 协议” 的箭头，到底分别在干什么？
A2：① 子 Agent（路线 / 行程）启动时把 AgentCard 注册到 Nacos；② 主管 Agent 从 Nacos 发现这些 Agent 的地址；③ 主管沿 A2A 把任务派到对应子节点。注册中心只是通讯录，不做派单。

Q3：行程规划 Agent 内部，”主干 ReAct 循环”和”子 Agent”是什么关系？
A3：主干是同步的 ReAct（思考→执行→反思）。碰到单点任务时异步 fork 出一个子 Agent 去执行，主干不阻塞、继续推进。子 Agent 走 Skills 专业流程，可能再用 MCP 调工具。

Q4：Skills 和 Tool 的区别是什么？为什么这里强调 Skills 而不是 Tool？
A4：Skills 是整套专业流程（workflow），Tool 是流程里被调用的单个动作。子 Agent 不是简单”调一个工具搞定”，而是按 Skills 走一整条流程，流程里再通过 MCP 调具体 Tool。

Q5：HTTP / A2A / MCP 三种协议各管哪一段，能不能互换？
A5：HTTP 管”用户 ↔ 主管”入口；A2A 管”Agent ↔ Agent”跨节点通信和注册；MCP 管”Agent ↔ Tool Server”工具调用。职责完全不重叠，互换会破坏分层——比如用 MCP 替 A2A 就丢失了 AgentCard 这套语义。

7. 关键词表

术语 一句话解释
主管Agent节点 暴露 Web API + 自主拆任务 + 自主派任务的三合一入口节点
远程子节点Agent 路线制定 / 行程规划等专科 Agent，独立进程、对等部署
Nacos注册中心 装 AgentCard 的”通讯录”，只做注册和发现，不参与派单
A2A协议 跨节点 Agent 间通信，覆盖”注册到 Nacos”和”发现+派任务”两阶段
ReAct主干循环 远程 Agent 内部的同步执行模式，思考-执行-反思反复迭代
子Agent 远程 Agent 内部异步 fork 出来处理单点任务的临时 Agent，不阻塞主干
Skills专业流程 子 Agent 执行任务遵循的整套 workflow，不是单个工具
MCP协议 Skills 流程内 Agent 调用远端 MCP Server 工具的协议
