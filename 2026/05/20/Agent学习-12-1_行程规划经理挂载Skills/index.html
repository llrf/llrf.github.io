12-1 行程规划经理挂载Skills

发表于2026-05-20|更新于2026-05-20|Agent学习第12章 专属SubAgent, 处理旅游规划专业Skills
|浏览量:

1. 一句话定位

这一集把”行程规划 Agent”补齐——上一集兄弟 Agent 用 .toolkit() 接上百度地图 MCP，你这边用 .skillBox() 把本地 ./skills/ 下的两个 SKILL.md（景点推荐 + 表格制作）挂进去，凑齐主管 Agent 派任务时两条腿都能跑。

2. 主体

2.1 三种”理论上”的构造方式（看一眼就好，别抄进主代码）

视频前 5 分钟讲了 AgentScope 把 SKILL.md 变成 AgentSkill 对象的三条路：

  • Builder 工厂方法：AgentSkill.builder().name("...").description("...")...build()，每个方法对应 SKILL.md 的 YAML 标签。
  • Markdown 工具类：把整份 SKILL.md 读成一个大字符串，丢进工具类自己解析。
  • new AgentSkill(name, desc, content, resources)：构造方法直接把字段填进去。

这一节是取舍重点：视频虽然花了一半时间在这三种上，但讲完一句”这三种方式对工程化都不是很好”，等于全推翻。所以你看消化稿时要把它当 API 兜底知识，不要在主流程里写。真正落地的是下一节。

2.2 工程化路线：FileSystemSkillRepository

对位上一版 SpringAI 1.1.2 的 ClasspathSkillRegistry，AgentScope 这边给的是 FileSystemSkillRepository：

物料这边：tripPlanner_agent/src/main/resources/skills/ 下建两个文件夹 Suggest_Sights/ 和 Make_A_Table/，每个文件夹放一份 SKILL.md。

2.3 一条容易踩的铁律

文件夹名 == SKILL.md 内 name: 字段。否则 repo.getSkill("Suggest_Sights") 直接返回不到东西、又不抛你预期的异常。这条规律和 10-5 那集对 SKILL.md 文件结构的约束是同一条，本集把它从”规范”升级成”运行时硬约束”。

2.4 三个名字别糊在一起（加工增量：消化稿叠在一段口播里，这里拆开成三栏对照）

名字 是什么 你在代码里怎么用
SKILL.md 磁盘上的配置文件（YAML frontmatter + 正文） 不直接读，交给 repository
AgentSkill 内存里的对象，对位一份 SKILL.md repo.getSkill("...") 返回值
SkillBox 容器/工具箱，装一组 AgentSkill new SkillBox() + registerSkill(...)

2.5 挂载入口和 toolkit 是并列的

agent builder 里 .skillBox(...) 是和 .toolkit(...)、.memory(...)、.hooks(...) 平级的槽位——一个 agent 完全可以同时挂 toolkit 和 skillBox，不是二选一。Skill 给”工作流程/专业知识”，toolkit 给”外部 API”，分工不重叠。

3. 没 get 的点

  • AgentSkillRepository / FileSystemSkillRepository 在 AgentScope Java 版的具体包路径和版本，视频里没贴出来，只能等下一集或翻文档。
  • Path.of("./skills") 这种相对路径在 Spring Boot 打 jar 之后能不能正确 resolve？还是得换成 classpath 路径？视频没演示运行结果，停在代码写完那一刻。
  • SKILL.md 正文里的”使用方法 / 可用资源”具体是怎么进 LLM 的——是开机时就拼进 systemPrompt，还是 description 触发后才注入？这关系到 token 成本，留到后续验证。
  • description 用中文还是英文对触发率影响多大，视频没提，下一集观察日志再说。

4. 跟其他集连接

上承

  • 10-3 Skills装载的是专业知识和工作流程：Skills 三件套的概念底盘，本集才在 Java 工程里用上。
  • 10-5 Skills的文件结构标准：把 SKILL.md 的 YAML frontmatter + name/description 钉死，本集 repo.getSkill("Suggest_Sights") 拿的就是那个 name。
  • 10-7 SpringAi 1.1.2实现Agent装载Skills：SpringAI 侧用 ClasspathSkillRegistry + SkillsAgentHook，AgentScope 这侧换成 FileSystemSkillRepository + SkillBox，API 路径不同但思路同构——都走文件系统加载，避免把 Skill 内容硬编码进代码。
  • 11-6 路线制定专员Agent挂载百度地图MCP：兄弟集，那边挂 toolkit，本集挂 skillBox，凑齐主管 Agent 派发任务的两个落点。

下启

  • 下一集大概率写两份具体的 SKILL.md（景点推荐 / 表格制作），并观察主管 Agent 派任务时 description 是怎么被 LLM 读到的。
  • 再往后可能进入”Skill 内部调用 MCP”的组合形态（参见 3-8 Agent_Skills+MCP），那种”景点推荐 Skill 反过来调一次百度地图 MCP”才是这套架构的真终态。

横向

  • 11-7 主管Agent自主分发任务给远程相应的成员：AgentCard / @Tool / Skill 三处都靠 description 当语义路标——本集你写的每条 Skill 的 description 就是它被触发的唯一钩子。
  • 10-4 Skills的渐进式加载机制：SkillBox 注册的只是元数据入口，真正的 skillContent / resources 仍按需加载，呼应 pull 模型。

5. 知识地图

记住三层映射：SKILL.md（磁盘）→ AgentSkill（对象）→ SkillBox（容器）→ Agent（挂载）。

6. 自测题

  1. repo.getSkill("Suggest_Sights") 这句话能成立的前提，除了文件夹叫 Suggest_Sights，还需要什么？
  2. 如果一个 Agent 既要调百度地图 MCP，又要用景点推荐 Skill，应该怎么写 builder？是二选一吗？
  3. AgentScope 给的三种构造 AgentSkill 的方式里，为什么视频建议主代码都不要用？
  4. new SkillBox() 和 MCP 那种 server 自动吐 tool list 在”注册风格”上最大的差别是什么？
  5. SKILL.md 里 description 字段，最终是给谁看的？它在运行时承担什么职责？

参考答案藏在 §2.2 / §2.5 / §2.1 / §3。

7. 关键词表

术语 一句话
AgentSkill 一份 SKILL.md 在内存里的对象化表示，至少含 name + description
SkillBox Skill 容器，对位 toolkit，通过 registerSkill 收一组 AgentSkill
FileSystemSkillRepository 工程化推荐的加载器，按 Path.of("./skills") 扫文件夹
SKILL.md Skill 的核心配置文件，YAML 头 + 正文
registerSkill SkillBox 上把一个 AgentSkill 塞进去的方法
skillBox 挂载入口 agent builder 里 .skillBox(...) 槽位，与 .toolkit(...) 并列
name 一致性铁律 SKILL.md 内 name 字段必须等于所在文件夹名
Skill vs MCP Skill 本地 pull 手工 register，MCP 远端 push 自动注册
