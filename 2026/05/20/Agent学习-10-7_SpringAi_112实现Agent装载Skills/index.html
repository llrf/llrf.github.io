10-7 SpringAi 1.1.2实现Agent装载Skills

发表于2026-05-20|更新于2026-05-20|Agent学习第10章 Skills 让 Agent 按照专业流程工作
|浏览量:

1. 一句话定位

你要把 3-7 学的”领域工作流 Skills”在 SAA 1.1.2 里真正落地——办法是走 .hooks() 而不是 .tools()，再按 resources/skills/<技能名>/SKILL.md 这条硬路径把 Markdown 喂进去。

2. 主体

2.1 三个版本号别看晕

打开 pom.xml 第一眼会撞见仨版本号，长得像但分属三条线：

角色 坐标 版本
主 BOM spring-ai-alibaba-bom 1.1.2.0
扩展 BOM spring-ai-alibaba-extensions-bom 1.1.2.1
SpringBoot spring-boot-dependencies 3.5.x

加工增量：视频按”主 BOM → 扩展 BOM → SpringBoot”顺讲，但没强调为什么扩展 BOM 尾号要错一位。我的解读是阿里把仓库拆成”主仓 + 扩展仓”两条独立发布线——dashscope starter 这种”非核心连接器”归扩展仓，所以版本号独立递增，第一眼看起来像抄错的 .0 vs .1，其实是两个仓库各自的小版本。

为什么必须挂扩展 BOM？因为你要的 dashscope-starter（百炼连接器）就在扩展仓里。少这条 BOM，DashScopeChatModel 根本拉不下来。

2.2 还有第三个依赖：spring-boot-starter-web

你不打算起 web 服务，但必须引 web 依赖——SAA 1.1.2 注册 Skills 的流程内部用到了 Jackson 的注解，而 Jackson 注解打包在 web starter 里。这是一个纯”传递依赖”借道，跟你写不写 Controller 无关。

2.3 ReactAgent 现在多了 .hooks() 槽位

回忆一下 6-6 教过的 ReactAgent.builder() 六件套（name / model / tools / …），1.1.2 多出来一个槽位：

.hooks() 是 AgentScope 概念的 Java 落地——可以理解成 Agent 版 AOP：日志、监控、Skills 都挂在这层。Skills 没去 .tools() 是因为它不是”一个工具调用”，而是”一整套工作流”，性质比单点 Tool 更外层。

2.4 两段 builder 链：把 SKILL.md 喂进去

classpathPath("skills") 里的 "skills" 是目录名，相对 resources/ 根。

2.5 目录结构是硬约定（最容易翻车）

三条铁律：

  1. 中间必须再嵌一层”技能名同名目录”，少这层加载不到。
  2. SKILL 大写、.md 小写。
  3. SKILL.md 里写的技能名要和目录名严格一致——目录名是给 registry 找路径用的，MD 里的 name 是给 LLM 看的描述，两边不一致 LLM 自报技能时就会说错名。

多技能就在 skills/ 下平铺多个子目录（百度地图/、PDF/、数据库/…），每个子目录各放一个 SKILL.md，registry 会自己扫。

2.6 验证：让 Agent 自报技能

跑 demo 时直接问 Agent “你有哪些技能？”，回答里能复述 SKILL.md 的 description（”基于百度地图的 API 执行”），就说明文件被读进了上下文，挂载成功。

3. 没 get 的点

  • registry 是自动扫还是要手工注册每个子目录？视频只挂了一个技能，没演示多技能场景。直觉上 classpathPath("skills") 既然指根目录，应该是自动扫描所有子目录的，但没看到证据。
  • hooks 是 List 形式，多个 hook 的执行顺序谁定？日志 hook + Skills hook 同时挂的时候，是按 List 顺序还是有优先级？
  • SKILL.md 的完整字段表：视频版只演示了”技能名 + 描述”两个字段。3-7 提过 Skills 还能配 prompt 模板、附件文件、所需工具，这些在 SAA 1.1.2 里对应的字段名是什么？要查官方文档。
  • 加载时机：SKILL.md 的内容是 builder 时一次性塞进 system prompt，还是延迟到 LLM 决定用这个技能时再拉？这决定了上下文 token 占用模型。

4. 跟其他集连接

上承

  • 3-7 具有专业知识的Agent Skills：那集讲”Skills = 领域工作流 + 按需加载 + 文件配置赋能”的概念，本集是它在 SAA 1.1.2 里第一次拿到代码落地。
  • 3-8 工具调用最强组合：Agent Skills+MCP：”三段式渐进加载”的第一段——元数据加载——本集就是 SKILL.md 这一层。
  • 4-9 SpringAi Alibaba 1.1 以bom方式导入依赖：BOM 三件套的写法你已经会了，本集只多挂一条扩展 BOM 把版本号挪到 1.1.2.0。
  • 6-6 SpringAi 1.1 正式进入Agent自主决策时代：ReactAgent.builder() 的第七个槽位 .hooks()，本集第一次启用。

下启

  • 下一集大概率展开 SKILL.md 完整字段表和多技能并存（百度地图 + PDF + 数据库），把”自动扫描”那个疑问回答掉。
  • 再远会跟 MCP 联动——Skills 工作流里调用 MCP 工具，验证 3-8 讲的”Skills 调度 + MCP 执行”那张分工图。
  • 最远跟 A2A 接上：本进程 Skills 文件 → AgentCard 的 skills 字段对外宣告 → 远端 Agent 跨网调用。

横向

  • 跟 6-7 SpringAi 1.1 组建旅游规划的Agent团队 形成两条赋能路径：6-7 是 Agent-as-Tool（横向嵌入另一个 agent 当工具），本集是 Skills-as-Hook（纵向外挂工作流文件）。前者扩”会做什么”，后者扩”按什么流程做”。
  • 跟 4-15 A2A的元数据AgentCard 里的 Skills 字段同名不同物：AgentCard.skills 是对外宣告能力的元数据列表，本集是把工作流文件真正挂进 Agent 内核。
  • 跟 4-13 A2A的服务注册 对照：同一个 ReactAgent builder，.tools(...) 挂 @Tool Java 方法（代码即工具）/ .hooks(...) 挂 Markdown 文件（文档即技能），两条赋能路径并存。

5. 知识地图

6. 自测题

  1. 为什么 SAA 1.1.2 工程要额外引一条 spring-ai-alibaba-extensions-bom，并且它的版本号尾巴跟主 BOM 不一样？
  2. Skills 挂在 ReactAgent 的哪个槽位上？为什么不是 .tools()？
  3. ClasspathSkillRegistry.builder().classpathPath("skills") 中的 "skills" 是文件名还是目录名？相对哪个根？
  4. resources/skills/ 目录下能直接放 SKILL.md 吗？为什么？
  5. 项目根本不暴露 HTTP 接口，为什么还要引 spring-boot-starter-web？
参考答案
  1. dashscope starter 等”非核心连接器”归阿里的扩展仓库发布，跟主仓库独立递增小版本，所以主 BOM 1.1.2.0 / 扩展 BOM 1.1.2.1 错位一位是常态，不是写错。
  2. 挂在 .hooks()。Skills 是一整套工作流而非单点工具调用，性质等同于日志/监控这种横切关注点，属于 Agent 的 AOP 层。
  3. 是目录名，相对 src/main/resources/ 根。
  4. 不行。中间必须再嵌一层”技能名同名目录”（如 skills/百度地图/SKILL.md），少这层 registry 扫不到。
  5. SAA 1.1.2 注册 Skills 的内部流程用到了 Jackson 注解，而 Jackson 注解打包在 web starter 里，纯传递依赖借道。

7. 关键词表

术语 一句话
SAA 1.1.2.0 第一个支持 Agent Skills 的 SAA 版本，主 BOM 尾号 .0
spring-ai-alibaba-extensions-bom 1.1.2.1 独立扩展 BOM，dashscope starter 等非核心依赖归这里，版本号尾 .1
SkillsAgentHook SAA 1.1.2 新增的 Hook 实现，把 Skills 工作流挂到 ReactAgent 的 hook 槽位
ClasspathSkillRegistry Skills 加载器，从 classpath 指定目录读 SKILL.md
hooks 槽位 ReactAgent.builder 的新槽位，与 .model() / .tools() 同级，专放外挂
SKILL.md 路径约定 resources/skills/<技能名>/SKILL.md，SKILL 大写，目录名必须等于技能名
Jackson 注解依赖 Skills 注册过程内部用 Jackson，逼工程必须额外引 spring-boot-starter-web
Hook 概念 来自 AgentScope，Agent 的拦截器/外挂槽位，相当于 Agent 版 AOP
