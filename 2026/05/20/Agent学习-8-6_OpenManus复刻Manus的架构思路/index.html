8-6 OpenManus复刻Manus的架构思路

1. 一句话定位

你之前看到的”Manus 很神”，到这一集变成了可以用 Java 撸出来的工程蓝图——通过 OpenManus（Python 复刻）这一中转站，把 Manus 的设计思路落地成你项目里要用的 JManus。

2. 主体

2.1 先把 Manus 的两条骨架捋直（frame 1-3）

frame 1 那张图你前几集见过，关键是要看出两层自循环是嵌套的，不是并列的：

  • 外层（规划循环）：思考计划 → 计划列表 → 执行计划 → 反馈问题 → 回头调整计划
  • 内层（执行循环）：思考 → 行动 → 观察

外层那个”执行计划”其实是个黑盒——一旦点开，里面跑的就是 N 个内层小循环（每个智能体处理自己那一份子任务）。所以 frame 2 用三个”自主”+”自主纠正错误”把外层抽象成了 规划 / 执行 / 反馈 三步走，本质是把整张大图做了一层”代数化”。

取舍：消化稿里把这层关系叫”两个 AI 自循环用同一个思维模式，但’执行’二字含义不同”——外层的执行 = 分发协调，内层的执行 = 选工具用工具。这条标注你要刻在脑子里，后面看 OpenManus 的”规划模块/执行模块”会再用一次。

2.2 Manus 的三大卖点（frame 4-6）

图上是按时间顺序一条一条加出来的：

  1. 自主决策：从需求理解到错误纠正全程不需要人介入，frame 2/3 那四个”自主”就是这个意思。
  2. 多智能体协同 + 隔离容器（frame 4）：很多人以为隔离容器是为了沙箱安全，其实不是——它的目的是让 N 个 Agent 各有自己的工作空间互不打扰，所以才能”异步、并行”。把因果关系反过来记：先有隔离容器，才能并行。
  3. 会用工具（frame 5-6）：浏览器、支付宝、数据库命令……Manus 之前你跟 LLM 只能”一来一回对话”，Manus 是第一个真正把对话变成生产力的形态。讲师专门补了一句”Manus 并不完美”，这是给后面 OpenManus 复刻必要性留的钩子。

2.3 复刻链路：闭源 → Python → Java（frame 7-9）

frame 7 给 Manus 贴了 闭源 标签——这就是动机。

注意这里的反直觉点：JManus 不是直接复刻 Manus，而是复刻 OpenManus。所以为什么这门课要先讲 OpenManus 才讲 JManus？因为 JManus 的设计意图全在 OpenManus 那一层。

2.4 OpenManus 的三大模块（frame 10-11）

frame 10 先甩出两块、frame 11 补上第三块——这是讲师的展开节奏，你按这个节奏读会顺很多：

模块 是什么 对应 Manus 的什么
① 模块化 Agent 一个 Agent 框架，新增 Agent 像搭积木一样嵌入 多智能体协同
② 工具驱动 一个工具集合/工具链，MCP 协议也算工具的一种挂在这里 会用工具
③ 处理复杂任务 规划模块 + 执行模块 + 动态 Agent 分配与调度 两个自循环

第三块再拆开（frame 11 右半边）：

  • 规划模块：怎么把复杂任务拆成子任务
  • 执行模块：把子任务派给对应 Agent 去干
  • 动态 Agent 分配与调度：这块讲师没展开（消化稿里也标为”困惑/待查”——它到底是规划模块的子能力还是上层调度器，本集没说清，等后续课）

加工增量：表格里这种”OpenManus 模块 ↔ Manus 特点”的一一对应不是 PPT 给的，是逆推出来的。讲师只是说”OpenManus 借鉴 Manus 思路”，但到底借鉴在哪条得你自己对上号。

2.5 思考骨架收束：两大框架（frame 12）

讲师最后把整集收口在一张大图上——不管外层规划还是内层执行，套路都是 思考 → 执行 → 反馈。这背后对应两个智能体思考框架：

  • Plan-and-Execute（PlanAct） —— 倾向先全盘规划再执行
  • Reason-and-Action（ReAct） —— 倾向边想边做边修

这两个名字本集只点名不展开，是给 8-7/8-8 留的钩子。

3. 没 get 的点

  • “动态 Agent 分配与调度”（frame 11）到底是规划模块的内置能力还是独立的调度器？图上画的位置很暧昧。
  • 隔离容器具体怎么落地——Manus 闭源没说，OpenManus 是用 Docker 还是轻量 sandbox？等之后挖源码。
  • OpenManus 的”模块化 Agent”到底是 Python class、插件机制还是配置文件？本集只用”搭积木”这种比喻带过。
  • PlanAct 和 ReAct 究竟用在哪一层——外循环 PlanAct + 内循环 ReAct？还是按 Agent 类型选？等 8-7/8-8。

4. 跟其他集连接

  • 上承 3-12：3-12 给的”多 Agent 五步骨架 + 单 Agent 五步循环 + 骨架嵌套”在这一集变成具体案例——Manus 的外/内循环就是骨架嵌套的实物。
  • 上承 3-11：第一次把 Manus / OpenManus / JManus 三者并列摆出来，但没讲为什么是这个链路；本集把”为什么 JManus = Java 版 OpenManus”补齐了。
  • 上承 3-9：3-9 的”主管 + 专科”模型在本集对应”规划模块 + 执行模块”。
  • 下启 8-7/8-8（推测）：PlanAct 和 ReAct 两个思考框架将单独展开。
  • 下启 7-10 / 4-9：JManus 的具体实现（DAG Graph + OverAllState）你已经在工作流章节见过细节，本集是给那些细节补”为什么这么设计”的源头。
  • 横向 5-5：5-5 的”主管 Agent / 汇总 Agent”和本集的”规划模块 / 执行模块”是同一件事在不同抽象层（团队组建层 vs 架构层）的描述。
