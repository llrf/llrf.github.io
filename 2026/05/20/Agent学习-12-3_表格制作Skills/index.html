1. 一句话定位

把”以文件形式加载 Skill”换成”以 classpath 资源形式加载”，顺手演示”通用 Skill 不自己写，去聚合平台直接抄”——景点推荐留给你自己写，表格制作让有赞 skill0.io 替你写。

2. 主体

2.1 加载方式要换：从文件路径换到资源仓库

上一集你写的是这样的代码——SkillFileRepositoryAdapter 拿着一个磁盘上的文件路径去读 SKILL.md：

这个写法没错，但和官方推荐的目录结构对不上号。你的 Skills 文件夹本来就是丢在 src/main/resources/skills/ 下面的——它是 资源，不是任意磁盘文件。所以正确的加载器应该是”从 classpath 资源仓库读”，而不是”从文件系统读”。

2.2 但是版本对不上：1.0.8 没有 ClasspathSkillRepository

这是这一集最绕的一步，第一遍不看版本号会以为讲师在自相矛盾：

  • 文档推荐的 ClasspathSkillRepository 是 1.0.9 才有的类。
  • 当前工程用的是 1.0.8，你根本拿不到那个类。
  • 1.0.8 能用的是 JarSkillRepositoryAdapter——而它已经被标记 deprecated。

加工增量：这条路径反直觉的地方在于——“用文档明确说已废弃的那个类才是当前正确做法”。文档是反向指路的：它在告诉你”未来要换，但现在还得用旧的”。所以 1.0.8 里你照着文档的”反面”去抄就对了。等升到 1.0.9，整段就是简单的类名替换（再补 try-with-resources），构造参数 "skills" 不变。

2.3 别自己造轮子：去 Skills 聚合平台抄

景点推荐是业务定制，你必须自己写；但表格制作、PDF 操作、浏览器控制这些 通用能力 早就有人写好了。Skills 是 Anthropic 开源生态里的”组件”，已经形成了像 npm 那样的市场。

这一集推荐的平台是有赞的 skill0.io，截图时收录已经过 423 个 Skill：

搜 xlsx → 选一个 → 进入详情：

注意右边的文件树——一个完整的表格制作 Skill 总共就两个文件：

  • SKILL.md：技能描述（必备）。
  • recalc.py：Python 脚本，干实际的 xlsx/csv 读写。

反直觉点：Java 工程里跑 Python？是的。Skill 在运行时拉这个脚本去执行，不是 JVM 直接跑——Skill 框架内部有自己的脚本执行路径（具体怎么调，本集没展开，留给”待查”）。

2.4 复制不是开箱即用：必须补 SKILL.md 三件套

把下载来的两个文件丢进 resources/skills/Make-A-Table/ 子目录：

然后打开 SKILL.md，你以为可以直接跑了？不行。框架会校验三件东西：

字段 不写的后果
name 报错（不能为空）
description 报错（不能为空）
核心能力（capabilities） 报错（内容不能为空）

本集补的”核心能力”就是把这个 Skill 能干什么列清楚：

  • 创建表格
  • 编辑表格
  • 数据分析、格式设计……
  • 针对 Excel（.xlsx / .xls）与 CSV

加工增量：所谓”从市场下载 Skill”≠”零配置”。聚合平台给你的是 Skill 模板，落到具体框架（AgentScope-Java）还得手动补 frontmatter。如果该平台的 Skill 是面向 Claude Code 写的，移植到 AgentScope 是否要每次改字段命名（中文”核心能力”段 vs 英文 capabilities），这个迁移成本本集没量化——是真实使用时需要踩坑的地方。

2.5 结果：两枚 Skill 同时进 SkillBox

收尾的代码是清爽的——SkillBox 里平铺两个 AgentSkill：一个你自己写（业务定制），一个从市场抄（通用能力）。这就是 Skill 来源的双轨范式。

3. 没 get 的点

  • recalc.py 在 Java 工程里到底怎么被执行？Skill 框架内置了一个 Python runtime，还是 shell 调本机的 python？环境依赖（pip 包）谁来声明？这些本集只字未提。
  • JarSkillRepositoryAdapter 升级到 ClasspathSkillRepository 时，构造参数 "skills" 真的可以原样不动吗？要等 10-7 或 12-4 那边验证。
  • skill0.io 上的 Skill 多数是给 Claude Code 写的（英文 frontmatter），移植到 AgentScope-Java 是否每次都要手动改字段？这条决定”下载即用”的真实人力成本。
  • SkillBox 注册顺序是否影响 LLM 选择 Skill 的优先级？本集没提，需要后续验证。

4. 跟其他集的连接

  • 上承：10-5 Skills的文件结构标准 立下”SKILL.md 必须有 name/description/能力描述”的规矩，本集是那条规矩的运行时验证——少一项就报错；12-1 行程规划经理挂载Skills 与 12-2 有限预算内规划精彩旅行的Skills 已经把 SkillBox + 文件式加载跑通，本集只是把”加载方式”从磁盘路径换成 classpath 资源。
  • 下启：10-4 Skills的渐进式加载机制 给的是”按需展开”的理论，12-4 Skills实现Agent工具的渐进式加载 接着把本集这两枚已注册的 Skill 在运行时按需展开，落地那套理论。
  • 横向：10-7 SpringAi_112实现Agent装载Skills 在 SAA 1.1.2 + Hook 体系里用 ClasspathSkillRegistry 干”等价”的事，相当于本集 ClasspathSkillRepository 的 Spring AI 平行宇宙；本集”去市场抄 Skill”的思路和 3-6 体验MCP：Jmanus配置MCP服务 里的”魔搭社区 MCP 广场”同构——MCP 和 Skills 这两条线各自起了一个生态市场。
