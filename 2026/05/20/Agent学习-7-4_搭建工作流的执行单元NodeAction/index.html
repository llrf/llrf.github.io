搭建工作流的执行单元：NodeAction

一句话定位

上一集 new 出 StateGraph 之后，这一集教你把”节点”塞进去——addNode(id, AsyncNodeAction) 是入口，但真正要写的那个类叫 NodeAction，里头唯一一个 apply(state) 方法就是节点干的所有事。

增量加工：这是个纯胶水方法。你写同步逻辑，框架替你套异步壳。所以视频里那句”基于异步的节点操作”，对你写代码这一侧来说没意义——你永远只跟同步的 NodeAction 打交道。

增量加工：返回的 Map 不是直接覆盖 OverAllState——框架会按上一节 KeyStrategy 配置的策略合并（key1 是 Replace 覆盖、key2 是 Append 追加，参考 7-2）。所以 return new HashMap<>()（空 map）跟 return null 效果一样：什么都不改。本集只是占个位，没演真改值。

增量加工：这是个命名分层提醒——OverAllState 里的 key、节点对象、节点 id（addNode 第一个参数那个字符串）是三回事，别串台。

知识地图

自测题（5 卡）

Q1：stateGraph.addNode 有 5 个重载，为什么挑 (String, AsyncNodeAction) 而不是 (String, Node)？
A：三个核心重载互相嵌套，(id, AsyncNodeAction) 调 (id, AsyncNodeActionWithConfig) 调 (id, Node)，(id, AsyncNodeAction) 是最外层入口，参数最少最干净。剩下两个 subGraph 重载是子图嵌套，本集用不上。

Q2：AsyncNodeAction 名字带 Async，为什么我们写的 NodeAction 是同步的，没写 CompletableFuture？
A：AsyncNodeAction.node_async(NodeAction) 是静态胶水方法，内部用 CompletableFuture.complete(syncAction.apply(t)) 把同步逻辑包成异步——异步机制由框架代劳，你只写同步。

Q3：NodeAction.apply 返回的 Map<String, Object> 是直接覆盖 OverAllState 吗？
A：不是。框架按上一节 OverAllStateFactory 里注册的 KeyStrategy 合并——Append 策略追加、Replace 策略覆盖。所以返回空 Map 等于什么都不改。

Q4：NodeAction 是函数式接口，按理可以用 lambda 一行写完，为什么本集要单独建 Node1 类？
A：项目里会加多个节点，lambda 全堆在 GraphConfiguration 同一个方法里会乱。把每个节点拆成独立类（放在 demo.aiagent.node 包下），清晰且可复用。

Q5：视频里第一次把节点类命名为 Key1，为什么改成 Node1？
A：key1 是 OverAllState 里那个 KV 的 key 名（用于 state.value("key1")），不是节点。节点对象、节点 id（addNode 第一参数）、state 的 key 是三层不同概念，命名要分开避免串台。
