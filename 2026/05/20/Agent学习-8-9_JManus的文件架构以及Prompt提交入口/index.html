8-9 JManus的文件架构以及Prompt提交入口

1. 一句话定位

把 JManus 当库二次开发之前，得先认门——这一集教你两件事：12 个顶层包看名字猜职责、用户 prompt 进门的第一站是 planning/controller/ManusController.executeQuery。

2. 主体

复刻，不是借鉴

讲师在开头反复”借鉴”了五分钟，最后才把口径定死：JManus 就是 OpenManus 的 Java 复刻。OpenManus 用 Python，JManus 用 Java（视频里念成”沙瓦”，转写器没识别出来）。所以你前面所有 OpenManus 的理论都能原样套——两条骨架（PlanAct + ReAct）、两个 AI 自循环、工具驱动、多智能体，一个不少。

为什么要看代码？讲师明说了：不是用可视化界面玩 JManus，而是把它当多智能体引擎嵌进自己的小程序。要嵌就得改，要改就得摸清骨架。

12 个顶层包，看名字猜职责

包路径 com.alibaba.cloud.ai.example.manus.*，外加一个入口类 OpenManusSpringBootApplication。

框架内置类（六个）

  • agent/ — 智能体的属性 / 创建工具类
  • llm/ — 调大模型
  • tool/ — 工具箱（工具驱动的实体）
  • workflow/ — 工作流
  • prompt/ — 提示词工程
  • event/ — 任务事件

用户扩展类（一个，反直觉）

  • dynamic/ — 中文叫”动态”，但不是动态生成，是用户自定义。打开看子目录就明白了：agent/ + mcp/ + prompt/ + cron/ + dialect/ + memory/ + model/ + namespace/——这些都是给你扔自己东西的位置，跟 agent/（框架内置）形成对比。

持久化类（一个）

  • recorder/ — 不是日志！里面是 entity/ + repository/，是执行记录的实体类 + 持久化。Java 后端的同学看到 entity 秒懂。

配置/工具类（三个）

  • config/ — 配置
  • exception/ — 异常
  • i18n/ — 国际化

核心（一个）

  • planning/ — 整个 JManus 架构的核心包。下集详讲，本集只敲门。

[取舍] 讲师过包的时候是按 IDEA 目录顺序念的，没分类。我把”反直觉的两个”（dynamic/ 和 recorder/）从清单里拎出来单标，因为这俩第一次看名字一定误解。

planning 包不是”计划”那么单纯

几个值得画框的点：

  1. memoryId 和 planId 不是一回事。planId 是单次执行标识，memoryId 是会话记忆 ID——用来串联同一个会话的多轮对话。memoryId 是 8 位随机字母（RandomStringUtils.randomAlphabetic(8)），不是 UUID。
  2. executeQuery 不直接执行。它只做三件事：收单 → 装 ExecutionContext → 丢给 PlanningCoordinator。真正干活的是工厂产物。
  3. 异步立即返回。CompletableFuture.supplyAsync 把任务塞到线程池，controller 立刻返回 taskId 给前端，让前端拿 ID 后续轮询/订阅。
  4. PlanningFactory / PlanningCoordinator 是下一集的主角。本集到这里收尾，留扣子。

ExecutionContext 五件套

把 prompt 进门后，所有上下文都被打包进一个 ExecutionContext 对象，看代码里 setter 的顺序就是五个字段：

字段 含义 来源
userRequest 用户原始 prompt request.get("query")
currentPlanId 当前计划 ID PlanIdDispatcher.generatePlanId()
rootPlanId 根计划 ID（= planId） 同上
needsSummary 是否需要总结 硬编码 true
memoryId 会话记忆 ID 用户传 / 随机 8 字母

rootPlanId = planId 这一行有点神秘——本集没展开。猜测是为了支持子计划：如果一个计划被切分成多个子计划，每个子计划有自己的 planId，但 rootPlanId 都指向最初的那个，方便追溯。

3. 没 get 的点

  • PlanIdDispatcher.generatePlanId() 内部到底什么格式？UUID？时间戳？带前缀？讲师只说”生成唯一 ID”。
  • rootPlanId = planId 为什么需要 root——是不是说明子计划有自己的 planId，root 用来追溯？本集没证实。
  • needsSummary = true 到底控制什么？是给用户的最终总结，还是中间步骤的反思？
  • memoryService.saveMemory(new MemoryEntity(...)) 在 supplyAsync 里、executePlan 之前调用——是先建空壳再边跑边填，还是只是创建一条会话记录？
  • /api/executor/execute 和 /api/executor/executeQuery 架构图上都画了，但视频只讲了 executeQuery。execute 是不是另一个 endpoint？submitUserInput / getExecutionDetails 这些方法也没展开。
  • JManus 用的是 SAA 1.0 还是 1.1？这影响后面看代码时 ReactAgent / Graph 这些 1.1 才有的 API 会不会出现。

    • 跟 6-2 同根——都基于 Spring Boot + SAA，@PostMapping / @RequestBody 那套是同一个技术栈。
