9-10 远程Agent封装为工具执行子任务

1. 一句话定位

把远程 Agent 在主管侧”变形”成一个 @Tool 方法——LLM 派单时完全看不出这次调用跨了进程。

2. 主体

2.1 整张图：你站在哪一侧

9-9 干的事情是图右边那两个绿框——路线制定 / 行程规划 Agent 把自己的 AgentCard 写进 Nacos。这一节你站到图左边那个”主管 Agent 节点”里，要解决两件事：

  1. 怎么去 Nacos 把卡片读出来；
  2. 读出来之后怎么让 LLM 顺手就能调。

讲师的想法（也是本集骨架）：远程 Agent → 封装为工具 → LLM 当本地工具调用。这条思路顺得起来，靠的是 AgentScope 的 @Tool 注解机制。

加工增量：AiFactory.createAiService 这个命名是陷阱——它是 com.alibaba.nacos.api.ai.AiFactory，Nacos 自己的 AI 模块工厂，返回的是 Nacos 的客户端 AiService，跟大模型一点关系没有。第一次看到很容易被骗去翻 SpringAI 的 ChatClient 文档，浪费 10 分钟。

另外 Properties properties = new Properties() 会冒红线，因为 AiFactory.createAiService 抛 NacosException（受检异常），方法签名必须 throws NacosException，这是无法绕开的”必经之痛”。

讲师演示完两个方法都把这坨复制了一遍，然后才下沉到 commons/utils/NacosUtil.getNacosClient()——这就是教科书级的”先重复、再抽象“演化路径，工程上完全合理。

2.4 把工具挂到主管 Agent

加工增量：在调用面上，callRouteMakingAgent() 和 callLocalCalculator() 对主管 LLM 来说是同一种东西——都是”一个有 description 的方法”。LLM 看的是 @Tool 的 description 字符串，完全无感这一次是本地计算还是跨进程 RPC。这就是 “Agent-as-Tool” 模式真正的爽点。

3. 没 get 的点

  • agent.call(...) 这一行的入参是什么？视频里讲师写空参就过去了，但 AgentScope 文档示例是 agent.call(userMsg).block()。子任务的 Prompt 到底是 @Tool 方法的入参（让 LLM 按 description 自己填）、还是 toolkit 框架自动注入用户原始消息？下一两集应该会补。
  • @Tool 方法返回 void 的话，远程 Agent 的回答怎么回流到主管 LLM？看本集最后 Variable 'agent' is never used 的 IDE 警告，似乎 .call().block() 还没真接到返回值，下集大概率要补 return msg.getText() 之类。
  • 卡片名 RouteMakingAgent / TripPlannerAgent 在 9-9 里到底是从哪一行注册进去的？回看 9-9 的时候要逐字符对一遍——这玩意儿没有编译期检查。
  • ASR 这次有个全局陷阱：NECUS 全都是 Nacos 的识别错误，读 transcript 时要在脑子里自动替换。

4. 跟其他集的连接

上承

  • [9-9 路线制定 / 行程规划 Agent 注册到 Nacos]（推断）—— 本集是它的对偶面：9-9 干的是服务端 A2AServer 把 AgentCard publish 上去，本集干的是客户端 A2aAgent 把 AgentCard pull 下来。.name() 这个字符串是两侧握手的唯一锚点。
  • 4-11 A2A 三组件 —— Provider / Registry / Consumer 那套骨架在这里复用：Provider = 9-9 的两个 A2AServer，Registry = Nacos，Consumer = 本集的主管 Agent。只是这回 SDK 换成了 AgentScope。

下启

把这个 RemoteAgentTool 挂到 ToolkitBuilder 里之后，主管 ReactAgent 就完成了”嘴和手”的对接。下一两集应该会跑端到端流程：用户输入 prompt → 主管 LLM 思考 → 选 callRouteMakingAgent → 远程执行 → 反馈 → 选 callTripPlannerAgent → ……，顺带把 agent.call() 的入参和返回值的”信息流”补完整。

横向

  • 4-14 A2A 服务发现 —— 同一件事的 SAA（Spring AI Alibaba）版本：那边叫 A2aRemoteAgent.builder().name(...)，这边叫 A2aAgent.builder().name(...).agentCardResolver(...)。name 即 Nacos 查询键 这条铁律两边都成立，是 A2A 协议本身决定的、不是某个框架的怪癖。
  • 6-7 组建旅游规划 Agent 团队 —— 那一集的 AgentTool.getFunctionToolCallback 是 同进程 的 Agent-as-Tool，本集是 跨进程 的 Agent-as-Tool。封装目标完全一致（让 Agent 长得像 Tool 给 LLM 选），实现路径不同。
  • 3-10 A2A 协议 —— 提供”为什么要发现”的协议层动机；本集是”在 AgentScope 里怎么做发现”的落地。

5. 知识地图

6. 自测题

  1. A2aAgent.builder().name("xxx") 这里的 "xxx" 是给本地变量起名、还是别的什么？写错了会发生什么？
  2. 为什么 AiFactory.createAiService(properties) 这一行常被新人误以为是创建大模型客户端？它实际返回什么？
  3. 主管 Agent 这一侧在 A2A 协议里扮演什么角色（服务端 / 客户端 / 注册中心）？9-9 干的事和本集干的事在协议层是什么对偶关系？
  4. AgentCardResolver 有 4 种实现，本集用的是哪一种？为什么不直接用”传一个 AgentCard 对象”那种最简单的？
  5. 一个加了 @Tool 的方法，对主管 LLM 来说，”本地工具”和”包装好的远程 Agent”长得一样还是不一样？为什么这件事是本节的”灵魂”？

7. 关键词表

术语 一句话
A2aAgent AgentScope 里”远程 Agent 的本地代理”客户端类，builder 三件套：name / resolver / build
AgentCardResolver 解析 AgentCard 的接口，4 种实现：直接卡 / WellKnown URL / Nacos / 自定义 Lambda
NacosAgentCardResolver Resolver 的 Nacos 实现，依赖一个 Nacos 的 AiService 客户端
AiFactory.createAiService 命名陷阱：是 Nacos 的 AI 模块工厂，跟大模型无关，返回 Nacos 客户端
.name() 即查询键 builder 里的 .name() 字符串是 Nacos 查 AgentCard 的 key，必须和注册名一字不差
agent.call().block() A2aAgent 是反应式 API，.block() 强制阻塞拿同步结果
@Tool 包装远程 Agent 让远程 Agent 长得像本地工具，LLM 派单时跨进程完全透明
NacosUtil.getNacosClient() 创建 Nacos 客户端那坨样板代码下沉到 commons 模块的复用工具方法
