9-9 团队成员的智能体卡片注册到Nacos

发表于2026-05-20|更新于2026-05-20|Agent学习第09章 Docker 部署分布式 Agent 搞定旅游规划
|浏览量:

1. 一句话定位

把上一集主管 prompt 里写死的”下属能干啥”，换成让远程 Agent 自己把卡片注册到 Nacos，让主管去注册中心捞——这一集只做”注册”这一半。

2. 主体

上集的”反例”先记牢

上一集（9-8）是这样玩的：你在主管 Agent 的 prompt 里硬塞一段文本，告诉它”routeMakingAgent：擅长处理自驾游路线制定 / tripPlannerAgent：擅长处理景点行程规划”，它就照着分发。

这能跑，但味儿不对——智能体的能力不应该由你手抄进 prompt，应该由主管自己去发现。所以这一集开始改造。

角色定位先扳过来

这是反直觉的第一关。直觉上”主管说了算”，但在 A2A 协议里：

  • 远程 Agent（TripPlannerAgent / RouteMakingAgent）= 服务端，因为它们是能力的提供者，要把卡片亮出来；
  • 主管 Agent = 客户端，它是消费者/发现者，从 Nacos 里捞别人的卡片。

这集只做服务端这半边——把 TripPlannerAgent 的卡片注册上去。客户端（主管怎么发现）留到 9-10。

卡片 name 必须等于 Agent name

这是铁律，不是建议。Nacos 那边搜服务靠 AgentCard.name 当主键，主管 Agent 上门发现的时候也是按这个 name 对齐回 ReActAgent。两边写不一致 = 卡片注册上去也搜不到 = 静默失败，最难调。

Skills 这次先不填——ConfigurableAgentCard 支持塞一组 AgentSkill（参考文档示例 text-generation / question-answering），但本集只搞 name + description，能力路由那块留到后面。

3. 没 get 的点

  • Skills 这次留白。后续主管发现卡片做任务分派时，匹配键到底是 name 还是 skills？光看本集不知道。
  • ConfigurableAgentCard 跟 SAA 1.1 那套 AgentCardProvider/AgentCardWrapper（4-15）是简单换皮还是数据结构本身有差异？老师只说”方式没大变”，没拆。
  • 多个 Agent 用同一个 name 注册到 Nacos 会冲突、覆盖、还是分实例？没演示。
  • 视频里有红线没看到剪辑后是否真的能起服务，得对照 9-10 开头能否成功发现。

4. 跟其他集的连接

  • 上承 9-8（主管 Agent 分发任务给相应 Agent）：同一个问题——主管怎么知道下属能干啥——上集用 prompt 硬塞，本集换成自动发现。机制升级，目标不变。
  • 上承 6-10（构建 ReActAgent）：本集要包装的 ReActAgent.Builder 就是从那里学的 AgentUtils.getReActAgentBuilder(...)。
  • 横向 4-13 / 4-14 / 4-15（SAA 1.1 的 A2A 服务注册 / 发现 / AgentCard）：同构对照组。老师强调 AgentScope 基于 SAA，本集就是把那一套在 AgentScope 框架下原样重写。
  • 横向 3-10（多 Agent 跨部门协作 A2A 协议）：那是协议层概念图，本集是框架落地。
  • 下启 9-10（远程 Agent 封装为工具执行子任务）：卡片注册好之后，主管要”发现+当工具调用”，本集只完成”注册”这一半。

5. 知识地图

6. 自测题

  1. 为什么提供能力的远程 Agent 是 A2A 的服务端，而主管 Agent 反而是客户端？
  2. AgentScopeA2aServer.builder(...) 的参数应该传 ReActAgent 还是 ReActAgent.Builder？为什么这么设计？
  3. application.yml 里 nacos.server-addr 为什么写在 agentscope.a2a 节点下面而不是顶层？
  4. ConfigurableAgentCard.name 与 ReActAgent.name 不一致会导致什么后果？错误是显式报错还是静默失败？
  5. 本集的两件套 starter 分别是 agentscope-a2a-spring-boot-starter 和谁？为什么需要后者？

7. 关键词表

术语 一句话
A2A 协议 Agent-to-Agent，远程 Agent 互相发现/调用的协议
A2A 服务端 / 客户端 提供能力的 Agent 是服务端，主管（消费者）是客户端
AgentCard（智能体卡片） name + description + skills 的元数据，注册到 Nacos 供检索
ConfigurableAgentCard.Builder AgentScope 提供的卡片构造器
AgentScopeA2aServer.builder 把 ReActAgent.Builder + AgentCard 组装成可注册的服务端
Builder 传 Builder 传 ReActAgent.Builder，不是已 build 的 Agent，生命周期交框架
name 一致性铁律 AgentCard.name 必须等于 ReActAgent.name，否则 Nacos 搜不到
@agentscope.a2a.server.enabled yml 里的 A2A 服务端总开关
