7-10_SpringAi_Alibaba11的Graph引擎

发表于2026-05-20|更新于2026-05-20|Agent学习第7章 Graph 搭建旅游规划工作流，像拼积木一样轻松
|浏览量:

1. 一句话定位

SAA 1.1 的”多智能体”在文档里有两条腿——Agent Framework（4-9~4-16 那条 A2A 主线）和 Graph 引擎；这一集只走 Graph 这条腿，结论是：1.0 时代你写过的工作流代码，1.1 直接拿来跑，API 一字未改。

2. 主体

2.1 文档目录就是这一集的地图

打开 SAA 1.1 文档首页，”多智能体”和”工作流”并列被标为两大核心；点进多智能体下一层，你会看到两个兄弟节点——Agent Framework / Graph。注意这里的”加工增量”：很多人会以为这俩是新旧替代关系，实际上它们是同级并列的两种实现风格，你既可以用 ReactAgent/FlowAgent 写”协同派”，也可以用 StateGraph 画”工作流派”。本集所有内容都在 Graph 这一支的子树里。

2.2 三件套：State / Node / Edge

讲师把摄像头停在文档”核心概念”那一页（frame f005、f010、f016），你看到的就是这三个对象：

  • State：用 OverAllState 这个对象贯穿整个工作流——任何节点都能读写。这跟 4-14 Consumer 那里拿到的 Optional<OverAllState> 是同一个东西，不是两个同名类。
  • Nodes：本体是 AsyncNodeAction 这个函数式接口。重点是函数式——节点不是类、不是 Bean，是个 lambda，写法长这样：node_async(state -> Map.of("messages", List.of(message)))。
  • Edges：本体是 AsyncEdgeAction，也是函数式接口，可以承载条件分支。

你需要在脑子里把这三件套跟 1.0 那几集对齐——讲师每讲一个，都要把 1.0 那一页切回来比一下，传达的信息很直白：完全相同。

2.3 装配三步：StateGraph → addNode/addEdge → compile

并行节点示例的代码（frame f022）是最值得反复看的一帧：

加工增量：注意”并行”是怎么表达出来的——A → A1 / A2 / A3 这三条同源边自动构成扇出，A1/A2/A3 → B 三条同汇边构成汇聚，不存在专门的 ParallelNode 类型。这是 Graph 引擎相对其他工作流框架最值得记的设计点：拓扑结构 = 并发语义。

KeyStrategyFactory 决定 State 的每个 key 怎么合并：三条并行边都写 "messages"，靠 AppendStrategy 把三份结果追加成 list，而不是后到的覆盖先到的。

2.4 编译完了你就拿到 CompiledGraph

workflow.compile() 返回 CompiledGraph，这是真正在运行时被驱动的对象。这一层在 1.0 也是同样的名字、同样的位置，没动过。

3. 没 get 的点

  • KeyStrategyFactory / AppendStrategy / ReplaceStrategy 在 1.0 的工作流课里好像没正式露过面——是 1.1 新加的概念但 API 形态兼容？还是 1.0 已经有只是讲师当时跳过了？回看 1.0 工作流那几集才能确认。
  • frame f020 右栏红字”并行节点的限制：不允许使用条件边”——这个限制是 addEdge 时编译期报错，还是运行时报错？语义上为什么不允许？没说。
  • 文档侧边栏（frame f019）已经列出后面要讲的能力：Redis 检查点持久化、人类反馈（human-in-the-loop）、时光旅行、子图 Subgraphs、给节点分配 MCP 工具——这些都还是名字，落地形态没看到。
  • AsyncNodeAction 的 lambda 和 6-8 那种”Agent 即对象”（ReactAgent / FlowAgent）能不能合流？把一个 Agent 当 Node 塞进 StateGraph，应该就是侧边栏里的”子图 Subgraphs”入口。

4. 跟其他集连接

  • 上承：4-9 把 SAA 1.1 的三大核心标签之一标为 DAG Graph——这一集就是把那张标签摊开。1.0 的工作流课（OverAllState / StateGraph / CompiledGraph 第一次出场）是本集”对比”的隐含基准，每个概念讲师都要切回 1.0 那一页对照。
  • 下启：下一集大概率沿着文档侧边栏走——条件边、并行流式输出、Redis 检查点持久化、人类反馈、子图、给节点挂 MCP 工具。KeyStrategy 的细节也会在后面补齐。
  • 横向：
    • 跟 4-9~4-16 A2A 主线并列：A2A 解决”跨进程多 Agent”，Graph 解决”同进程 DAG 编排”，两条腿走多智能体。
    • 跟 6-8 ReactAgent / FlowAgent / ParallelAgent / SequentialAgent / LlmRoutingAgent 高度同构——那一集”Agent 当节点”的写法，本质是给 Graph 套了 Agent 层壳；OverAllState 在两边都是同一个状态包（4-14 也用过）。
    • 跟 3-12 多 Agent 五步骨架是”概念图 vs 框架落地”的关系：3-12 讲分工和通信抽象，Graph 把”通信”具体落成 State 的读写。
