10-04 Skills的渐进式加载机制

发表于2026-05-20|更新于2026-05-20|Agent学习第10章 Skills 让 Agent 按照专业流程工作
|浏览量:

1. 一句话定位

Skills 文件夹塞了一堆东西（领域知识、流程模板、工具说明、脚本资源），但它不一次性灌进上下文——分三段按时序拉，先目录、再工具、最后资源。

2. 主体

痛点先摆出来

上一集说 Skills 是”技能系统”，比 MCP 多出了领域知识 + 工作流程模板。你立刻应该有一个疑问：

MCP 一股脑把所有工具推过来已经把上下文撑爆了。现在 Skills 文件夹里东西更多——知识、流程、说明书、脚本、资源——这不是更糟？

Skills 的设计就是回应这个疑问的。它把”加载”拆成三段，每段时机不同。

三段加载（时序很关键）

阶段 加载什么 触发时机 大小
① 元数据 技能名称 + 描述 + 操作步骤索引 Skill 一被挂上就读 极小
② 工具 这次任务真正要用的那几个工具 智能体读完元数据、确认要执行时 中等
③ 附加资源 脚本、指令、参考资料 执行到具体那一步时 不定，按需

注意第 16 帧画布上写得很直白：元数据 → 技能名称 / 描述 / 操作步骤，旁边一行小字”完成之后被释放”。元数据本身就是被设计成可丢弃的临时路标。

元数据 = 路标，不是知识

这一点反直觉。你直觉上以为”加载一个 Skill”就是把那个目录读进来。其实只读了一个类似 README 的索引文件。智能体看到的是：

名称：财务月度结账
描述：处理某某流程的标准方法
步骤索引：1. 拉数据（用工具 A）；2. 对账（用工具 B）；3. 出报表（脚本 X）

——它知道往哪走，但还没真的走过去。具体的知识、工具实现、脚本内容都在文件夹里躺着，等被点名。

【加工增量】视频里讲师反复说”夹载”（粤/台口音的”加载”），消化稿提示过这个点。第一遍听容易卡壳，意识到是”加载”以后整集就顺了——这里我直接用”加载”。

工具按需：主动方反转

最有意思的是第二段。原本 MCP 是 push 模式：服务端有多少工具，全部塞回来。智能体被动接收，自己挑。

挂上 Skills 之后变成：智能体读完元数据，知道”我这个任务只要工具 A 和工具 B”，于是反向告诉 MCP：

你只回传这两个，其他别给我。

主动方从 MCP 翻转到 Skills。MCP push → Skills pull，是这一段的关键差异。

【困惑标注】消化稿里也提了：协议层这一步是怎么实现的？MCP 本身好像没有”过滤回传”的接口，可能是 Skills 在客户端侧做的筛选，而不是真改了 MCP 服务端的行为。本集没讲细节，先记着。

附加资源：最晚的那一段

第三段更靠后。工具的元数据先进上下文，但工具执行过程中可能要调脚本、读指令——这些等到工具真正运行到那一步时才加载。即使脚本就和工具说明放在同一个 Skills 文件夹里，也不会和工具元数据一起被拉进来。

逻辑就是一个：”反正没用上就先不读，省 token”。

3. 没 get 的点

  • 元数据的物理载体到底是 SKILL.md 顶部的 YAML frontmatter，还是单独一个 manifest？视频没给文件示例。
  • “Skills 告诉 MCP 只回传两个工具”——协议层落地细节空白。猜测是客户端侧 filter，但没确认。
  • 三段加载是 Claude Code 内部约定，还是 Skills 规范本身定义的？跨厂商一致性不明。
  • 元数据加载到上下文后，如果智能体判定这个 Skill 用不上，元数据会被释放吗？还是占满整个会话？画布上写”完成之后被释放”，但没说什么时候判定为”完成”。

4. 跟其他集的连接

  • 承 10-3：上一集定性 Skills 是”技能系统不只是工具”，但留了个隐忧——文件夹这么大不会撑爆上下文吗？这一集就是回答。
  • 承 3-7 / 3-8：那两集已经在概览层提过”工具按需加载”和”三段渐进式”，但偏概念图。本集把三段的时序、各段加载内容、谁主动谁被动讲清楚了。
  • 横向呼应 SubAgent：SubAgent 用独立上下文隔离来治”主上下文爆炸”，Skills 用按需加载来瘦身。两条不同路径，目标一样。
  • 下启：接下来应该会展开 Skills 的目录结构（SKILL.md 头部、scripts/、resources/ 子目录），以及多 Agent + Skills 怎么组合（每个 SubAgent 挂自己的 Skill）。

5. 知识地图

6. 自测题

  1. Skills 文件夹很大，但加载到上下文里的”第一段”为什么不会撑爆窗口？这一段里具体有什么？
  2. 在挂 Skills 之前，MCP 默认的工具加载方式是什么？挂 Skills 之后，主动方发生了什么变化？
  3. “附加资源”和”工具”都在 Skills 文件夹里，为什么前者比后者还要更晚才进上下文？
  4. 元数据被描述成”路标”。这个比喻在说什么——元数据不是什么、是什么？
  5. 如果你给一个会计领域的 Skill 写元数据，至少要包含哪三类信息？

7. 关键词表

术语 一句话解释
渐进式加载 三段时序拉取，不是一次性灌满
元数据索引 技能名称 + 描述 + 操作步骤索引，文件极小，先行进入上下文
工具按需加载 Skills 反向叫 MCP 只回传需要的工具
附加资源按需加载 脚本/指令等到执行到具体那一步才进上下文
Skills 文件夹 物理上很大（知识/流程/工具说明/脚本），逻辑上分级暴露
上下文窗口保护 渐进式加载的根本目的——避免 token 浪费、避免无关内容堵塞
MCP push vs Skills pull MCP 默认全量推送，Skills 按需拉取，二者协同
路标而非知识 元数据告诉智能体”该往哪走”，真正的知识等走到了再取
