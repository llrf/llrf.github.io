旅游规划打印出Agent的深度思考

一句话定位

你前几集写好的 planHook 有时候打印思考段是空的——这一集告诉你，问题不在 Hook，而在模型有没有”开思考”这件事，开关在 AgentUtils.getReActAgentBuilder 里调 enableThinking(true)。

主体

现象：Hook 看起来”时灵时不灵”

你回想一下：在 9-7 和 11-8 里，你已经挂过一个 planHook，钩在主管 Agent 的推理事件槽上，专门把”推理过程”打到控制台。但跑业务的时候，思考段时不时是空的。

第一反应大概是去翻 Hook 代码找 bug——别去。这事跟 Hook 一点关系都没有。

加工增量：Hook 不生产思考，只搬运思考。它从 LLM 返回里捞 reasoning_content 字段，模型不填这个字段，Hook 拿到的就是 null。看起来像 Hook 失灵，实际是上游 LLM 根本没在思考。

百炼把模型分两类

打开阿里云百炼文档 → 模型推理 → 文本生成 → 深度思考。这一页列得很清楚：

  • 混合思考模式：支持思考，但可关。用 enable_thinking=true/false 控制。Qwen3.5 系列代表。
  • 仅思考模式：恒开思考，关都关不掉。DeepSeek-R1 代表。
  • 不支持思考：思考字段永远是空，怎么调 Hook 都没用。

再叠一层商业版/开源版的差异——qwen3.5-plus / qwen3.5-flash 商业版默认开思考，开源版（397b / 122b / 27b / 35b 那一票）也支持但要你显式开。普通免费的 qwen-plus 默认不思考。

取舍：教学项目用 DeepSeek-R1。理由很简单：仅思考模式，省去配置心智，连 enable_thinking 的开关都不用纠结。代价是它思考的时候偶尔冒英文——一个咖啡馆的中文问题，思考链可能用英文 reasoning。课程没去治这个，你也别治。

开关在哪开

不是 Hook 层，不是 ReActAgent 层，是更底下的模型 builder 层。

公共模块 AgentUtils.getReActAgentBuilder 里有 DashScopeChatModel.builder()，链式调一下 .enableThinking(true) 就完事了。这一行对应百炼 API 的 enable_thinking 参数。

注意这个解耦：Hook 负责读、模型 builder 负责开。两层分开改，互不污染。

两条管道：reasoning_content vs content

百炼把响应拆成两个字段：

  • reasoning_content → 装思考链（”先想”那一段）
  • content → 装最终回答（”后说”那一段）

planHook 抓的是前者，最终 response 拿的是后者。两条管道并行，所以打印顺序大概是：

  1. Agent 使用的大模型: deepseek-r1（builder 配置打印）
  2. 整段 reasoning（Hook 抓 reasoning_content）
  3. 最终回答（response 里的 content）

副作用：等待时间变长（思考要 token），百炼文档默认给的示例都是流式输出——不流式你就盯着黑屏等。

验证

通过 imooc-charge-station 接口 POST /trip，prompt 用一个语义题：

在咖啡馆里想要杯星巴克，这里的星巴克指代的是什么？

DeepSeek-R1 会在 reasoning 里把可能性都列一遍——咖啡品牌、当前店即星巴克门店、类似风味的咖啡——然后在 content 里给一个综合回答。日志上你能清楚看到思考过程被完整打印出来。

没 get 的点（留给以后）

  • enableThinking(true) 用在”不支持思考”的模型上，AgentScope 是静默忽略还是抛错？得翻 SAA 源码。
  • DeepSeek-R1 思考冒英文，能不能 system prompt 强制中文 reasoning？教学没碰。
  • 商业版 qwen3.5-plus 计费是不是 reasoning_content + content 总 token 一起算？跟 Langfuse trace 的消耗对得上吗？
  • reasoning_content 进下一轮 history 会不会撑爆上下文窗口？长会话需不需要主动剪 reasoning？

跟其他集连接

  • 上承 9-7：计划和执行中的事件拦截 Hook 定义了 PreReasoningEvent / PostReasoningEvent 这些槽位，本集的 planHook 就是挂在那套槽里读 reasoning。
  • 上承 11-8：人工介入修改主管Agent制定的计划 用 PostReasoningEvent 拦推理结果做编辑，本集是它的”只读打印”版——同一个事件源，不同的消费方式。
  • 横向 13-4：旅游规划Agent团队集成Agent追踪观测 是可观测性的另一条腿——Langfuse 拿全链路 trace，本集的 Hook 拿单 Agent 的内心戏。两条腿一起走。
  • 呼应 3-1：大模型困境 讲”模型能力决定 Agent 上限”——本集是具体实例：你 Agent 能不能”思考可见”，完全卡在模型选型上。
  • 下启 13-7：测试路线制定专员规划最优驾车路线 会在已开思考的链路上跑真业务。

知识地图

自测题

  1. planHook 在控制台打不出思考段，第一嫌疑人是谁？为什么不是 Hook 本身？
  2. 混合思考模式和仅思考模式的区别是什么？各举一个代表模型。
  3. enableThinking(true) 这一行写在哪个文件、哪个方法里？为什么不是写在 Hook 里？
  4. 百炼响应里思考和回答分别走哪个字段？为什么不能合并成一个字段？
  5. 普通免费 qwen-plus 默认开思考吗？想用商业版思考能力得选什么模型？
