8-8 ReAct是灵活应变的基层执行者

1. 一句话定位

ReAct 是 OpenManus 架构里”被分派下来那一只单 Agent”在脑子里跑的循环——想一步、做一步、反思一步、偏了立刻改，专伺候”已经被拆到不能再拆”的叶子任务。

2. 主体

2.1 先回到 OpenManus 那张图

把 f001 这张架构图摊开来看（你之前在 8-7 已经看过一遍）：

  • 左半边”规划模块”上挂着红框 Plan-and-Execute (PlanAct)，标的是”复杂任务”。
  • 右半边”执行模块”上挂着红框 Reason-and-Action (ReAct)，标的是”简单任务”。

第一眼会觉得两个红框是”两种可选思考框架，二选一”。但其实它们是上下级：PlanAct 负责把大需求拆成子任务、派单、监督、动态调整；每一个被派下来的子任务，进到对应单 Agent 内部以后，用 ReAct 跑。

增量加工：讲师把”简单任务”这个词反复说，但没明说”简单 ≠ 容易”。这里你要自己补一刀——“简单”的真正含义是颗粒度已经到底、不可再拆。不是说 ReAct 弱，是它根本不负责拆活儿，它只负责”在叶子节点里把单步走清楚”。

2.2 ReAct 的两个动作（其实是三个）

讲师挂在嘴上的是两个词：Reason（思考） + Action（行动）。但他讲流程的时候其实塞了三段：

  1. 思考（Reason）——拿到任务，先想：
    • 第一步做什么？第二步做什么？第三步做什么？
    • 这件事我手上哪些工具能用？
    • 思考的产出是一个”接下来这一步”的小决策，不是一份大方案。
  2. 行动（Action）——埋头干这一步。调工具，或者输出一段内容。
  3. 反思 / 校准——干完这一步立刻问自己：
    • 这一步的结果对不对？
    • 有没有偏离最终目标？
    • 偏了就马上改，回到第 1 步重新想下一步。

增量加工：原始 ReAct 论文（Yao 2022）里这三段叫 Thought / Action / Observation。讲师把 Observation 合并进了”反思”。你心里要清楚：Observation 其实是看工具回来的结果，而”反思”是基于那个 Observation 做评判——两件事被讲师糊在一起讲了。

2.3 凭什么说”思考”贯穿全程

常人理解的”思考-行动”是先把方案想完再动手，类似瀑布。ReAct 反过来：每一步开干前都要 Reason 一次。所以你眼里看到的不是”想 → 做”，而是循环：

这就是为什么 8-7 那一集里 PlanAct 必须”动态调整子任务执行顺序”——上层一调整，下层每个跑 ReAct 的小 Agent 立刻就感知到、立刻在自己的循环里重新 Reason，整个系统才能”灵活应变”。

2.4 PlanAct 和 ReAct 怎么咬合

维度 PlanAct（上） ReAct（下）
面向 复杂任务 简单（叶子）任务
关键动作 拆 + 派 + 监督 + 调度 思考 + 行动 + 反思
视野 整盘棋 当前这一步
单位 多 Agent 系统 单 Agent 内部
在 OpenManus 图里的位置 规划模块红框 执行模块红框

两层各有反思：PlanAct 反思”子任务结果对不对”，ReAct 反思”我这一步对不对”。层级不同，不冲突——下面校准不动了再反馈给上面，上面再决定要不要换路线。

3. 没 get 到的点

  • “偏了立刻改”具体怎么改？是回退、是重规划、是只调工具参数？讲师没细说。等到 ReactAgent.builder() 的 .saver() / OverAllState 代码层（6-6 / 7-2）才能看清。
  • 讲师把 Observation 合进反思，后面 AgentScope（6-9 / 6-10）里这三段是否会再独立出来？
  • 两层反思的边界——当 ReAct 自己改不动时怎么往上抛？是抛异常、还是写 OverAllState 让 PlanAct 监督节点读到？

4. 跟其他集连接

  • 上承 8-7：PlanAct 那一集只讲了”上面怎么拆、怎么派、怎么调度”，把”被派下来的那只单 Agent 内部怎么执行”留了个口子。本集就是来填这个口子的。回扣 3-12 多Agent的核心执行流程 里的”单 Agent 五步循环”——感知→思考→决策→行动→反思——就是 ReAct 的全展开版。
  • 下启代码层：
    • Spring AI Alibaba 1.1 里 ReactAgent.builder() 是 ReAct 的实例化（6-6）。
    • AgentScope 里 ReActAgent.builder()（6-9 / 6-10）。
    • 多 Agent 团队里被派单的那只”专科 Agent”就是 ReAct Agent（3-9 / 5-2 / 5-3 / 5-4）。
  • 横向 7-13：7-13 总结Agent和Graph分别构建的工作流 里讲的 FlowAgent vs ReactAgent——FlowAgent 只摆队形不思考，ReactAgent 才是本集这套”想-做-反思”心智的代码化身。

5. 知识地图

6. 自测题（5 卡）

  1. ReAct 全称是什么？它和 PlanAct 在 OpenManus 架构图里分别挂在哪个模块上？
  2. “针对简单任务”里的”简单”指的是”容易”还是”颗粒度到底了”？区别在哪？
  3. ReAct 的反思发生在什么时候？为什么不能等任务全做完再反思？
  4. 讲师讲的两步（思考 + 行动）和 ReAct 论文里的三段式（Thought / Action / Observation）差在哪？
  5. PlanAct 已经有”评估子任务结果”了，ReAct 又有”反思”——两层反思怎么分工不打架？
