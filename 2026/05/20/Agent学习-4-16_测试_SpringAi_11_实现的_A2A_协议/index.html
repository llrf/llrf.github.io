测试 SpringAi 1.1 实现的 A2A 协议

1 · 一句话定位

把 4-15 搭好的 Provider / Consumer 两个空架子按下 Run，验证 AgentCard 能自动飞进 Nacos，再被 name 钓回来——一节”接缝在哪”的对账课。

2 · 主体

2.1 先看终态：那张卡片长啥样（加工增量在 §2.1）

讲师顺序是”Provider 跑起来 → 看卡片 → 再写 Consumer”。你换个看法：先盯住 Nacos 控制台里那条记录，整条调用链立刻显形。

卡片上你要认的字段只有四个：

字段 作用 谁在写它
name join key——Consumer 凭它去取卡片 Provider 的 application.yml
version 1.0.0 / 1.1.0 等版本标识 Provider 的 application.yml
服务地址 http://内网IP:8181/a2a，Consumer 拿到后直连这里 Spring 启动时根据 web 端口推出来
协议版本 A2A 协议本身的版本 SAA 框架填

看清这张卡你就明白：A2A 的本质是”卡片即接口契约”——Provider 把契约扔进 Nacos，Consumer 凭一个字符串 name 就能拉到完整契约。Nacos 在这里既是注册中心又是契约仓库。

2.2 Provider 这端：卡片从哪儿冒出来的

启动 Nacos 用 docker（第一章已演示），控制台进 :8088，账号密码都是 nacos。第一次登录会报一次错，忽略，再登一次即可。Nacos 3.1 在原本的 MCP 管理之外新增了 Agent 管理——A2A 这条线就挂在这里。

跑 Provider 之前要拆两颗雷：

雷一·.model(...) 怎么拿 ChatModel？

直觉是 new 出来传进去。实际是方法参数注入：

ChatModel 早在 Spring 启动时被 spring-ai-starter-* 自动注册成 Bean，配置类的 @Bean 方法签名声明它，容器自动按类型喂进来。比 @Autowired 字段干净得多。

雷二·spring-boot-starter-web 必须显式加

A2A 通过 HTTP 暴露端点（http://ip:8181/a2a），Web 容器起不来端点就没了。版本对齐 SAA 自带的 spring-boot 3.4.8，或直接 3.5 也行，不冲突。

Provider 跑起来后控制台刷一下 Agent 列表，那张卡就在了。

2.3 name 一致性约束（取舍出现在 §2.3）

这是整集最容易踩的坑：

两个 name 必须字符严格相等。 SAA 的取舍在这：它没有强制把两者合并成一个变量，而是让你自己保证一致——好处是配置和代码各管各的层（卡片层 vs 执行层），坏处是写错 Consumer 永远找不到对象，且不报错只是”匹配不到”。

你的应对：把 name 提成 application.yml 里的常量，Provider 配置类和 ReactAgent 都从同一 key 读，把”两个 name”折叠成”一个 name”。

2.4 Consumer 这端：A2aRemoteAgent 不是执行体

写一个 Controller 暴露 HTTP 接口，里面调 Service，Service 里 build 一个 A2aRemoteAgent——这是 SAA 封装的远程代理句柄：

它本身不执行任务，只负责”凭 name 去 Nacos 拿卡片 → 拿到服务地址 → 把请求转过去”。真正执行的是 Provider 端的 ReactAgent。

必填三件套是 SAA 1.1 的运行时强校验：description / instruction / shareState(true) 缺一个就 500，逐个补就行。视频里只演示了 description 这一个，剩下两个口头带过——你照单全补即可。

2.5 OverAllState：结果怎么取（本集挖坑）

远程 Agent 执行完，结果存进 OverAllState——一个 key-value 状态对象。本集为了”先验证能调通”把取值代码注释掉了，只在调用成功后打一行 远程Agent被成功调用。后续课程才讲 key 怎么定、怎么按 key 拿 value。

2.6 工程细节：双实例同 IDE 跑

两个模块要在同一个 IDEA 窗口里同时启动，端口分开：

  • Provider · 8181
  • Consumer · 8182

操作：右键启动类 → Modify Run Configuration → Modify Options → 勾 Allow multiple instances。两个启动类都要勾，否则 IDEA 默认只允许一个 main 在跑。

最后用 API Force（或 Postman）打 Consumer 那个接口，Consumer 控制台打印出 远程Agent被成功调用，链路就跑通了。

3 · 没 get 的点

  • ChatModel 走 DashScope 还是 DeepSeek 在哪配？ 本集说”后面课程讲”。猜测是 spring.ai.dashscope.api-key / spring.ai.deepseek.api-key 这种 starter 各自的命名空间，SAA 按 classpath 上有哪个 starter 推断默认 ChatModel——但具体还得等后续验证。
  • instruction 字段的语义。 是 system prompt 喂给远程 Agent？还是只是给 Consumer 自己看的元数据？必填+运行时校验，说明它有用，但本集没演示它怎么影响行为。
  • 服务地址是内网 IP（192.168.31.72:8181）。同机跨进程没问题；生产环境跨网段时，Nacos 拿到的这个地址 Consumer 能不能直连？大概率得配 spring.cloud.nacos.discovery.ip 之类强制公网/服务网格地址，但本集没碰。

5 · 知识地图

6 · 自测题（5 卡）

  1. Q：Provider 的 ReactAgent name 写了 weatherAgent，但 application.yml 里 spring.ai.alibaba.a2a.server.card.name 写成 weather-agent，会发生什么？
    A：Nacos 里会出现一张 name=weather-agent 的卡片，Consumer 用 weatherAgent 永远匹配不到（或匹配错）。两个 name 必须字符严格相等。

  2. Q：A2aRemoteAgent 自己执行任务吗？它要 ChatModel 吗？
    A：不执行。它是”远程代理句柄”——凭 name 从 Nacos 拿卡片、拿服务地址、转发请求。真正干活的是 Provider 端的 ReactAgent，所以 ChatModel 注入在 Provider 那边而非 Consumer。

  3. Q：A2aRemoteAgent.builder() 哪三个字段缺了会 500？
    A：description / instruction / shareState(true)。SAA 1.1 把它们设成运行时强校验。

  4. Q：为什么必须显式声明 spring-boot-starter-web？
    A：A2A 通过 HTTP 暴露端点（如 http://ip:8181/a2a）。没有 Web starter，Spring 不会启 Web 容器，端点就起不来，Consumer 即便拿到服务地址也连不上。

  5. Q：为什么 ChatModel 不用 new 也不用 @Autowired 字段？
    A：ChatModel 已经被 dashscope/deepseek 的 starter 注册成 Bean。@Configuration 类里 @Bean 方法的参数 Spring 会按类型自动注入，比字段注入更简洁也更可测试。
