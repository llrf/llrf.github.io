11-2 测试团队成员基于A2A协议注册到Nacos

发表于2026-05-20|更新于2026-05-20|Agent学习第11章 MCP+A2A，助力旅游规划团队协作
|浏览量:

1. 一句话定位

你按下 Run，看 9-9 那段「自带注册中心 + 手动 build」代码是怎么炸的——然后顺手把它砍掉、改成 Spring Bean 自动注入、再把 pom 改得「主管节点不背锅」，最后到 Nacos 控制台看见 Agent 卡片真的出来了。

2. 主体

2.1 那个让人愣三秒的”病”

视频里讲师反复说「这个病」，听写转录把 Bean 识别成了”病”——你心里得做一次替换，否则前 5 分钟会以为他在讲什么疾病。后面所有”以并的方式自动注入”都按”以 Bean 的方式自动注入”来读。[加工增量]

直接 Run TripPlannerAgentApplication，控制台一行触目惊心的红：

读这条报错时锁三个关键词：

  • 谁炸了：agentScopeA2aServer —— a2a-starter 提供的自动配置类。
  • 从哪来：AgentScopeA2aAutoConfiguration.class —— 你引了 starter，Spring Boot 主动想给你装这个 Bean。
  • 缺什么：AgentRunner 类型的 Bean —— 你没写。

这不是 Maven build 报错，是运行时装配阶段炸的。Maven 那边写着 Build completed successfully。

2.2 AgentScope 的注册中心有两条路

这一集真正的认知盘整在这里。

路线 入口 卡片来源 注册中心 项目用吗
(a) Bean 自动注入 @Component + 返回 ReActAgent Spring 从 Bean 反射抽 name/description 由 application.yml 的 nacos 段决定 → Nacos 用
(b) 手动 build AgentScopeA2aServer.builder(builder).agentCard(card).deploymentProperties(...).build() 自己 new ConfigurableAgentCard 任意填 AgentScope 自带的（要在本节点起 server） 不用

(b) 看起来更灵活——能自定义 AgentCard 字段；但它有个致命前提：AgentScopeA2aServer 是个自带注册中心对象，你得在本节点把它启动起来当 server。这跟项目的分布式架构（Nacos 当通讯录、Agent 跨机部署）正面冲突——所以整段 DeploymentProperties("localhost", 8080) 那一坨在最后被整段注释，墓碑写着 “手动写入注册中心，项目不用种方式”。

取舍点 [加工增量]：选 (a) 的代价是 卡片字段不可自定义——name / description 这些 Spring 是直接从 ReActAgent 对象里反射出来的，你想塞 icon_url 或自定义 skills 就只能回 (b)。本项目接受这个代价。

2.3 (a) 怎么写——其实只剩三件套

砍掉 (b) 之后，TripPlannerAgent.java 里只需要：

  1. @Component —— 让 ReActAgent 进 Spring 容器。
  2. 方法返回 ReActAgent（不能是 void、不能是 AgentScopeA2aServer）。
  3. application.yml 里的 nacos.discovery.server-addr 那段—— Spring Boot 靠这段判断”我要注入的是 Nacos，不是别的注册中心”。

智能体卡片去哪了？Spring 自动从 ReActAgent 对象里抽出 name/description 拼成卡片，再交给 nacos-starter 推到 Nacos。这就是上面表里”卡片来源”那一栏的实质。

2.4 pom 改造——主管节点不能背锅

补完 Bean 还不算完，再启动一次还可能炸——因为主管 Agent 节点也被传染了。

事情是这样：a2a-starter 一旦出现在某个模块的 classpath，AgentScopeA2aAutoConfiguration 就会自动激活，强制要求这个模块提供 AgentRunner Bean。但主管 Agent 节点只读不写——它从 Nacos 拉别人的卡片，自己不需要注册任何东西，它不该也不能提供 Bean。

讲师在根 pom.xml 把 a2a-starter 从 <dependencies> 里砍掉，挪到 <dependencyManagement> 只声明版本：

然后只在 tripPlanner_agent / routeMaking_agent 这两个真的要被注册的子模块里 <dependency> 引入。manager_agent 模块绝对不引——它只引 agentscope-nacos-spring-boot-starter（读取注册中心，单方向）。

[加工增量]：把”根 pom 引 vs dependencyManagement 声明”翻译成日常话：根 pom <dependencies> 是”全公司发工服”，所有员工都得穿；<dependencyManagement> 是”工服库存表”——谁要谁去库房按尺寸领。a2a-starter 这种「一引入就强行索要 Bean」的依赖，必须放进库存表，不能强发。

3. 没 get 的点

  • AgentRunner 这个类型到底是 a2a-starter 自动配置类的哪一段定义出来的？源码层这一集 skip 了。先记着它是 starter 的”必须由你提供”的依赖。
  • application.yml 里 nacos 那段的完整字段长什么样——讲师说”前面课程配置过”一笔带过，本集没全屏。等回看 9-9 或单独一集补。
  • Register 1 endpoint(s) to Nacos 里的 endpoint 是指 HTTP 8085 端点，还是 A2A 协议的某个抽象端点？需要后续看 Nacos endpoint 列表才能确认。
  • 192.168.85.72:8085 这个 IP 是 docker 内网的还是宿主机的？跨机部署时主管 Agent 能否真访问到这个地址？这一集没演跨机。
  • 主管 Agent 节点既然不写注册中心，那它读 Nacos 用的是哪条依赖？大概率是 agentscope-nacos-spring-boot-starter 单方向，但 a2a-starter 是否真的可以完全不引？讲师说”它只需要这个依赖就可以了”一笔带过。

4. 跟其他集连接

上承：9-9 团队成员的智能体卡片注册到Nacos 写下的 ConfigurableAgentCard.Builder + AgentScopeA2aServer.builder 代码，本集就是按 Run 看它怎么炸——并把它做减法到只剩 @Component + return ReActAgent。9-3 SpringBoot 4 和 AgentScope 整合 立的 BOM/版本变量是本集 pom 改造能编译过的前提。9-4 创建不同节点的 ReAct Agent 把”@Component + 构造方法装配 + 返回 ReActAgent”这套三件套打底，本集在它末端补上注册中心维度。

下启：下一集大概率是主管 Agent 从 Nacos 拉卡片 + 走 A2A 调远程子 Agent；application.yml 里 nacos 配置 + agentscope.a2a.server.enabled 这类配置 key 应该会被拎出来单讲；MCP 工具叠加到子 Agent 的工作排在更后面。

横向：与 SAA 1.1 那条线的 4-13 A2A 的服务注册 / 4-14 A2A 服务发现 / 4-15 AgentCard 形成”同一件事两套框架”对照——SAA 的 spring-ai-alibaba-nacos + A2aRemoteAgent 对应 AgentScope 的 agentscope-nacos-spring-boot-starter + AgentScopeA2aServer；name 一致性铁律两条线都成立。与 3-10 多Agent跨部门协作A2A协议 是”协议层 vs Spring 框架封装层”虚实对照——3-10 讲 AgentCard 是什么，本集讲 Spring Boot 怎么把它自动塞进 Nacos。与 9-10 远程Agent封装为工具执行子任务 形成因果——只有先把卡片成功注册到 Nacos，9-10 的 NacosAgentCardResolver 才有东西可解析。

5. 知识地图

6. 自测题

  1. 启动 TripPlannerAgentApplication 报 UnsatisfiedDependencyException: No qualifying bean of type AgentRunner——病根在 a2a-starter 还是你自己的代码？要么提供 Bean，要么挪走 starter，二者必居其一，为什么？
  2. AgentScope 注册卡片到 Nacos 的两套方案分别是什么？本项目为什么放弃手动 build 那条？关键词：分布式、本节点起 server 进程。
  3. 走 Bean 自动注入这条路，TripPlannerAgent 里方法返回值必须是什么类型？为什么不能是 void？智能体卡片的 name/description 此时是哪里来的？
  4. 为什么 a2a-starter 要从根 pom 的 <dependencies> 挪到 <dependencyManagement>？主管 Agent 模块该不该引这个 starter，依据是什么？
  5. 启动成功后看到的服务地址 http://192.168.85.72:8085——这个 IP:port 是 Nacos 的地址还是别的？主管 Agent 后续要用这个地址做什么？

7. 关键词表

术语 一句话
AgentScopeA2aServer AgentScope 自带的注册中心 server 对象，手动 build 那条路绕不开
UnsatisfiedDependencyException 引了 a2a-starter 却没给 Bean 时的标志性运行时报错
AgentRunner a2a-starter 自动配置类要求模块提供的 Bean 类型，缺它就炸
@Component 自动注入 Bean 方案的入口——把 ReActAgent 塞进 Spring 容器交给 starter 自己推到 Nacos
DeploymentProperties 手动 build 方案的 host/port 配置对象；本项目不用，已注释
dependencyManagement pom 改造的关键招式——把 a2a-starter 从”全员强发”降级为”按需领取”
智能体卡片自动提取 Bean 方案下 Spring 从 ReActAgent 对象反射出 name/description 拼成卡片，不可自定义
