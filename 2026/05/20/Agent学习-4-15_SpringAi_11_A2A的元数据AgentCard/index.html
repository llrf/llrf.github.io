4-15 SpringAi 1.1 A2A的元数据AgentCard

发表于2026-05-20|更新于2026-05-20|Agent学习第04章 SpringAi 1.1 实现 MCP+A2A
|浏览量:

1. 一句话定位

AgentCard 是远程 Agent 的”名片”——存在 Nacos 注册中心、只装元数据（name/description/url/version/capabilities/skills），消费端按 name 这把钥匙把它捞出来，再让真正住在 Provider 进程里的 Agent 去干活。

2. 主体

2.1 为什么需要 AgentCard：从一个反问开始

你已经知道 A2A 三个核心组件（4-11 讲过：Provider / Registry / Consumer），也知道消费端用 A2aRemoteAgent.builder() 拿到远程 Agent（4-14 讲过）。但有个问题被跳过去了——注册中心里有一堆远程 Agent，消费端凭什么挑出”我要的那一个”？

不是按 IP、不是按端口，是按一张”名片”。每个远程 Agent 把自己的元数据写进一张卡片，丢进 Nacos；消费端用名字去查这张卡片，拿到卡片才能定位到对应的 Agent。

注意一个反直觉点：注册中心里存的不是 Agent 本体，而是这张元数据卡片。真正的 Agent（带工具、带记忆、带推理）仍然跑在 Provider 那个进程里。Nacos 只是黄页，不是托管平台。

2.2 AgentCard 装了什么（字段清单）

点开 AgentCardWrapper（卡片对象的包装类，源码里它直接代理 this.agentCard.xxx()），你能看到这些字段：

  • name：远程智能体的名字 —— 这是查询 key，命门所在
  • description：它能干什么的自述
  • url / uri：注册中心地址（讲师口述如此，源码字段名是 uri）
  • version：版本号
  • documentationUrl：文档链接
  • capabilities：一个 AgentCapabilities 对象，描述能力
  • defaultInputModes / defaultOutputModes：默认输入输出模式（List）
  • skills：List<AgentSkill>，专业领域技能

skills 这里要特别注意——它不是 MCP 工具。MCP tool 是单个动作（如”查天气”），skills 是整条业务流程的封装。这块本集只点到为止，后面集会展开。

2.4 命门：name 一致性铁律 [取舍出现在 §2.4]

.name("AgentProvider") 里的字符串不是随便起的，它是按名字查卡片的查询 key。它必须同时等于：

  1. Provider 端 ReactAgent.builder().name(X) 的 X
  2. Provider 端 application.yml 里 spring.ai.alibaba.a2a.server.card.name 的值
  3. Consumer 端 A2aRemoteAgent.builder().name(X) 的 X

三处必须一字不差。一旦不一致，Nacos 找不到卡片，整条链路断掉。

取舍：讲师顺序是”发现问题 → 翻源码 → 倒推答案”的探索路径（先看 builder、再看接口、再看 default 方法、最后才落到 name），我把它倒过来——先抛结论（卡片是什么、长什么样、name 是命门），再快速过源码佐证。原因：复习时字段清单和命名一致性才是真正会踩的坑，源码看一眼记得”接口里有 default 方法所以能注入”就够了，不必从源码反推用法。

2.6 A2A 协议三步运行流程 [加工增量在 §2.6]

把整个 A2A 跑通的循环梳理一下：

  1. Provider 注册：ReactAgent 启动时，把自己的 AgentCard（来自 yml server.card）写进 Nacos。
  2. Consumer 查找：A2aRemoteAgent 通过 AgentCardProvider.getAgentCard(name)，按 name 从 Nacos 捞到目标 Provider 的卡片。
  3. Nacos 派活：注意是 Nacos告诉 Provider 去干活，不是 Nacos 自己执行（它没有这个能力，它只是个服务发现中间件）。Provider Agent 干完，把结果写进 OverAllState，返回给 Consumer。

加工增量：原讲解只列了三步事实，我加了个对比维度——A2A 是”服务发现”风格（Provider 主动注册 → Consumer 按名查），而 4-10 学的 MCP 是”协议握手”风格（Client 启动时主动 list_tools 拉清单）。两者本质都是”发现远端能力”，但路径相反：A2A 借力 Nacos 这种成熟的微服务基础设施做异步发现，MCP 走的是端到端协议握手。理解这个分水岭，后面再看任何 Agent 互联方案都能秒归类。

5. 知识地图

6. 自测题（5 卡）

Q1：Nacos 注册中心里到底存的是什么？是远程 Agent 本体吗？

展开看答案

存的只是 AgentCard——一张元数据卡片，包含 name/description/url/version/capabilities/skills 等字段。真正的 Agent（含工具、记忆、推理能力）依然跑在 Provider 自己的进程里。Nacos 的角色是”黄页”，不是”托管平台”。

Q2：AgentCardProvider 是一个接口，为什么消费端可以直接 @Autowired 注入它？

展开看答案

因为接口里有 default 方法实现（特别是 getAgentCard(String agentName) 和 supportGetAgentCardByName()），且 SDK 内置了具体实现类（如 NacosAgentCardProvider）。Spring 能从容器里拿到这个具体实现 Bean，所以 @Autowired 能成功。

Q3：你写 .name("X") 时，这个 X 必须和哪几处保持一字不差？写错一个字会怎样？

展开看答案

X 必须同时等于：① Provider 端 ReactAgent.builder().name(X)；② Provider 端 yml 的 spring.ai.alibaba.a2a.server.card.name；③ Consumer 端 A2aRemoteAgent.builder().name(X)。三处任一不一致，Consumer 都会从 Nacos 里查不到对应的 AgentCard，整条 A2A 链路断掉。

Q4：把 A2A 三步运行流程按角色和动作说一遍。

展开看答案

① Provider 注册：ReactAgent 启动后，把自己的 AgentCard（来自 yml 里 server.card.*）写入 Nacos。② Consumer 查找：A2aRemoteAgent 通过 AgentCardProvider.getAgentCard(name) 从 Nacos 按名捞出目标卡片。③ Nacos 派活：Nacos 根据 Consumer 拿到的卡片，通知对应 Provider Agent 去执行任务（不是 Nacos 自己执行）；Provider 执行完把结果写进 OverAllState 返回。

Q5：AgentCard 里的 skills 和 MCP 的 tool 是同一个东西吗？

展开看答案

不是。MCP 的 tool 是单个动作（如”查天气”），调用即返回。AgentCard 的 skills（List<AgentSkill>）代表专业领域技能——它包含整条业务流程的封装，粒度更粗、语义更高。具体差异本集只点到为止，后续 Skills 专题会展开。
