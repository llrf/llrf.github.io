7-07 图形化展示工作流

发表于2026-05-19|更新于2026-05-21|Agent学习第07章 Graph 搭建旅游规划工作流，像拼积木一样轻松
|浏览量:

1. 一句话定位

把你手搓的 StateGraph 在编译前 X 光一下，吐出 PlantUML 文本，再丢给 IDEA 插件渲染成图，验证「我脑子里的工作流」跟「代码里的工作流」是不是同一个。

2. 主体

2.1 为什么这集要存在

⏱ 00:00–01:43 · 回顾 invoke/stream + 引出图形化验证需求

上一集（7-6）你已经知道 CompiledGraph 有 invoke（同步阻塞，一把梭返回）和 stream（非阻塞，节点级流式返回）两种跑法。问题是：两个 println 都能”跑出结果”，但你怎么验证图的拓扑就是你以为的拓扑？ 节点多起来，靠脑补就崩。这一集就是给那张图拍 X 光。

2.2 方法找在哪：StateGraph 上，不是 CompiledGraph 上

📺 02:36–03:55 · IDE 源码看 getGraph 三个重载 + Type 枚举

这是反直觉的第一关。getGraph 不挂在 CompiledGraph 上，它挂在 StateGraph 上。也就是说：

  • 你必须在 compile() 之前 调它；
  • 在 parallelGraph() 这个 @Bean 方法里，要写在 return stateGraph; 之前。
  • 在 WorkFlowController 里你拿到的是 CompiledGraph，那里写不出来。

getGraph 有三个重载，参数从多到少是：

参数是 GraphRepresentation.Type，是个枚举，挑 PLANTUML（另一个值留到困惑区）。返回的是一个 GraphRepresentation 对象——不是图片、不是 SVG、不是 base64，是个对象，里面有 .content() 才是 PlantUML 源码字符串。

加工增量：视频里讲师没明说返回对象的全限定名，看截图是 com.alibaba.cloud.ai.graph.GraphRepresentation。这条记下来，下次遇到自动补全列里有重名能直接选对。

2.4 两道必踩的坑

📺 06:29–07:15 · 现场报错 ClassNotFound + pom 补 gson

坑 1：ClassNotFoundException: com.google.gson.GsonBuilder

跑起来直接报错，parallelGraph Bean 初始化时就死。原因：spring-ai-alibaba-graph-core 用了 gson 但没把它作为传递依赖给你。pom 里手动加：

加工增量：视频没说为什么 SAA 不传递 gson。猜测是 graph-core 把它声明成了 optional 或者 scope=provided。结论不重要，记住”SAA 工作流 + 第一次跑 → 大概率缺 gson”就行。

坑 2：装 PlantUML Integration 插件

File → Settings → Plugins → Marketplace → 搜 "PlantUML Integration"，作者是 Eugene Steinberg / Vojtech Krasa。装完才有 .puml 文件类型和右侧实时预览。

2.5 从文本到图

📺 07:15–09:50 · API Force 触发 Bean + IDEA 建 .puml 渲染

  1. API Force（或 Postman）请求一次 GET /workflow/parallel——别担心，这个接口没真去调大模型，几十毫秒返回 200，目的就是触发 Bean 初始化让打印走完。
  2. 在 console 里找到两条 #### 之间的 PlantUML 源码，全选复制。
  3. New → File → PlantUML File → Class 模板，给个名字（讲师叫 parallel.puml）。模板会自带一段 Class 图示例，全删，把日志里那段贴进去。
  4. 模板自带的 input 字样讲师说”删掉”——结合截图，是 circle start<<input>> 之外贴重了的残留代码。删干净后右侧预览就出图了。
  5. 看到的图：START → node1 → node2 → END，标题 parallel，footer 写着 powered by spring-ai-alibaba。

2.6 生成的 PlantUML 长这样

⏱ 09:50–10:27 · 看渲染后的图 + 解释 PlantUML 骨架符号

记一下几个符号：circle 画 START/END，usecase ... <<Node>> 画节点，__START__ / __END__ 是 SAA 框架硬编码的标识。

3. 没 get 的点

  • 三个重载里 String title、boolean printConditionalEdges 的默认值多少？带条件边（addConditionalEdges）的工作流，最短重载会自动把条件边画出来吗？还是必须显式传 true？
  • GraphRepresentation.Type 除了 PLANTUML 还有什么？是不是 mermaid？如果是 mermaid，GitHub README 直接渲染、不用插件，工程上似乎更省事。
  • IDEA 的 PlantUML 预览是本地跑 plantuml.jar 还是调云端？离线机能不能用？
  • 讲师”删掉 input”那一刀具体删的是哪行？看视频太快，需要实际跑一遍对照。

4. 跟其他集连接

  • 上承：本章前面（7-x）讲了 addNode / addEdge / compile() / invoke vs stream——本集是给那条手搓出来的”链式工作流”拍 X 光。parallelGraph 这个 Bean 名沿用上集。
  • 下启：下一集大概率把”两个节点串行”扩到真正的并行/分支（Bean 名已经叫 parallel 了），那时图会从一条直线变成 DAG，本集的打印手段就是 DAG 调试的标配。再往后接到 SAA 1.1 的 DAG Graph（参考 4-9）。
  • 横向：跟 6-6 ReactAgent / 6-8 Agent 协同 的可视化诉求同源——Agent 套娃越深越需要画图；那边走的是 OverAllState + subAgents 的结构描述，本集走的是 PlantUML 文本中转。和 4-14 OverAllState 同属”工作流可观测性”光谱。

7. 关键词表

术语 一句话
StateGraph.getGraph(Type) 编译前的方法，把图结构吐成某种 UML 文本；三个重载，挑最短的只传 Type
GraphRepresentation 返回对象，.content() 才是 PlantUML 字符串
GraphRepresentation.Type.PLANTUML 枚举值，告诉 SAA 用 PlantUML 方言输出
打印时机 = 编译前 方法挂在 StateGraph 上，CompiledGraph 上没有
PlantUML Integration 插件 IDEA Marketplace 直装，作者 Eugene Steinberg / Vojtech Krasa
gson 隐性依赖 SAA graph-core 不传递 gson，必须 pom 手动加
围栏 println 技巧 用两条 #### 包住源码，便于 console 肉眼框选复制
PlantUML 骨架 @startuml + skinparam + circle __START__/__END__ + usecase <<Node>> + 箭头
