4-12 SpringAi 1.1 MCP注解：全新的MCP实现

发表于2026-05-19|更新于2026-05-21|Agent学习第04章 SpringAi 1.1 实现 MCP+A2A
|浏览量:

1. 一句话定位

SpringAI 1.1 用一套 MCP 原生注解把 1.0 的”借用 + 手动注册”重写为”定义即注册”。

2. 主体讲解

2.1 为什么需要”原生注解”

1.0 里你写的是 @Tool / @ToolParam，它们躺在 org.springframework.ai.tool.annotation 下——这是 Spring AI 通用工具注解，并不知道自己将被用作 MCP 工具。所以 1.0 还要你额外手写一段 MethodToolCallbackProvider.builder().toolObjects(...) 的 @Bean 把方法塞进工具清单。

1.1 直接给 MCP 准备了一套同名前缀注解：@McpTool / @McpToolParam / @McpProgressToken / @McpPrompt / @McpResource / @McpComplete / @McpElicitation / @McpLogging ……一整排（看下面 IDE 自动补全那张图）。它们都在 org.springaicommunity.mcp.annotation——注意这个包属于 community，不在 spring-ai 主包里，是 starter 顺手拉进来的传递依赖。

加工增量在 §2.1：视频按代码顺序铺概念，这里我把”为什么需要新注解”提到最前，因为不解释清楚”包属于 community 而非 spring-ai”，你下次导包还是会困惑。

2.2 依赖地基（先把”地”打平）

只引一个 starter：

mcp-annotations 不用单写，starter 会拉。但有个坑：starter 属于 SpringAI 本家，不属于 Spring AI Alibaba（SAA），所以你 pom 里光有 spring-ai-alibaba-bom 是拿不到 1.1.0 的。必须把 spring-ai-bom 也一并 import 进 <dependencyManagement>，starter 才能解析到 1.1.0。

取舍出现在 §2.2：讲师顺序是”导 starter → 替换注解 → 进阶 → 删注册 → 开扫描”；我换成”依赖（地）→ 扫描开关（电）→ 注解三件套（房）→ 进度回写（家具）”，理由是排查问题时先看地基。

@McpTool 的关键属性还是那两个：name（显示名）和 description（给大模型看的”何时以及如何使用”说明，必填）。

@McpToolParam 等同于老 @ToolParam，标注业务入参。

2.4 进度回写：让长方法”边跑边汇报”

光在参数上标一个 @McpProgressToken 是不够的——它只让客户端能传一个 token 进来，不代表服务端就会主动汇报进度。汇报这个动作要你显式发起，写法分三步：

  1. 在参数列表多加一个 McpSyncServerExchange exchange（来自 io.modelcontextprotocol.spec，是 MCP 协议层的核心对象，注意它不在 community 包，是一方的）。
  2. 判 token 非空（客户端可能根本没传）。
  3. 调用 exchange.progressNotification(new McpSchema.ProgressNotification(token, progress, total, message))。

ProgressNotification 有两个重载，简单那个签名是 (String token, double progress, Double total, String message)。注意第二参 progress 是原始 double（必填），第三参 total 是包装 Double（可 null，表示”我不知道一共多少”），第四参 message 是给前端展示的提示池字符串。复杂那个多一个 Map<String,Object> metadata，本节没用。

执行到 50% 写一次、到 90% 再写一次、message 也跟着改成”准备返回数据”——这就是”边跑边汇报”。

3. 我一开始没 get 的点

  1. @McpProgressToken 是参数级，不是 tool 级。我以为它会和 description 并排塞进 @McpTool(...) 的括号里，结果是单独标在 String progressToken 形参前面。视频里讲师自己也写错了一次才改对。
  2. @McpTool 的包归属反直觉。org.springaicommunity.mcp.annotation——community 三方包；而 McpSyncServerExchange 又来自 io.modelcontextprotocol.spec——一方协议包。同一个方法签名里三方注解 + 一方核心混着，import 时要看清来源。
  3. starter 把”依赖管理”和”扫描开关”拆成两步。我以为引入 starter 自动什么都搞定，结果还要在 application.yml 显式开扫描，否则注解写了也没效果（静默失效）。
  4. spring-ai-bom 必须额外 import。SAA 项目里我们已经习惯了只 import spring-ai-alibaba-bom，但这次 starter 来自 SpringAI 而不是 SAA，所以两个 BOM 都要。

4. 跟其他集的连接

上承

  • 4-5 创建MCP工具：那一集用 @Tool / @ToolParam（org.springframework.ai.tool.annotation）；本集换成 @McpTool / @McpToolParam（org.springaicommunity.mcp.annotation）。
  • 4-6 将MCP工具注册到MCP服务：那一集要你手写 MethodToolCallbackProvider 的 @Bean；本集整段删除——“定义即注册”。
  • 4-1 BOM 导入 SAA + 4-2 导入 MCP 依赖：本集再次踩中”BOM 包归属”的坑——starter 在 SpringAI 而非 SAA，所以必须加 spring-ai-bom。

下启

  • MCP 客户端如何消费 progress 通知（流式 UI 进度条）。
  • @McpPrompt / @McpResource / @McpComplete / @McpElicitation / @McpLogging——同一包下的姐妹注解，对应 MCP spec 里其它能力（prompt 模板、资源订阅、补全、追问、日志）。

横向

  • 3-4 / 3-5 / 4-3 MCP 协议本身：ProgressNotification 是 MCP spec 里早就定义的标准通知；注解只是把它”零代码”暴露出来。协议层 → 注解层的桥就是 McpSyncServerExchange。

5. 知识地图

6. 自测题

  1. @McpTool 属于哪个包？为什么必须额外引入 spring-ai-bom？
  2. @McpProgressToken 写在哪里？它能修饰什么类型的形参？
  3. 1.1 里还需要手写 MethodToolCallbackProvider 的 @Bean 吗？为什么？
  4. McpSchema.ProgressNotification 简单重载的四个参数分别是什么？哪一个可以为 null？
  5. 引入 starter 后还差一步注解才能生效，是哪一步？
参考答案
  1. org.springaicommunity.mcp.annotation，由 spring-ai-starter-mcp-server-webflux 传递引入。这个 starter 属于 SpringAI 而非 SAA，所以只有 spring-ai-alibaba-bom 解析不到，需要把 spring-ai-bom 也 import 进 dependencyManagement。
  2. 写在方法参数列表里，修饰一个形参（不是 @McpTool 的属性）。只能用于 String 或 int。
  3. 不需要。1.1 是”定义即注册”——扫到 @McpTool 自动加进工具清单，1.0 的注册 @Bean 整段删除。
  4. (String progressToken, double progress, Double total, String message)。第三参 Double total 可以为 null（包装类型），其它三个不行。
  5. 在 application.yml 里把 MCP 注解扫描 enable 设为 true，否则注解形同虚设。

7. 关键词表

术语 一句话
@McpTool 1.1 的工具注解，替代 @Tool；属性 name + description（description 给大模型选工具用，必填）
@McpToolParam 1.1 的入参注解，替代 @ToolParam
@McpProgressToken 参数级注解，让客户端可以传 token 追踪长方法进度；只能修饰 String/int
McpSyncServerExchange 协议层的服务端会话对象（io.modelcontextprotocol.spec），调它的 progressNotification 把进度写回客户端
McpSchema.ProgressNotification 进度通知 DTO，签名 (token, progress, total, message)；total 是包装 Double 可为 null
spring-ai-starter-mcp-server-webflux 1.1 的 server starter（基于 WebFlux 跑 SSE），传递依赖 mcp-annotations
mcp-annotations 包归属 真实包名 org.springaicommunity.mcp.annotation——community 三方包，不是 spring-ai 主包
定义即注册 1.1 取消 MethodToolCallbackProvider 手动注册，扫描到 @McpTool 自动入工具清单

待查：application.yml 里 MCP 注解扫描的确切配置 key（视频未给画面）；progressToken 是客户端必传还是可选；ProgressNotification 带 metadata 那个重载的使用场景；1.1 是否保留 @Tool 老写法的兼容。
