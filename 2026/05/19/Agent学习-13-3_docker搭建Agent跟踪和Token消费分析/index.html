13-03 docker搭建Agent跟踪和Token消费分析

发表于2026-05-19|更新于2026-05-21|Agent学习第13章 旅游规划优化，监控，部署
|浏览量:

1. 一句话定位

你的 Agent 跑起来之后，”它到底花了多少钱、卡在哪一步、调了哪个工具”这些问题不该靠日志肉眼追——这一集把 Langfuse 这个开源 LLMOps 平台用 docker 拉起来，给应用挂上一个外部观测面板。

2. 主体

2.1 你要的不是”监控服务器”，是”监控 LLM 调用”

⏱ 00:00–00:37 · 区分 LLM 观测与 JVM 监控，纯讲

老师一开口说”做监控”，很容易把它理解成 Spring Actuator / Prometheus 那种 JVM、CPU、QPS 监控。实际上这里盯的对象完全不同：

  • 一次 LLM 调用的响应时间和 token 用量
  • 一次 Agent 任务里调了哪些 MCP / 工具、上下文长啥样
  • 调用花了多少钱（成本是 token 用量 × 模型单价，平台算）
  • 用户反馈、评估打分、A/B 对比

所以它对标的不是 Grafana 看机器，而是 Sentry / DataDog 看应用——只不过应用是 LLM 应用。

2.2 一条命令拉起六个容器

📺 00:37–02:29 · 终端 docker compose up 启动六容器栈

部署路径很短：

视频里第一次显示的命令是 sudo docker compose run（见 PPT，f001 / f011 / f012），这是个坑：run 是”跑某个 service 的单次命令”，而你要的是把整套栈拉起来常驻——必须是 up。f009 / f014 终端里实际敲的也是 up，PPT 那行先别照抄。

加工增量：run vs up 在消化稿里只是一句话提了一下，这里展开是因为我自己第一次跑 docker compose 也踩过——同样是一条命令，行为完全两码事。

启动过程会拉很多镜像（OCR 里看到 “54/16” 的进度，6 个 service，54 层 layer）。最终 docker compose up 完成后会看到 6 个容器都 Running（f017）：

容器 角色
langfuse-web 控制台（你打开 :3000 看到的页面）
langfuse-worker 异步处理（消费队列、算成本、跑评估）
postgres 元数据：用户、组织、项目、API Key
clickhouse trace 明细（列式存储，专为高并发写设计）
redis 队列 / 缓存
minio 对象存储（大 prompt / response / 附件）

只有前两个是 Langfuse 自己的代码，后四个是基础设施。这也解释了为什么”一句 docker compose up”要拉 54 层——大头是 ClickHouse 和 minio 这种重组件。

2.3 注册 → Organization → Project → API Key

📺 02:29–03:46 · Langfuse Web UI 现场注册、建项目、申 API Key

启动完 localhost:3000 进去（f016 / f018），流程跟 GitHub / Sentry 一模一样：

  1. 注册账号（密码要大小写 + 特殊符号，老师强调过）
  2. 建一个 Organization（图 f019 里叫 AiTripPlanning，就是后面要接的项目名）
  3. 在 Organization 下建一个 Project（叫 AiTrip）
  4. 进 Project → Settings → API Keys → Create new

到第 4 步你会拿到三件套（f023 截图原文）：

记牢”三件套”这个数字：

  • pk + sk 这种命名是 Stripe 同款——public 用来标识来源，secret 用来签名
  • base_url 必须显式给，因为 Langfuse 可自托管，平台不知道你装在哪
  • 少一个连不上——下一集真接的时候这三个 env 一个都不能漏

2.4 Home 面板上”成本”是平台算的，不是模型回传的

📺 03:03–03:24 · Langfuse Home 面板现场看 Trace 与 Cost 指标

进 Home（f020 / f021）能看到这些卡片：Traces、Model costs、Scores、Traces by time、Model Usage、Cost by model、Usage by model、Cost by type、Usage by type……

注意 cost 和 usage 是平级两栏：

  • Usage 是事实：模型回传的 token 数（prompt tokens / completion tokens）
  • Cost 是加工：Langfuse 在 Settings → Model Definitions 里维护一张”模型 → 单价”的表，trace 进来后用 usage × 单价算出来

这意味着两件事：

  1. 国产模型（deepseek、qwen、元宝）默认表里可能没有，要自己补 Model Definition，不然 cost 永远 $0.00
  2. 同一次调用，”花了多少 token”和”花了多少钱”是两个数据来源，别混

2.5 这一集到此为止，下集才真接

⏱ 03:57–04:08 · 收尾说明本集只装平台，下集才接 trace

整集的范围其实非常窄：把平台装好、登进去、拿到 API Key——还没把 Agent 的 trace 真推进来。Home 上所有图表显示 “No data”（f021 OCR 反复出现），这是正常的。下一集（13-4，按目录）才把这套 .env 灌进 AiTripPlanning 项目让 trace 涌进来。

3. 我没 get 的点

  • Spring AI / AgentScope 接 Langfuse 用的是 OpenTelemetry 协议，还是 Langfuse 私有 SDK？两条路埋点点位不一样，下一集应该会揭晓。
  • LANGFUSE_BASE_URL=http://localhost:3000 这个写法，如果 Agent 也跑在 docker 容器里，localhost 指向容器自己——这时候是不是要换成 host.docker.internal 或者直接用容器名通过 docker network 走？跨容器通信这块视频没讲。
  • ClickHouse 自托管能扛多大并发？生产环境一般要不要换成托管 ClickHouse Cloud？
  • minio 在这套架构里到底存什么？猜是超长 prompt / response 的对象引用，但没验证。
  • Scores 里 LLM-as-a-Judge 是哪个模型当 judge、单价怎么算（自己 judge 自己算成本套娃）？

6. 自测题

  1. Langfuse 一个 docker compose 起了 6 个容器，哪两个是”业务”，剩下四个分别承担什么职责？
  2. 视频 PPT 上写的 sudo docker compose run 为什么是错的？正确命令是什么，差别在哪？
  3. Home 面板上 “Cost by model” 和 “Usage by model” 平级摆放——这两份数据各自从哪来？为什么国产模型可能 cost 一直 $0.00？
  4. 把 Langfuse 接进 Agent 应用，最少要往 .env 写哪几个变量？少了 LANGFUSE_BASE_URL 会怎样？
  5. 三级权限模型 Organization → Project → API Key，为什么 API Key 是绑在 Project 而不是 Organization 上？

7. 关键词表

术语 说明
Langfuse 开源 LLMOps 可观测性平台，专给 LLM/Agent 应用做 tracing + token 计费 + 评估
六容器栈 langfuse-web + langfuse-worker（业务）+ postgres / clickhouse / redis / minio（基础设施）
Trace / Observation / Score 一次完整调用 = Trace，里面每步 = Observation，事后打分 = Score
Model costs 平台维护各模型单价，token 用量 × 单价 = cost，独立于模型返回
API Key 三件套 LANGFUSE_PUBLIC_KEY + LANGFUSE_SECRET_KEY + LANGFUSE_BASE_URL
Organization → Project → API Key 三级权限模型，每个项目独立 key、独立 trace 空间
docker compose up vs run up 拉整套栈持续运行，run 只跑单个 service 一次性命令；PPT 写的 run 是坑
LLM-as-a-Judge Langfuse 内建的”用大模型给大模型打分”评估机制，Scores 自动来源之一
