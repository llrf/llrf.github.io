13-05 测试主管Agent接收Prompt及结构化输出

1. 一句话定位

这集把 /trip 这个 POST 接口从”裸字符串进、裸字符串出”升级成”两端都套 Schema 的强类型契约”——HTTP 边界、Java POJO、LLM 提示词三层用同一组字段名串起来。

2. 主体

2.1 为什么入参也要一个 Schema

📺 00:00–01:35 · IDE 中新建 PromptSchema 类并加 UTF-8 produces

直觉会以为”结构化输出”只管出参，但你打开 /trip 一看就知道入参也跑不掉：

  • @RequestMapping(produces="application/json;charset=UTF-8", method=POST) 一旦写成 POST + JSON，HTTP body 就必须是个对象，裸字符串过不来。
  • 中文 prompt 走通路依赖 charset=UTF-8，少了就乱码。
  • 所以你需要一个最小信封：

前端发的就是 {"prompt":"帮我规划一趟北京三日游..."}，Controller 用 @RequestBody PromptSchema input 接住，然后 input.getPrompt() 拿到字符串。

这里的”加工增量”：消化稿提醒过我——PromptSchema 用 @Getter、ResponseSchema 直接 public String response 写裸字段，看似不一致，其实方向不同：前者是”Java 对象 → JSON 出去给后端 = 需要 getter”，后者是”LLM 文本 → Java 对象 = 需要无参构造 + 可写字段”。两边的 Jackson 走的是不同方向，所以写法不对称是合理的。

2.2 出参 Schema 的两条硬约束

📺 01:35–02:58 · IDE 中写 ResponseSchema 并强调无参构造

两条规矩：

  1. 字段名 = 你希望 LLM JSON 里那个 key 叫什么。这里叫 response，所以最终返回里那个值就一定挂在 "response": "..." 下面。
  2. 必须有无参构造函数。反序列化的硬约束——Jackson 先 new ResponseSchema() 再 set 字段，没有无参构造就 new 不出来。

视频里讲师只说了句”必须要有”，没解释原因。

2.4 TOOL_CHOICE 还是 PROMPT，为什么这集选 PROMPT

⏱ 04:22–05:00 · 文档对比两种模式选 PROMPT 兼容老模型

StructuredOutputReminder 翻文档只有两个候选：

模式 怎么实现 谁能用 代价
TOOL_CHOICE（默认） 强制让 LLM 调一次特定工具，把 schema 当工具签名 支持 tool_choice 协议的新模型（qwen3-max、gpt-4 系） 一次 API 调用，准
PROMPT 在系统提示词里塞一段”请按这个 schema 输出 JSON”的提醒 任何能听懂指令的模型 可能多次重试，慢

项目选 PROMPT 的理由很务实：兼容性优先。TOOL_CHOICE 性能更好但门槛高，老模型直接不支持；PROMPT 是用人话哄模型，老模型也能跟着学样。

视频结尾点了一句模型兼容性边界：千问三能跑通，DeepSeek 一类老模型可能直接报错。这是选模型时一个隐藏维度——“这模型支不支持结构化输出”和”这模型聪不聪明”是两件事。

6. 自测题（5 卡）

  1. ResponseSchema 为什么必须写一个无参构造函数？
  2. 项目为什么选 StructuredOutputReminder.PROMPT 而不是默认的 TOOL_CHOICE？说出一个具体原因。
  3. agent.call(userMsg, ResponseSchema.class).block() 之后还要再调一次 .getStructuredData(ResponseSchema.class)，这两步各自干了什么？
  4. 如果 controller 上少写了 produces="application/json;charset=UTF-8"，最直接的坏处是什么？
  5. 视频测出的响应耗时是 28 秒，这件事会在哪一集被正面解决？解决思路大概是什么？
参考答案
  1. Jackson 反序列化 LLM 文本到 POJO 时，要先 new ResponseSchema() 出一个空对象再 set 字段——没有无参构造就 new 不出来。
  2. TOOL_CHOICE 依赖 tool_choice 协议，老模型（如某些 DeepSeek 版本）不支持；PROMPT 用系统提示词引导，兼容性更广，代价是可能多次调用变慢。
  3. .call(..., ResponseSchema.class).block() 把 schema 语义传给 Agent 并同步等结果；.getStructuredData(ResponseSchema.class) 把 LLM 生成的 JSON 文本反序列化到 POJO 实例。
  4. 中文 prompt 通路会乱码——这是中文场景的硬性要求。
  5. 13-6 旅游规划打印出Agent的深度思考；通过流式输出（streamResponse / SSE）把推理过程实时吐给前端，避免前端傻等 28 秒。

7. 关键词表

术语 一句话
PromptSchema 入参信封，@Getter + String prompt 一个字段，把裸字符串包成 {"prompt":"..."} 满足 HTTP POST 的 JSON 要求
ResponseSchema 出参信封，public String response + 必须有无参构造，LLM 文本回填到这个对象的 response 字段
无参构造函数 Jackson 反序列化的硬约束——先 new 空对象再 set 字段，没有无参构造就 new 不出来
structuredOutputReminder ReActAgent.builder() 的一个槽位，构建期告诉 Agent “请按某种结构化模式输出”
StructuredOutputReminder.PROMPT 用提示词引导的结构化模式，兼容老模型，可能多轮、较慢
TOOL_CHOICE vs PROMPT 一个靠 tool_choice 协议一次定型（新模型）、一个靠系统提示词哄（任何模型）；项目选后者求兼容
getStructuredData 运行期把 LLM 返回的 JSON 文本反序列化到指定 POJO 类的方法
UTF-8 produces produces="application/json;charset=UTF-8"，中文 prompt 通路的硬约束，少了就乱码
