5-05 Agent团队和大模型的无缝协作

Agent团队和大模型的无缝协作

1 · 一句话定位

把 5-1 ~ 5-4 攒出来的旅行规划三专科 Agent 装进一个完整流水线：上面加一个主管 Agent、下面接一个汇总 Agent，再把”谁在做决策”这件事翻过来——真正的大脑是 LLM，不是主管 Agent。

2 · 主体

2.1 先把骨架画出来：5 个 Agent = 2 通用 + 3 业务（加工增量在 §2.1）

教学顺序是”业务三件套 → 补出通用两件套 → 画工作流”。一年后回看你只需要一句口诀：

任何复合需求都套这俩通用壳，中间塞业务专科。

角色 类型 干什么 谁能复用
主管 Agent（规划 Agent） 通用 意图识别 + 拆解子需求 + 分发 所有复合需求
路线制定 Agent 业务 地点搜索、经纬度转换、最优路线 旅行类专属
行程规划 Agent 业务 按偏好/天气筛景点、抓图文、定每日行程 旅行类专属
费用统筹 Agent 业务 算账、出明细表、监控优惠券 旅行类专属
汇总 Agent（整合 Agent） 通用 收三个专科的结果，拼成友好回复/表格/文件 所有复合需求

讲师那句”这两个智能体是通用的”是本集最值钱的一句——它告诉你：以后看任何多 Agent 架构，先把头尾两个壳剥掉，剩下的中间层才是真正的”业务”。这把 3-9 提的”主管 + 专科”公式从两件套升到了三件套：主管 + 专科 + 汇总。

2.2 每个专科 Agent = 角色定义 + 工具子树

讲师反复强调一句话：“这些工具就代表了这个 Agent 的能力。” 换言之没工具就是空壳。每个 Agent 卡片都是固定两段式：

  • 角色定义：做什么（prompt 内核，本集一笔带过）
  • 具有能力：用什么做（工具集，本集大头）

把三个专科的工具子树拼出来就是这张图：

挑几个关键观察：

  • 路线制定 Agent 只挂两把工具——「地点搜索工具」（含经纬度坐标转换）+「路线工具」（距离计算 + 路线可视化展示）。看似简单，但已经覆盖了”两点之间最优路径 + 地图渲染”这一整条能力链。
  • 行程规划 Agent 挂的是「网络搜索工具」一把大刀——景点信息抓取、图片抓取、天气查询、本地文件操作、表格制作五件事一锅炖。讲师没拆它的子工具，说明这一块在他的拆分里是个”综合服务”而非”原子工具”。
  • 费用统筹 Agent 拆得最细：「计算工具」（加减乘除）、「文本工具」（表格制作 + 文件操作）、「编程工具」（浏览器操作 + 脚本编写——用来监控优惠券发放）。监控优惠券这个用法值得记一笔：爬虫脚本被当成 Agent 的工具能力之一，不是单独的服务。
  • 「表格制作」和「文件操作」在行程规划和费用统筹重复出现——说明工具是按”Agent 的能力维度”挂的，不强求”每个工具全局唯一”。实现成本这事下一集大概率会回答。

2.3 底层逻辑：主管 Agent 其实不是大脑（取舍出现在 §2.3）

这里是本集的反直觉点，也是它真正的”题眼”。

你的本能反应：用户需求 → 主管 Agent → 主管自己拆解 → 分给专科。
讲师告诉你的真相：用户需求 → 大模型先做意图识别和拆解 → 把”详细计划”反馈给主管 Agent → 主管 Agent 只负责”按计划往下分发”。

更狠的一刀：LLM 在整条流程里出现了两次。

  1. 第一次（顶层拆解）：用户需求 → LLM 做逻辑分析 → 根据”它知道有哪些 Agent、各自有什么能力”，制定详细计划 → 计划交给主管 Agent。
  2. 第二次（每步选工具）：每个专科 Agent 拿到子任务后，手上有一堆工具——这一步到底该用哪个？专科 Agent 再次问 LLM：”我有这些工具，干这事用哪个？” LLM 做逻辑分析 → 返回工具名 → Agent 调用之。

这意味着：

一次复杂任务里，LLM 被调用的次数 ≈ 任务步骤数 + 1（顶层规划那次）。

这里有个明显的取舍：把”决策”全部外包给 LLM，好处是 Agent 写起来很薄（只要枚举工具就行）；坏处是 LLM 调用次数会膨胀，每一步都要往返一次 token，成本和延迟都会被步骤数放大。讲师没提这件事——但你心里要留这根弦，它会决定后续工程落地时”哪些决策固化成代码、哪些留给 LLM 当场判断”。

2.4 智能体的四个能力：正好补 LLM 的四个短板

讲师用四句话收尾，但你可以反着读——这四个能力正好对应 LLM 自己搞不定的事：

Agent 能力 LLM 的对应短板 Agent 怎么补
感知能力 不知道现场环境 搜周边信息喂给 LLM 辅助分析
计划能力 给出清单但不会自己往下分 接住 LLM 的计划清单，分发给单个智能体
记忆能力 不记得执行到第几步 本地记住”这个清单已经走到 step 3”
执行能力 不能动手调工具 拿 LLM 返回的工具名，真正去 call

LLM 只会”逻辑分析”，落地的所有动作都是 Agent 在做。

这句话和 §2.3 那张底层图合在一起，就是本集留给一年后的我那条唯一的核心论断：LLM 是中枢神经，Agent 是手脚和短期记忆，两者缺一不可。

3 · 没 get 的点

  • 主管 Agent 把任务分完后，它本身还在跑吗？ 是常驻在循环里监督某个专科出错时重新协调？还是分完就退场等汇总？讲师没明说。猜测是常驻——否则中途失败没人兜底。
  • “记忆能力”具体怎么实现？ 是 Agent 内部状态变量、外部存储（Redis / DB），还是直接塞进 LLM 上下文窗口？跟 4-14 露过头的 OverAllState 是不是同一个东西？
  • 同一个工具（如「表格制作」「文件操作」）在不同 Agent 下重复挂载 —— 是真的复制一份代码，还是底层是同一个 Bean / 同一个 MCP server 被多个 Agent 引用？影响实现成本。
  • 五个 Agent 之间走什么通信协议？ 同进程方法调用？还是已经是 A2A（4-11 ~ 4-16 那套）？本集只画了流程图没碰落地。
  • LLM 调用次数膨胀怎么办？ 步骤一多 token 成本和延迟都会爆——有没有”批量决策”或”缓存路由”的优化？讲师没提，自己留意。

4 · 跟其他集连接

  • 上承：

    • 3-9 给了”主管 + 专科”两件套的概念，3-12 给了”五步骨架 + 单 Agent 五步循环 + 骨架嵌套”。本集把 3-12 的骨架嵌套用旅行规划演了一遍，并补上第三件套：汇总 Agent。
    • 3-7 / 3-8 那句”工具组合 = Agent 能力”在本集每个专科卡片的「具有能力」列表里直接复现——能力的具象就是一组工具名。
    • 5-1 ~ 5-4 把三个专科分别”立绘”完毕；本集是给这三个角色补上头（主管）和尾（汇总），构成完整队形。

  • 下启：

    • 5-6 极大概率讲”百度地图 MCP 工具体系全景”——给本集的路线制定 / 行程规划两个 Agent 补具体可用的工具源。
    • 真正的代码落地大概率在更后面：主管 Agent 拆解 prompt 怎么写、专科 Agent 怎么注册工具（呼应 4-5 / 4-6 的 @Tool）、Agent 间通信走不走 A2A（4-11 ~ 4-16）、汇总 Agent 怎么聚合多份结果。
    • “记忆能力”这条线大概率引向 OverAllState（4-14 已出现）或 DAG Graph（4-9）。

  • 横向：

    • 3-10 是把本集的”五人协作”跨进程化的协议层；本集是”同公司内部部门协作”，A2A 是”跨公司协作”。
    • 3-11 里的 JManus / AutoGen / CrewAI 全是这套”主管 + 专科 + 汇总”的工程化实现；3-11 选型 → 本集理论 → 4-x 系列 SAA 代码落地，是一条线。
    • 4-14 / 4-16 里 Provider / Consumer 的拆分，其实就是”主管 Agent 调用专科 Agent”的 Spring 版本。

5 · 知识地图

6 · 自测题（5 卡）

  1. Q：用户问”国庆深圳到清远自驾三天怎么安排”，主管 Agent 自己会做意图识别和拆解吗？
    A：不会。意图识别和拆解是大模型干的——LLM 把”详细计划”交给主管 Agent，主管 Agent 只负责按计划往下分发。把主管 Agent 误当成”大脑”是本集最大的反直觉点。

  2. Q：一次旅行规划任务里，LLM 大致被调用多少次？
    A：任务步骤数 + 1。第一次在顶层做拆解和计划，之后每个专科 Agent 执行每一步时都要再问一次 LLM”我手上这些工具该用哪个”。所以步骤越多，LLM 调用越多，成本和延迟跟着膨胀。

  3. Q：本集补出来的”通用两 Agent”是哪两个？为什么说它们通用？
    A：主管 Agent（规划 Agent）和汇总 Agent（整合 Agent）。任何复合需求都需要”先拆解 + 再聚合”这两步，所以这两个壳和具体业务无关，可以套在任何多 Agent 架构上。

  4. Q：Agent 的四个能力分别是什么？每个对应 LLM 的哪个短板？
    A：感知（LLM 不知道现场，Agent 搜周边喂给它）/ 计划（LLM 不会自己往下分，Agent 接清单分发）/ 记忆（LLM 不记得执行到第几步，Agent 本地存进度）/ 执行（LLM 不能动手，Agent 真正去调工具）。

  5. Q：费用统筹 Agent 为什么挂了「编程工具」？这暴露了什么设计思路？
    A：用来监控优惠券发放——写脚本去抓取折扣信息。这暴露的设计思路是：任何能落地动作的代码片段都可以被当成 Agent 的一种”能力”挂上去，不一定非要是规范的服务。这把”工具”的边界拉得很宽，呼应 3-7 / 3-8 的 Skills 思路。

7 · 关键词表

术语 含义
主管Agent 通用模块（又叫规划 Agent / Supervisor）；承接 LLM 给的详细计划，把子任务分配给具备相应能力的专科 Agent；本身不做意图识别，只是 LLM 决策的”二传手”
汇总Agent 通用模块（又叫整合 Agent）；收集所有专科 Agent 的执行结果，整合成总结性表格 / 文件 / 友好回复反馈给用户
通用两Agent 主管 Agent + 汇总 Agent 这一对组合；本集核心增量——任何复合需求架构都套这俩壳，中间塞业务专科
LLM 中枢论 整条流程的中枢神经是大模型而非主管 Agent，Agent 只做执行和协调、不做推理；本集对 3-9 / 3-12 那条骨架的根本性颠覆
LLM 双次出场 一次复杂任务里 LLM 至少被调用两次——第一次顶层拆解（用户需求 → 计划清单），第二次每个专科 Agent 执行每一步时选工具；总调用次数 ≈ 任务步骤数 + 1
智能体四能力 感知 / 计划 / 记忆 / 执行——正好补 LLM 的四个短板（不知现场 / 不会分发 / 不记进度 / 不能动手），其中执行能力最关键
工具即能力 每个 Agent 卡片固定两段式”角色定义 + 具有能力”，「具有能力」这一段全是工具名；没工具的 Agent 就是空壳；呼应 3-7 / 3-8
复合需求拆解 把一个看似简单的需求（如旅行规划）按维度切成多个子需求（交通 / 行程 / 费用），每个子需求配一个专科 Agent；可迁移到任何”看似简单实则复合”的需求
