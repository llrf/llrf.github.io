Skills装载的是专业知识和工作流程

1. 一句话定位

10-2 你刚听到”Skills 是个专属工作流”这个词，这一集就是把那个词撑开——Skills 不是工具包，而是专业知识 + 工作流程 + 执行逻辑三件套，整套以文件夹形式塞给 Agent。

2. 主体

2.1 先把 Skills 和 MCP 钉死（避免和 3-7/3-8 混）

10-2 后你可能还在心里把 Skills 当成”高级版工具调用”。这一集开篇就在这帧图上把两者并排放：

  • MCP = 外部工具连接的标准（横向：让任何 LLM 用同一套协议调用墨刀、百度地图、携程网……）
  • Skills = 技能系统的标准（纵向：让 Agent 装下整个产品领域 / 代码领域 / 测试领域的 know-how）

两者不冲突、不替代。这一刀和 3-8 那集”Skills + MCP 最强组合”是同一道菜的两个视角——3-8 讲怎么搭，本集讲怎么分。

加工增量：讲师只说”两个不同概念”。我把它进一步抽象成横向 vs 纵向的两层标准——MCP 解决”工具怎么连”，Skills 解决”领域怎么装”。这个轴一旦立住，后面所有内容都挂得上。

2.2 Skills 三件套：拆开”专属工作流”

帧图右下方那三个并列的橘色框就是骨架：

件 内容 产品经理为例
专业知识 不只领域知识 产品知识 + 用户心理学 + 行为学 + 消费习惯
工作流程 行业固定 SOP 跟老板谈 → 写需求文档 → 查竞品 → 画版本 → 老板确认 → 上墨刀 → 跟前后端对尺寸 → 交付
执行逻辑 工具调用 墨刀 / Axure 怎么用（MCP、Function Calling 那层）

10-2 那集”专属工作流”的”工作流”两字——这里你才发现它的全称是工作流程，是三件套之一，不是 Skills 的全部。3-7 那集对 Agent Skills 的第一印象是”工具按需加载 + 领域知识”，本集明确说：工具调用只是一环，指甲盖那一块。产品经理之所以是产品经理，不是因为会用墨刀，而是因为有那一整条 SOP 和那一脑袋用户心理学。

2.3 承载形式：一个文件夹

讲师强调得很直白——Skills 怎么交付？就是一个文件夹。里面装：

  • 工具（tools）
  • 脚本（scripts）
  • 资源（resources）
  • 文档（docs）

这听上去过于朴素，但反直觉的点恰恰在这里：你不需要发明一套 SDK 或 API，专业知识就是写成 md，流程就是写成步骤说明，工具就是脚本和 MCP 配置——文件夹是最低门槛的承载形式。具体里面长啥样，本集没展开，留给 10-5。

2.4 真正的刀口：Skills 工作流 vs Workflow

这一段是本集的灵魂，也是最容易和 7-12 那集 Graph 工作流混的地方。

Skills 里的工作流程 前面讲的 Workflow
是什么 行业固定 SOP 节点拼装的流程图
写在哪 Agent 的文件夹里 流程图（业务逻辑在节点连线里）
谁来搭 已经沉淀好，直接拿 主管手动封装（分支/汇总/并行）
怎么跑 Agent 自己按 SOP 走 由编排引擎驱动
适合场景 行业有固定流程 任务个性化/定制化

讲师用产品经理串到底：要完成什么任务 → 完成的步骤 → 最后输出——这三段恰好是 Skills 工作流的内部结构（帧图里”要完成什么任务 / 完成的步骤 / 最后输出”那条线）。

加工增量：我把它压成一个判断题——业务逻辑沉在哪里？沉在 Agent 文件里就是 Skills，沉在流程图节点里就是 Workflow。这条线一拉出来，以后做技术选型就不会两个都想用。

3. 没 get 的点

  • 文件夹里的”脚本”到底是 bash、Python，还是 prompt 模板？本集没展开，等 10-5 文件结构标准。
  • “Agent 自己按固定流程走”是怎么走的？大概率是把 SOP 写进 system prompt 让 LLM 自己 follow（看 Claude Code 的做法），但本集没明说。
  • 专业知识 + 工作流程会不会和 RAG 重叠？Skills 的”多出来的部分”应该是 SOP + 工具，但和”领域知识 RAG”的边界还得自己实操验证。
  • Skills 的固定 SOP 如果有进化或冲突怎么办？文件夹是否要版本化？本集没提。
  • 帧图正中央的”Agent 主管 / Agent 执行者 / 主上下文”那一栏画得密，但本集语音没展开，需要回看 10-1 SubAgent。

4. 跟其他集的连接

  • 上承：3-7 具有专业知识的Agent_Skills 给了”领域知识 + 按需加载”的第一印象；10-2 Agent_Skills就是个专属工作流 第一次抛出”工作流”这个词——本集把那个词拆成三件套。
  • 下启：10-4 Skills的渐进式加载机制 回答”一文件夹怎么按需加载不爆上下文”；10-5 Skills的文件结构标准 把”文件夹里到底放什么”敲死；10-7 SpringAi_112实现Agent装载Skills 是代码落地。
  • 横向：3-8 工具调用最强组合Agent_SkillsMCP 讲 Skills 和 MCP 怎么搭，本集讲怎么分；3-12 多Agent的核心执行流程 里的”主管 Agent + 专科 Agent” 在本集帧图里实体化为”产品领域 Skills / 代码领域 Skills / 测试领域 Skills / 安全领域 Skills / 运维领域 Skills”五个主管分挂 Skills 包；Workflow 对比那段回看 7-12 基于Graph搭建旅游规划工作流 的节点编排。

5. 知识地图

6. 自测题（5 卡）

  1. Skills 三件套是哪三件？工具调用属于哪一件？
  2. MCP 和 Skills 是不是同一个东西？用一句话说清两者各自解决什么问题。
  3. 产品经理的 Skills 包里，”专业知识”除了产品知识还包括什么？
  4. Skills 里的”工作流程”和前面讲的 Workflow 关键差异在哪？业务逻辑分别沉淀在哪里？
  5. Skills 通过什么形式赋予智能体？里面装的四类东西是什么？

7. 关键词表

术语 含义
Skills 三件套 专业知识 + 工作流程 + 执行逻辑，Skills 的最小完备拆分
专业知识 领域知识 + 用户心理学 + 行为学 + 消费习惯，不只是 know-what
工作流程 = 固定SOP 完成任务 → 步骤 → 最后输出，行业内固定可复用
执行逻辑 = 工具调用 怎么用墨刀、Axure 等具体工具，MCP/Function Calling 那一层
文件夹承载 Skills 以文件夹形式赋予 Agent，内含工具/脚本/资源/文档
Skills vs MCP 技能系统标准 vs 外部工具连接标准，纵向装领域 vs 横向连工具
Skills 工作流 vs Workflow 业务逻辑沉在 Agent 文件里 vs 沉在流程图节点里
应用场景分野 行业有固定流程用 Skills，个性化定制用 Workflow
