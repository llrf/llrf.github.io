7-05 搭建工作流的流程顺序：Edge

发表于2026-05-19|更新于2026-05-21|Agent学习第07章 Graph 搭建旅游规划工作流，像拼积木一样轻松
|浏览量:

一句话定位

工作流四对象的第三块——边。7-3 你 new 出空蓝图 StateGraph，7-4 用 addNode 把两个干活的节点塞进去；这一集用 addEdge 把节点之间画箭头串成一条单向链：用户 Prompt → node1 → node2 → 大模型输出。

主体

1. 一个 API 一句话：addEdge(String, String)

两参都是 String，就是节点的 id。不传节点对象——节点对象在 addNode 阶段已经按 id 注册过了，addEdge 阶段全程只认字符串。这个解耦你要记住：addNode 管”谁存在”、addEdge 管”谁连谁”，互不重叠。

源码内部把这两个字符串包成 new Edge(sourceId, new EdgeValue(targetId))，扔进 this.edges.elements 这个列表里。

4. 三条边的姿势其实是同一个签名

**【加工增量】**三条边写法不对称，容易让你误以为是三个重载——其实就是同一个 (String, String) 签名，常量名长得不像字符串才让人产生错觉。心里默念：START / END 也都是 String。

6. 这一集结束时你手上的拓扑

对应的图：

工作流叫 "parallel"，但实际画出来是纯顺序链——名字和拓扑不一致这件事先记下，估计后面会演同一个 source 多 target 的并行分支用法。

没 get 的点

  • 条件边在哪？本集只演直链（一对一）。但源码里有 if (index >= 0) { newTargets.add(...) } 这段——意思是同一 sourceId 可以多次 addEdge，被合并到一条 Edge 的多个 EdgeValue 上。这就是分支的种子，但按什么条件路由（看 OverAllState 的某个 key？）讲师没讲，估计后面会有 addConditionalEdge 之类的 API。
  • **StateGraph.START / END 的字面值是什么？**视频只看到使用、没截到常量定义。猜测是带下划线前缀的保留串。
  • **invoke 阶段用户 Prompt 怎么注入 START？**本集只画了静态拓扑。START → node1 这条边存在了，但用户输入的字符串怎么进到 OverAllState 让 node1 的 apply 读到？要等 7-6 编译运行才知道。
  • 工作流名叫 parallel 但画的是顺序链——同一 source 多个 target 的并行用法，本集没演。
  • **AsyncNodeAction.node_async(...) 的 async 到底什么时候生效？**边是同步声明的，节点是 async 包装——是返回 CompletableFuture 的语法包装，还是运行期真会并发调度？要等 7-6 看 invoke 行为。

跟其他集连接

  • 上承 7-4：本集开头一分钟在回顾 addNode(id, AsyncNodeAction.node_async(new NodeX())) 的写法和 NodeAction 接口的 apply(OverAllState) 套路；本集要连的”node1 / node2”就是 7-4 注册的那两个 id。再往上 7-3 new 出 StateGraph 容器，7-2 造好 OverAllState——本集补完工作流四对象的第 ③ 块（边）。
  • 下启 7-6：本集只画了静态拓扑，节点 apply 里到底拿到什么 key、写回什么 key、用户 Prompt 怎么通过 START 注入 OverAllState——全要等 stateGraph.compile() + .invoke(Map) 跑起来才看得见。再往后 7-7 把这张拓扑画出来，7-12 把本章 demo 落到 5 章那套四角色团队。
  • 横向 6-8：6-8 的 SequentialAgent.builder().subAgents(a1, a2).build() 一行声明 a1 → a2 顺序，是高层封装；本集是底层 StateGraph，addEdge("a1", "a2") 显式画线。看懂本集后回头看 6-8 会觉得 SequentialAgent 内部很可能就是在调 addEdge。
  • 横向 3-10 / 4-14：本集是同一进程内的节点连线（sourceId/targetId 静态指定，编译期写死的 DAG）；A2A 是跨进程的 Agent 调用（Nacos 注册中心 + AgentCard 运行期动态发现）。一个静态拓扑，一个动态网状。
  • 横向 4-5：@Tool 注解 / Skills 文件 / addEdge 都是”声明式编程”——预先声明而不是用代码逻辑判断（这点和条件边冲突，本集没讲分支，全是直链）。

知识地图

自测题（5 卡）

  1. Q：stateGraph.addEdge(...) 两个参数分别是什么类型？为什么不是 NodeAction 对象？
    A：两个都是 String，是节点的 id。节点对象在 addNode("node1", ...) 阶段已经按 id 注册过了，addEdge 阶段只用 id 引用，做到节点对象与拓扑结构的解耦——这是声明式 DAG 的核心哲学。

  2. Q：用户 Prompt 和大模型输出这两个端点要不要 addNode？怎么在 addEdge 里引用它们？
    A：不要 addNode。它们是框架预留的两个”假节点”，分别用 StateGraph.START 和 StateGraph.END 两个静态常量当 id。它们本质上是保留字符串，直接塞进 addEdge 的参数位即可，例如 addEdge(StateGraph.START, "node1")。

  3. Q：把 START → node1 → node2 → END 这条完整链画出来要写几句 addEdge？分别长什么样？
    A：三句。① addEdge("node1", "node2") ② addEdge(StateGraph.START, "node1") ③ addEdge("node2", StateGraph.END)。三种姿势其实是同一个 (String, String) 签名，只是常量名长得不像字符串容易让人误判。

  4. Q：addEdge 源码开头那条 if (Objects.equals(sourceId, END)) throw ... 在守什么规则？
    A：守 DAG 的单向性。END 是终点，不能再作为发出方（不能 addEdge(END, X)），否则箭头流出终点就破坏了有向无环图的语义。对称地，START 不能作为接收方。

  5. Q：本集结束时你手上的工作流能跑了吗？还差什么？
    A：还不能。手上有的是静态拓扑——节点 + 边都声明完了。还差：① stateGraph.compile() 把蓝图编译成可执行对象，② .invoke(Map) 喂入用户 prompt 真正跑起来，③ 验证 START 怎么把用户输入注入 OverAllState 让 node1 读到。这些是 7-6 的内容。
