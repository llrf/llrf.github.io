4-08 Jmanus导入SpringAi自定义的MCP服务

发表于2026-05-19|更新于2026-05-21|Agent学习第04章 SpringAi 1.1 实现 MCP+A2A
|浏览量:

1. 一句话定位

把 4-1~4-7 攒了七集的 SAA 天气 MCP 服务端”插”到 JManus 上跑通的那一刻。

2. 主体讲解

这一集你其实只在做一件事

⏱ 00:00–00:30 · 引出本集只做一件事，纯讲

把一台已经写好的 MCP 服务器，注册进 JManus。

听起来很短，因为它本来就很短。这集完全不动 Java 代码，全部产出就是：一个 application.yml、一个空壳启动类、一段 JManus 上的 UI 填表。配前后端在一台机器上跑就完了。

但短不等于无脑 —— 中间藏了两个坑，你按文档照抄是踩不出来的。

两侧字段的对应关系（先把这个建立起来）

⏱ 04:00–05:00 · JManus 表单字段与服务端 yml 对应关系，纯讲

JManus 那侧的”新建 MCP 配置”表单只有三个字段：MCP 名称、连接类型、URL。三个字段全部对应你 MCP 服务端这侧 application.yml 里的设定。把这张对应关系记牢，剩下都是细节：

JManus 表单字段 服务端 yml 字段 / 含义
MCP 名称 spring.ai.mcp.server.name（必须和服务端一致，方便管理）
连接类型 SSE / STUDIO / STREAMING 三选一，对应传输层
URL http://host:port + sse-message-endpoint 的路径

⏱ 04:49

连接类型那一栏的选择就是 4-3 / 4-4 讲过的传输层落地点 —— STUDIO 是本地进程（要填 Command/Args/Env），SSE 和 STREAMING 都是远程（只要 URL）。你这集走的是 SSE，因为前面 4-4 就铺垫好了走 SSE。

坑 1：sse-message-endpoint 文档没写但必须配

📺 00:30–02:30 · IDEA 中编辑 application.yml 加上文档省略的端点

application.yml 关键内容：

⏱ 00:46

前 4 个字段（port / name / version / type）都是照 SAA 官方文档抄的。但最后一行 sse-message-endpoint: /mcp/weather —— 文档里没有。如果你像我一样老实照文档抄，启动倒是能起，但 JManus 那侧根本对不上。

讲师明确说：”这个坑我帮大家踩了。” 这就是取舍出现在 §2 —— 我没有去深究 SAA 文档为什么省略这个字段、SAA starter 在没配的情况下默认走的是什么 endpoint，这件事拍源码就能搞清楚但跟”跑通”无关。这一集只关心：配上它，能用就行。

坑 2：那个 URL 必须含 “sse”

📺 02:30–07:30 · 启动服务后到 JManus 填表保存遇 400 报错并修正

启动类 WeatherMCPApplication 写完（就一个 @SpringBootApplication 加 SpringApplication.run(...)，没别的），点 Run，Netty 在 8081 跑起来：

⏱ 02:37

然后启动 JManus，进工作台 → 设置（两条横杠）→ Tools/MCP 配置 → 新建 MCP 配置 → 三个字段填上：

  • MCP 名称：imooc-weather-mcp-server
  • 连接类型：SSE
  • URL：http://127.0.0.1:8081/mcp/weather

点保存。报错 400：

⏱ 05:43

这不是 MCP 协议要求的，是 JManus 前端自己加的硬校验：只要你选 SSE 连接类型，URL 的 path 部分必须出现字符串 “sse”。所以你得回去把 sse-message-endpoint 改成带 sse 的路径（例如 /sse/mcp/weather），重启服务端，把新 URL 填回 JManus，保存才成功。

这里就是加工增量在 §2 —— understanding.md 里只把两个坑并列罗列，没有点破第二个坑的本质：它跟 MCP 协议本身无关，是 JManus 这个 Host 出于自身实现方便加的前端验证。你要意识到这一点，下次换一个 MCP Host（比如 Claude Desktop、Cursor），就不会预期它也校验 “sse” 字样。

3. 我一开始没 get 的点 / 容易踩的坑

  1. 如果你照 SAA 官方文档原样抄 application.yml，会得到 JManus 那侧死活连不上。 文档省略了 sse-message-endpoint，必须自己补，否则等于没暴露 SSE 端点。
  2. 如果你以为 URL 只要协议+host+port+path 合法就行，会撞 JManus 的 400。 SSE 类型下 path 必须字面上包含 “sse”，这是 JManus 前端校验，不是协议要求；解决方式是把服务端 endpoint 改成带 sse 的名字。
  3. 如果你以为本集要新写 @Tool 或动 Java 代码，会发现完全没用上。 工具是上集就注册好的，本集只是改 yml + UI 操作。启动类 WeatherMCPApplication 也只是个空壳 @SpringBootApplication。
  4. 如果你以为”导入 MCP”是改 JManus 代码，会找错地方。 是纯 UI 操作 —— 工作台 → 设置（两条横杠图标）→ Tools/MCP 配置 → 新建 MCP 配置。零代码改动，跟 3-6 用魔搭社区 MCP 的操作完全一样的面板。

4. 跟其他集的连接

上承

  • 4-2：spring-ai-mcp 依赖把 MCP server starter 拉进来。

  • 4-4：SSE 实时通信细节，解释为什么用它做 MCP 远程传输。
  • 4-5：@Tool / @ToolParam 写了天气工具的方法级声明。
  • 4-6：MethodToolCallbackProvider 把方法打包成工具清单 Bean。

本集是 4-x 系列第一次能从消费者视角（JManus）真正调用到自己写的 MCP的闭环时刻。前 7 集都在搭”被调用方”，本集补上”调用方的注册”。

下启

保存成功后服务器列表里就多了 imooc-weather-mcp-server。下一集很可能是：

  • 在 JManus 里让 Agent 真正去调用这个 weather 工具（测一次”北京今天天气”那种）；
  • 或者讲 Agent 配置如何挂载特定 MCP 服务，以”减少工具冲突，提高选择准确性”（页面上”使用说明”第 3 条已经埋了伏笔）。

横向

  • 3-5 讲过 MCP 客户端要先 list 服务端工具：本集是 list 这件事跑通的可视化证据 —— 服务器列表里出现条目 = client 已经成功握手并拉到清单。

5. 知识地图

6. 自测题

Q1（概念回忆） JManus 新建 MCP 配置的三个表单字段是什么？分别对应服务端 application.yml 里的什么？
A1：MCP 名称（对应 spring.ai.mcp.server.name） / 连接类型（SSE 对应传输层选择，决定走 SSE / STUDIO / STREAMING） / URL（http://host:port + sse-message-endpoint 路径）。详见 §2 对应关系表。

Q2（反直觉陷阱） 你照 SAA 官方文档把 application.yml 配齐了，启动也成功，但 JManus 那侧加 MCP 报错连不上。最可能漏了哪一行？
A2：spring.ai.mcp.server.sse-message-endpoint。这一行 SAA 官方文档没写但必须配，否则 SSE 端点路径没暴露，客户端无法对接。详见 §2 坑 1。

Q3（反直觉陷阱） 你保存 MCP 配置时报 400 - SSE type URL path must contain 'sse'，但你的 URL 是 http://127.0.0.1:8081/mcp/weather，端口路径都对，为什么不让保存？这是 MCP 协议规定的吗？
A3：不是 MCP 协议规定的，是 JManus 前端自己加的硬校验：选 SSE 连接类型时 URL 的 path 必须字面出现 “sse”。解决方式是把服务端 sse-message-endpoint 改成含 sse 的路径（如 /sse/mcp/weather），重启后用新 URL 填回 JManus。详见 §2 坑 2。

Q4（跨集连接） 本集和 3-6（魔搭社区 MCP 配置）操作面板完全一样，区别只在哪里？这个对比说明 MCP 的什么价值？
A4：区别在 URL —— 3-6 的 URL 是魔搭社区给的 24h 临时 hosted MCP 地址，本集的 URL 是本机 8081 的自建服务。面板和填法一致说明 MCP 把”工具来源”标准化了，消费者（JManus）不关心 server 是 hosted 还是 local。详见 §4 横向。

Q5（应用 / 推广） 假设你换用 Cursor 或 Claude Desktop 作为 MCP Host，把你这台 8081 的天气服务接进去，要做的事和本集完全一样吗？哪一步可能不一样？
A5：服务端那侧完全一样（yml + 启动类，提供 SSE endpoint）。Host 那侧的填表流程类似但不一定逐项相同 —— 关键是”URL path 必须含 sse”是 JManus 自己的校验，换 Host 就不一定有这条限制，所以 sse-message-endpoint 的命名可以不必带 sse 字样。详见 §2 坑 2 与 §3 第 2 条。

7. 关键词表

术语 一句话定义

JManus MCP 配置三要素 SSE 模式下表单的三个字段：MCP 名称 / 连接类型 / URL
SSE URL 路径含 sse 校验 JManus 前端硬规则：SSE 类型 URL 的 path 必须出现 “sse”，与 MCP 协议无关
连接类型三选一（STUDIO/SSE/STREAMING） STUDIO 本地进程要 Command/Args/Env，SSE / STREAMING 远程只要 URL
WeatherMCPApplication 启动类 MCP Server 的 SpringBoot 启动类，空壳 @SpringBootApplication，能力全部来自 starter 自动装配

服务端 / 客户端在同一 Host 跑通 MCP server (8081) 与嵌在 JManus 内的 MCP client 完成一次握手 = 整条 4-x 系列跑通
