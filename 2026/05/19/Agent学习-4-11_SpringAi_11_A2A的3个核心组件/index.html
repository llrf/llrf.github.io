SpringAi 1.1 A2A的3个核心组件

一句话定位

A2A 在 Spring AI Alibaba 1.1 里就是给 Agent 套一层注册中心，凑出 Provider / Registry / Consumer 三件套。

主体讲解

先把骨架钉死：三个核心组件

你只需要记住一张图：A2A Provider 把本地 Agent 暴露出去 → 在 Nacos Registry 里注册自己有什么能力 → A2A Consumer 去 Registry 查询 / 发现，然后远程调用。

这套术语其实有两层皮，别被绕进去：

讲师口中 官方文档 干什么
A2A Provider A2AServer 把本地 ReactAgent 暴露成 A2A 服务
A2A Registry A2ARegistry Agent 注册中心，Spring AI Alibaba 用 Nacos
A2A Consumer A2ADiscovery 远程调用别人 Agent，做服务发现

讲师全程喊 Provider / Consumer，那是微服务习惯。看官方文档的时候你会看到 Server / Discovery，是同一回事，一年后翻代码碰上哪个词都别懵。

这里把讲师的顺序换掉了（取舍出现在 §主体讲解）：原视频是先写 pom、建模块，再反向追问”A 怎么知道 B 存在”，最后才揭谜底”原来要有注册中心”。我反过来——先把 Registry 是核心这件事敲死，剩下的全是补充。一年后你不需要再被悬念吊一遍。

反直觉的事实：A2A 不只用于跨厂商大模型

你大概率会以为 A2A = 跨厂商大模型互通专用。错。A2A 协议解决的是”分布式 Agent 之间标准化通信”，跟模型同不同根本无关：

  • 跨厂商模型的 Agent 互调 → 用 A2A
  • 同一个大模型，部署在不同节点 → 也用 A2A

共同点只有一条：分布在不同节点。只要它们按同一标准协议讲话就行。跨模型只是 A2A 的一个 use case 而已。

类比抓手：这就是 Spring Cloud 的微服务套路

如果你写过 Spring Cloud，下面这张映射表你 30 秒就懂：

微服务世界 A2A 世界
服务提供者 A2A Provider
注册中心（Nacos） A2A Registry（也是 Nacos 3.1）
服务发现者 / 消费者 A2A Consumer
服务实例信息 AgentCard（Agent 的能力名片）

唯一的区别是：注册中心里挂的不再是 service instance，而是 AgentCard——里面记着这个 Agent 叫什么、能干什么。Consumer 不是按服务名瞎调，而是按”能力描述”去匹配哪个 Provider 能解决当前问题（具体怎么匹配下集应该会讲）。

加工增量在 §主体讲解：原视频从头到尾没把 A2A 与 Spring Cloud 做直接映射，只是各自描述。这里把两套术语做成对照表，下次你看到 spring.ai.alibaba.a2a 开头的配置，脑子里立刻能对到 spring.cloud.nacos，迁移成本归零。

工程落地：两个模块 + BOM + 一个开关

代码层面这集只摆了骨架，关键点就 4 个：

  1. BOM 管版本：跟 MCP 那集一样，导 spring-ai-alibaba-bom 1.1.0.0-RC2。

  2. agent-framework starter：A2A 实现都在 spring-ai-alibaba-agent-framework 里，因为有 BOM 兜底，不写 version。

  3. 两个模块同机起：a2a-provider 用 8081，a2a-consumer 用 8082。同机部署所以必须避端口冲突。

  4. 打开 A2A 服务端开关：Provider 的 application.yml 里 spring.ai.alibaba.a2a.server.enabled: true，这一行不写，Provider 就只是普通 Spring Boot 而已。

我一开始没 get 的点

  • “Nekers” 是什么鬼：transcript 里反复出现的 Nekers，其实是 ASR 把 Nacos 听岔了。看到这个词直接脑补成 Nacos 就行。
  • 跨模型才能用 A2A？：不是。同模型不同节点也用，A2A 解决的是分布式 Agent 通信，模型同不同无关紧要。
  • Consumer 怎么找到 Provider？：不是直连 IP。Provider 启动时往 Registry 注册 AgentCard，Consumer 启动时去 Registry 查询 / 订阅。中间必须有 Registry 这个节点，跟 Nacos 注册服务一模一样。
  • Server 和 Provider 是两个东西吗？：不是。官方写 A2AServer / A2ADiscovery，讲师讲 Provider / Consumer，两套词同一件事。下集真上代码时记得对一下 import 的类名到底叫哪个。

跟其他集的连接

上承

  • 3-10 多Agent跨部门协作：A2A协议：那集讲了 A2A 的 7 步流程和 AgentCard 概念，是协议层面的铺垫；本集是 Spring AI Alibaba 1.1 的落地实现。
  • 4-1 以bom方式导入SpringAi Alibaba依赖 和 4-2 导入MCP依赖：BOM 三件套 + starter 不写 version 的范式，这集直接复用。

下启

  • 4-12 起大概率会逐个拆：AgentCard 字段定义、A2AServer 详细配置、Nacos 3.1 接入步骤、Consumer 端远程调用 API 长什么样。本集里只露了 a2a.server.enabled: true 一个开关，配套的其他配置（注册地址、AgentCard 提供者等）都在后面。

横向

  • 跟 3-4~3-6 的 MCP 系列 对照看：MCP 是 Host-Client-Server 三层，给 LLM 接工具；A2A 是 Provider-Registry-Consumer 三层，给 Agent 接 Agent。两个都是”分层 + 注册 / 发现”思路，但 MCP 解决”工具复用”，A2A 解决”Agent 跨节点协作”。
  • 跟 3-9 多 Agent 协作、3-12 多 Agent 核心执行流程 对照：那两集讲的是”主管 Agent + 专科 Agent”的分工设计，本集解决的是”专科 Agent 不在同一进程里怎么办”的物理层问题。
