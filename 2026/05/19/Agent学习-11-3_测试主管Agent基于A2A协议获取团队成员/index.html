2.2 远程 Agent 怎么在代码里”长出来”

工具方法长这样（manager_agent 模块下 RemoteAgentTool.java）：

三个关键点你要看进眼里：

  1. .name("RouteMakingAgent") 是查找 key，必须和远端 ReactAgent.builder().name(...) 一字不差，也必须和 Nacos 控制台里 Agent 列表那一行的名字一字不差。错一个大小写就拉不到。这条规则在 4-14 / 4-15 就埋好了，这里第一次实战兑现。
  2. NacosAgentCardResolver 吃的是 NacosUtil.getNacosProperties()（Nacos 地址 / 命名空间），它负责按 name 去注册中心”翻字典”，把 Agent Card 翻出来塞给 A2aAgent。
  3. @Tool 注解的方法是 LLM 看得见的工具，方法体里跑 A2A 调用 — 等于把”调用远程 Agent”这个动作再包了一层”工具”，让 ReAct 框架的 LLM 能在 prompt 里命中它。这层胶水你在 SAA 1.1 那条线里见过类似设计，这里换到 AgentScope 框架。

加工增量：消化稿里我额外画了一层心智模型 — LLM → @Tool 方法（胶水层）→ A2aAgent（A2A 客户端）→ Nacos → 远端 Agent。如果你以为 LLM 直接拿 Agent 卡片去调，那是错的，中间那层 @Tool 方法是手动写的。

6. 自测题（5 卡）

  1. Q：A2aAgent.builder().name("RouteMakingAgent") 这个字符串里如果把大写 R 改成小写 r 会怎样？
    A：拉不到 Agent Card，因为 Nacos 注册中心存的 key 是远端 ReactAgent.builder().name("RouteMakingAgent") 一字不差注册进去的；客户端的 name 必须三处一致。

  2. Q：本集为什么把启动类的 @SpringBootApplication 注释掉了？
    A：AgentScope 这条线让 ManagerAgent 裸跑（new ManagerAgent().run()），不依赖 Spring 容器扫描，工具靠 getReActAgentBuilder().tools(...) 手工挂上去。

  3. Q：两阶段测试法分别验证哪一环？
    A：第一阶段（注释掉 A2aAgent 那段）只验证「LLM → 命中 @Tool 方法」；第二阶段（解除注释 + 打印 description）验证「NacosAgentCardResolver → 拉到远端 Agent Card」。

  4. Q：启动顺序为什么必须先 RouteMakingAgent 再 ManagerAgent？
    A：RouteMakingAgent 启动时才把自己的 Agent Card 推到 Nacos；ManagerAgent 启动后立刻去 Nacos 查找，如果远端还没注册就查不到（NPE / 拉不到描述）。

  5. Q：本集的 agent.call().block() 跑完了结果去哪了？
    A：丢弃了。callRouteMakingAgent() 返回 void，本集只验证”能调通”。把返回值接回主管上下文是 11-4 的活。

7. 关键词表

术语 一句话
A2aAgent.builder() AgentScope 框架下的远程 Agent 客户端构造器，链式设置 name + agentCardResolver。
NacosAgentCardResolver 服务发现解析器，吃 NacosUtil 提供的连接配置，按 name 去 Nacos 拉 Agent Card。
@Tool 包装远程 Agent 把”调用远程 Agent”包成 LLM 看得懂的工具方法，description 给 LLM 看，方法体跑 A2A。
name 一致性铁律 客户端 .name、服务端 ReactAgent.builder().name、Nacos 里的 Agent Card name 三处必须一字不差。
agent.call().block() A2aAgent 的同步运行入口，call() 返反应式流，block() 阻塞取结果。本集没用返回值。
ManagerAgent 裸跑 启动类 @SpringBootApplication 注释掉，main 里 new ManagerAgent().run()，不进 Spring 容器。
getDescription() 探针 A2aAgent 拉到后调 getDescription() 返回远端 description 字段，能拿到证明卡片完整。
两阶段测试法 先注释重活验轻活（命中工具），再放重活（拉描述），日志驱动的渐进验证。
