主管Agent暴露和用户交互的接口

1. 一句话定位

你给整套分布式 Agent 装一个”前门”——一个 POST /trip 接口，用户只跟主管 Agent 说一句话，剩下的路线/行程/A2A 全是它自己跑。

2. 主体

用户站在哪一头

⏱ 00:00–00:31 · 架构图讲解人与主管 Agent 的入口位置

看一眼架构图（f001）：四个节点里只有”主管 Agent”那条线上画了”用户 WebApi 请求（输入 Prompt）”的入口箭头，路线 Agent、行程 Agent 都不直接面向人。结论：人 → 主管 Agent 这一段必须是 HTTP，主管 → 子 Agent 那一段才是 A2A 协议。所以本集要做的就是给主管 Agent 套一层 Spring MVC 外壳。

三步搭好这层外壳

📺 00:31–01:24 · IDE 中新建 Controller 并写 /trip POST 接口

在 manager_agent 模块里新建 controller/ManagerAgentController（f004→f005），代码骨架就这几行：

注意这里 ManagerAgent（你自己写的包装类，f012）和 ReActAgent（框架里真正干活的那个）不是一个东西——Controller 拿到包装类，再从里面 getManagerAgent() 掏出 ReAct 实例。

一个容易漏的小动作

📺 01:24–01:33 · IDE 中给 ManagerAgent 类补 @Component

@Resource 想生效，被注入的 ManagerAgent 这个类自己也得是 Spring Bean。所以回到 ManagerAgent.java 给它补上 @Component（f012、f013）。取舍提示：视频里这一步是回头补的，说明老师讲的时候也忘了——很正常，遇到注入失败你先去看类头上有没有这个注解。

端口为什么要全局规划

⏱ 01:33–02:07 · 端口分配表与多模块同跑约束讲解

四个模块都在同一个 IDEA 里同时跑（要勾 Run Configuration 的 Allow Multiple Instances），全用默认 8080 必撞。Preview 文档（f014、f016）写死了一张表：

模块 端口 角色
ManagerAgent 8081 用户 Prompt 入口
RouteMakingAgent 8082 路线制定
TripPlannerAgent 8085 行程规划
NacosA2A 8848 A2A 协议的注册中心

加工增量：视频口播是 8081，但 f022 终端打印的是 Tomcat started on port 8182，f020/f024 API Fox 调的也是 127.0.0.1:8182/trip。怀疑后期老师改过端口或者临时让位（也许 8081 被本机占用了）。你自己跑的时候以 properties 里实际配置为准，别死记 8081。

验证只到”接口能进函数”

📺 02:07–03:17 · APIFox 发请求 + IDEA 终端看日志现场验证

在 API Fox 里发一个 POST 127.0.0.1:8182/trip（f019→f025），然后回 IDEA 看日志（f028）：

  • aliApiKey: **** —— 13-1 的敏感配置确实读进来了
  • 主管 Agent 使用的大模型: qwen3-max
  • Registered tool 'callRouteMakingAgent' / callTripPlannerAgent / create_plan 等一长串

这三类日志同时出现就算通了。但要诚实：tripPlan() 现在是 void 还没收任何参数（f032），managerAgent.run() 是空跑——这一集只搭好”门”，门后面的接待流程还没接 prompt（见下一集 13-5）。

3. 没 get 的点

  • 视频口播 8081 vs 终端 8182 这个出入到底是临时改的还是录制时口误，需要去后续课件里 grep server.port 看一眼。
  • managerAgent.run() 这个调用是同步还是异步？如果同步，一次旅游规划要跑十几秒甚至更久，HTTP 连接会不会就被挂住直到超时？后面观测链路时（13-3 docker / 13-4 追踪）应该能看到。
  • 为什么主管 Agent 不也注册成一张 A2A Agent Card 让别人调用？目前的设计是把”用户”和”Agent”严格分成两类身份：人/前端走 HTTP，Agent 之间走 A2A。这种分层是不是必须的，需要再观察。

4. 跟其他集连接

  • 上承 13-1：13-1 把 .env + Properties 那套配置打通，本集启动后 aliApiKey、qwen3-max 这两行日志就是给 13-1 打的回执。
  • 上承 11-1：11-1 回顾AgentScope旅游规划的整体架构 画的四模块骨架里，”用户 → 主管”那条线一直是悬空的，本集第一次把它接到了实际 Controller。
  • 下启 13-5：测试主管 Agent 接收 Prompt 及结构化输出，会把 tripPlan() 的 void 改成 @RequestBody 真吃 prompt，把架子填满。
  • 下启 13-3/13-4：docker 化 + 调用链追踪，开始观测这条链路而不只是”能进函数”。
  • 横向对照 11-7：11-7 主管Agent自主分发任务给远程相应的成员 已经跑通”主管 → 远程 Agent”那一段，本集相当于在它前面接了”用户 → 主管”。
  • 横向对照 11-8：11-8 人工介入修改主管Agent制定的计划 走的是 Hook 拦截让人插话，本集走的是 Web API 给人开门——两种”人和 Agent 交互”的姿势，一种事中改，一种事前发起。

5. 知识地图

主线：HTTP 只在最上面一段，越往下越是 Agent 之间的协议；本集只动了顶部那一格。

6. 自测题

  1. 为什么 @Resource ManagerAgent 在 Controller 里能注入，关键是给 ManagerAgent 类加了什么注解？
  2. ManagerAgent 和 ReActAgent 是同一个对象吗？Controller 里那行 getManagerAgent() 在做什么？
  3. 四个模块的端口为什么必须各不相同？默认都用 8080 会发生什么？
  4. 启动后只看到 aliApiKey 打印、没看到 Registered tool 'callRouteMakingAgent'，可能是哪一层出了问题？
  5. 本集的 tripPlan() 签名是 void、没接 @RequestBody，那 API Fox 点”发送”之后主管 Agent 真的开始规划了吗？为什么？
