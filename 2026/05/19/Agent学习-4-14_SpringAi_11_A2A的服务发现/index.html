4-14 SpringAi 1.1 A2A的服务发现

发表于2026-05-19|更新于2026-05-21|Agent学习第04章 SpringAi 1.1 实现 MCP+A2A
|浏览量:

1. 一句话定位

Consumer 这边不写 ReactAgent，写一个 A2aRemoteAgent——它是个壳，唯一职责就是拿 .name("AgentProvider") 当 key 去 Nacos 把远程 Agent 找出来，然后用 invoke() 把提示词转发过去。

2. 主体

2.1 心智模型先立起来：Consumer = Nacos 客户端 + 远程代理

整个 4-11 给你看过 A2A 的三件套（Provider / Registry / Consumer）。4-13 你把 Provider 那边的 ReactAgent 建好、注册到了 Nacos。这一集做的就是最后一块拼图：Consumer 端怎么从 Nacos 里把那个 ReactAgent 拽过来用。

关键反直觉点先放最前面（取舍出现在 §2.1：消化稿原本是按视频顺序”先建 Service → 试 ReactAgent → 发现不对 → 改 A2aRemoteAgent”组织的，我把”试错”砍掉了，直接给结论；试错回看价值低）：

  • Consumer 不执行业务。业务（比如查天气）是远端 Provider 那边的 ReactAgent 干的，Consumer 这边只负责”发现+转发”。
  • 所以这边不能套用 ReactAgent.builder()。需要的是另一个对象：A2aRemoteAgent——同样 SAA 1.1 给你封装好了，专门做”远程代理调用”。

2.2 application.yml：先把 Nacos 地址讲清楚

A2aRemoteAgent.builder() 凭什么能拉到远程 Agent？因为配置文件里告诉了它注册中心在哪：

记住两个点：

  • server-addr 指向 Nacos 实例的位置（默认 8848）。
  • discovery.enabled: true 必须开，不开就没有服务发现能力，builder 那行会拉空。
  • Consumer 端口 8082，跟 Provider 错开（同机起两个 Spring Boot 进程，不撞端口）。

2.3 A2aRemoteAgent：name 是查询 key，不是变量名

这是这一集最容易踩的坑。看代码：

第一直觉会觉得 .name("AgentProvider") 是给本地这个对象起个变量名/ID。不是。这个字符串就是 Nacos 里 Provider 注册时写的那个 name（即 4-13 里 ReactAgent.builder().name("AgentProvider") 那一处）。它充当查询 key，写错了就找不到对应远程 Agent。

可以这样记：Consumer 这边的 .name(x) 和 Provider 那边的 .name(x) 是一根绳子的两头，绳子穿过 Nacos。

2.4 invoke：触发远程调用，但返回的不是字符串

两件需要内化的事：

  1. invoke 签名上有 throws GraphRunnerException，必须 try 或 throws 出去，IDE 那条红线就是在催你这个。
  2. 返回值不是 String。是 Optional<OverAllState>。这就引出下一节。

2.5 OverAllState：硬塞进来的”工作流状态包”

OverAllState 严格来说是后面 DAG/工作流那一章才会展开的概念。这里硬塞进来你只需要抓住三点：

  • 它是工作流里在节点之间流动的状态对象——上一个节点把执行结果塞进它，下一个节点从它里面拿。
  • 它内部是 KV（key-value）结构。每个节点把自己的结果以特定 key 写进去。
  • 所以从 Optional<OverAllState> 抠答案，必须知道 key。讲师在这里”暂时先用一个 key”含糊带过了——实际能用的 key 集合来自 Provider 端 ReactAgent.builder().outputKey(...) 配置（前面截图里能看到这个方法），下一集大概率会补。

2.6 为什么不能用 ReactAgent（反例对比）

把这个放最后做个回扣（加工增量在 §2.6：视频里”试错→改对”是讲师的教学法，对一年后的你没价值；我把它压成一个对照表，明确”职责差异”这一个点）：

维度 ReactAgent A2aRemoteAgent
部署位置 Provider 端，本地执行 Consumer 端，本地不执行业务
是否需要 model / tool 需要 不需要
name 的语义 注册到 Nacos 的注册名 查询 Nacos 用的 key
内部行为 思考-决策-工具调用 转发请求到远程 Agent

一句话：ReactAgent 是”干活的”，A2aRemoteAgent 是”找人干活的”。

3. 没 get 的点

  • state.value(key) 那个 key 到底叫什么？讲师”暂时先用一个 key”含糊带过了。猜测来源：Provider 端 ReactAgent.builder().outputKey(...) 指定的字符串。等下一集联调时验证。
  • Consumer invoke 拿到的 OverAllState，是 Provider 整个工作流执行完的最终态，还是只 Provider 自己那一份？跨节点状态同步如何映射到 A2A 协议的 Task 上？
  • transcript 里讲师顺嘴说了一句”强制转换为 Stream 类型”，但截图里没看到这一行落地。存疑。

4. 跟其他集连接

  • 上承：4-11（A2A 三组件总览）告诉你”为什么需要服务发现”；4-13（Provider 端 ReactAgent）写完了”被发现的那个 Agent”。这一集是把 4-11 的概念图落成 Consumer 端的代码。
  • 下启：下一集应该会三方联调——同时启动 Nacos / Provider / Consumer，跑通完整链路，并且会把”那个 key 到底是什么”补上。OverAllState 的完整展开要等到工作流（DAG Graph）章节。
  • 横向：跟 4-10 SAA 1.1 整合 MCP 是同层封装——都是 SAA 1.1 对一个外部协议的包装；差异点是 A2A 多了一个”注册中心”层（Nacos），MCP 直接走 Streamable HTTP/SSE。跟 3-10 多 Agent 跨部门协作 A2A 协议是”协议描述层 vs Spring 框架封装层”的关系：3-10 讲的是 Agent Card / Task 这些协议概念，4-14 讲的是 Spring 里怎么写代码。

5. 知识地图

依赖跟 Provider 完全相同（agent-framework + a2a-nacos starter），只是代码逻辑和端口不同。

6. 自测题

  1. Consumer 端为什么不用 ReactAgent 而用 A2aRemoteAgent？两者职责差异是什么？
  2. A2aRemoteAgent.builder().name("AgentProvider") 这个字符串的语义是什么？写成别的会怎样？
  3. application.yml 里 discovery.enabled: true 如果忘开会发生什么？
  4. invoke() 的返回值类型是什么？为什么不是 String？解包要写哪几步？
  5. OverAllState 为什么是 KV 结构？这个设计跟它”在工作流节点间流动”有什么关系？
