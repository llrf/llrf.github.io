12-04 Skills实现Agent工具的渐进式加载

发表于2026-05-19|更新于2026-05-21|Agent学习第12章 专属SubAgent, 处理旅游规划专业Skills
|浏览量:

1. 一句话定位

把已有的 Toolkit 塞进 SkillBox，让本地工具也能蹭上 Skill 的「用时再加载」机制——不是加载机制本身变了，而是工具借住进了 Skill 的房子。

2. 主体

为什么要把工具「挂进 Skill」

⏱ 00:00–01:45 · 上下文窗口与渐进披露动机，纯讲

上下文窗口有限。如果一上来就把所有工具的脚本、资源、说明全塞进去，模型还没开始干活就先被噪音淹了。Skill 体系已经解决过一次这个问题——SKILL.md 平时只露名字和一句话简介，真要用时再 cat 进来。本集做的事情就是：让 Toolkit 也享受这套待遇。

注意一个反直觉点：「渐进式加载」≠「Agent 不知道有这工具」。工具名 + @Tool(description=...) 仍然要进上下文，否则模型根本不会去选它。延迟到调用时才加载的，是工具内部的资源、脚本、真实执行体。这点和 Skill 一模一样——Agent 始终知道「我有这把锤子」，但锤子的图纸和材料清单等敲钉子那一刻再读。

三步代码骨架

📺 01:45–02:35 · IDE 中演示 Toolkit + SkillBox 三步代码

第 2 步的构造器参数容易让人误以为「工具已经注册了」——并没有。它只是开了一条通道，告诉 SkillBox 「以后我挂进来的工具都跟这个 toolkit 关联」。真正的注册在第 3 步。

SkillBox 上的两个注册入口

📺 02:35–03:45 · 代码现场演示 registerSkill vs registration().tool

入口 用途
skillBox.registerSkill(skill) 注册一个 AgentSkill（SKILL.md + 资源 + 脚本那一坨）
skillBox.registration().tool(new XX()) 注册一个工具，让它走渐进披露通道

名字相近，别看花眼。讲师口语里常把 registerSkill 念成「wegift」，听音轨时按上下文还原。

工具本体没变

📺 03:45–04:35 · IDE 中新建 tool 包并写 Calculate 工具类

跟之前章节写工具的姿势完全一致。@Tool 的 description 就是「Agent 启动时能看到的那部分」，写好它直接决定模型选不选你。

Agent 这一侧——双挂载铁律

📺 04:35–05:28 · IDE 中演示 builder 同时挂 toolkit 与 skillBox

这是最容易翻车的地方。Toolkit 要传两遍：

如果只把工具挂进 SkillBox 而忘了 .toolkit(toolkit)，Agent 上下文里压根没工具名，渐进披露通道再漂亮也是死路。讲师讲到这里的原话是「这个也是必须的」——记住这个铁律，比记代码更重要。

加工增量：两次「注册」职责拆开看

⏱ 05:28–05:30 · 解读层，纯讲

这点讲师讲得含糊，我自己琢磨出来的解读——

代码里看起来工具被注册了两次（skillBox.registration().tool(...) 一次，builder.toolkit(toolkit) 一次），实际上是两件不同的事：

  • 前者：把工具「挂进 Skill 体系」，让它享受渐进披露
  • 后者：把 Toolkit「告诉 Agent」，让模型知道这工具存在

职责完全不同，缺一不可。理解了这个拆分，整集就通了。

3. 没 get 的点

  • skillBox.registration().tool(new Calculate()) 传的是实例。那如果工具想用 Spring 管理（无状态 bean 共享一份），能不能传 Calculate.class？11-x 里见过 toolkit.registerTool(Calculate.class) 的写法，两种到底有什么差别？
  • 渐进披露的「触发时机」到底卡在 ReAct 哪一步？是 think 阶段选定工具后、action 执行前才把脚本读进来？还是更早？得翻 SkillBox 的 SkillRegistration 源码确认。
  • 多个 SkillBox 能并存吗？SubAgent 各自挂一个的话，主 Agent 看不看得到子 SkillBox 里的工具？这关系到「分层 Agent」能不能用这套机制做隔离。
  • 同一段代码里露脸的 JarSkillRepositoryAdapter（以文件形式读取 SKILL.md）和本集工具挂载没直接关系，但同框出现，下一集应该会展开。

4. 跟其他集连接

  • 上承 10-3 / 10-4：那两集只讲了「Skills 渐进式加载」的概念和目录结构，是抽象层；本集把抽象落到「工具」这个具体对象上。
  • 上承 11-6《路线制定专员 Agent 挂载百度地图 MCP》：那一集教了 Toolkit + registerMcpClient 的标准挂载手法；本集是它的升级版——同样的 Toolkit，多挂进一个 SkillBox。
  • 横向 3-8《Agent_Skills+MCP》：那集讲过「MCP 推全量 / Skills 拉按需」的分工。本集相当于「把 Skills 这套 pull 模式套到本地工具上」，让本地工具也按需。
  • 下启：「Skill 内部资源/脚本如何真正延迟加载」「多工具 + 多 Skill 混挂时的命名空间冲突」「SubAgent 各自挂 SkillBox 的隔离效果」都是本集留下的尾巴。

5. 知识地图

6. 自测题（5 卡）

  1. new SkillBox(toolkit) 这一行是否就完成了工具的注册？为什么？
  2. SkillBox 上注册「技能」和注册「工具」分别用哪两个方法？
  3. 如果代码里 skillBox.registration().tool(new Calculate()) 写了，但 builder.toolkit(toolkit) 忘了，Agent 会怎么样？
  4. 「渐进式加载」延迟加载的是工具的什么部分？什么部分仍然要先进上下文？
  5. 为什么不能把所有工具一股脑全塞给 Agent？这跟本集要解决的问题是什么关系？

7. 关键词表

术语 含义
渐进式加载 先告诉 Agent「有什么」，等真用到再加载「是什么/怎么用」
SkillBox 技能容器，构造器接收 Toolkit；同时是技能注册中心和工具渐进披露入口
Toolkit 工具集合对象，独立于 SkillBox 存在，必须单独传给 ReActAgent.Builder
registration().tool() SkillBox 上把工具挂进渐进披露通道的链式入口
registerSkill() SkillBox 上注册 AgentSkill 的方法，与工具注册并列
@Tool 工具方法的元数据注解，description 是 Agent 启动时就能看到的那部分
双挂载铁律 工具要 skillBox.registration().tool(...) + builder.toolkit(toolkit)，缺一不可
