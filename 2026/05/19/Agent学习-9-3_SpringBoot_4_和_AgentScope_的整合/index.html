9-03 SpringBoot 4 和 AgentScope 的整合

发表于2026-05-19|更新于2026-05-21|Agent学习第09章 Docker 部署分布式 Agent 搞定旅游规划
|浏览量:

1. 一句话定位

你要为后面的”主管 + 路线 + 行程”分布式协作铺地基——把 AgentScope 升到 1.0.8、用 SpringBoot 4 兜住、拆出 4 个 Maven 模块、再用一个 HelloAgent 跑通”你好”。这一集没有业务代码，全是 pom.xml。

2. 主体

2.1 三个版本一眼定栈

📺 00:00–00:33 · 在 IDE 里看 properties 里的三版本变量

打开根 pom 你会看到三个 properties：

  • spring-boot.version=4.0.2
  • AgentScope.version=1.0.8
  • logback.version=1.5.25

整个仓库后面所有子模块的版本号都从这里取，不在子模块里写死。这是 4-1 / 4-9 用过的套路在 AgentScope 阵营里第二次复用。

2.2 BOM 三件套，不是 parent 继承

📺 02:02–02:35 · pom 里写 dependencyManagement + import 的 BOM 块

讲师嘴上说”采用 Parent”，但屏幕上其实是 BOM 写法：

加工增量：讲师在这里口误把 BOM 叫成了 Parent。两者效果不一样——spring-boot-starter-parent 会强行接管你整个项目的 parent，而 dependencyManagement + import 只接管版本号，根 pom 保持干净，可以挂任何 parent（包括你自己公司的）。课里用的是后者，后续讲到 spring-boot-maven-plugin 打包时可能要补 plugin 配置回来。

2.3 整合胶水：就一个 starter

📺 00:33–02:02 · pom 里加 agentscope-spring-boot-starter 一行

AgentScope 和 SpringBoot 的整合就靠这一行：

不像 SAA 那边要分 chat / mcp / a2a / graph 几个 starter——AgentScope 这版还是 all-in-one：好处是门槛低，坏处是你想只用某一块功能也砍不掉。

2.4 1.0.7 的 Jackson 包袱，1.0.8 自己消化了

⏱ 03:36–03:55 · 解释 1.0.8 不再需要 Jackson exclusion

6-9 / 6-10 / 6-15 那条 AgentScope 三件套老坑——<exclusion> 排除自带 jackson + 重新引 jackson-databind——在 1.0.8 里不需要再做。讲师亲口宣判 EOL：

“我们这里并没有把 JSON 依赖去掉……可能修复了这个错误，反正没有报错就是了。”

那段 <exclusion> 模板你以后可以删，但教学注释最好留一行警示读者”这里曾经有过坑”。

2.5 SLF4J 还是要补一个实现

📺 02:53–03:07 · pom 里补 logback-classic 依赖

这是 AgentScope / SAA 系列通病：starter 里只给了 SLF4J 接口，不绑死实现，你不补一个 logback-classic 控制台就一片空白。

2.6 4 个 Maven 模块就是 5-1~5-5 那张角色图

📺 03:07–03:36 · IDE 里创建四个子模块

  • manager_agent：主管 Agent，对应 5-5 里那个派单的
  • routeMaking_agent：路线制定 Agent
  • tripPlanner_agent：行程规划 Agent
  • commons：公共模块（DTO / 配置 / 工具类共享）

加工增量：”分布式”这个词在这集还是同 JVM 多模块——只是把代码边界先切开，留出”以后转 A2A 跨进程”的口子。真要跨进程估计要绕回 4-11~4-16 的 Provider / Registry / Consumer 三件套，但 AgentScope 阵营可能用自己的 A2A 实现而非 SAA + Nacos。

2.7 HelloAgent 跑通就算过关

📺 03:55–05:58 · 写并运行 HelloAgent 看流式输出

最后写一个最简的验证类：拿环境变量里的 DashScope API Key、ReActAgent.builder() + DashScopeChatModel 组个 Agent、stream 发一个”你好”、Flux.doOnNext 打印。控制台流式吐出”你好！有什么我可以帮你的吗？” + exit code 0，就证明 1.0.8 + SpringBoot 4 + 不排除 Jackson 三件事可以同时成立。

3. 没 get 的点

  • agentscope-spring-boot-starter 内部到底自动装配了哪些 Bean？HelloAgent 还是手写 ReActAgent.builder() 的，没看到 @Autowired 注入——这个 starter 可能只做依赖聚合不做自动装配，要等后面看 manager_agent 真实代码才能确认。
  • 三个模块为什么用下划线（manager_agent）而不是中划线（Maven artifactId 习惯）？目录名两者都合法，要看 pom 的 artifactId 行才能定。
  • API Key 是放 application.yml 还是 IDEA Run Configuration 的环境变量？讲师只说”放到 Application 的环境变量里”，没明确哪一种。
  • 没用 spring-boot-starter-parent 意味着失去 spring-boot-maven-plugin 自动 finalName 这些便利，后面打包会怎么补？

4. 跟其他集连接

  • 上承 6-9 / 6-10 / 6-15：1.0.7 时代的 AgentScope ReActAgent 三连击和 Jackson 排除三件套——这集把 Jackson 那部分判了死刑。
  • 上承 5-1~5-5：那边画的”主管 + 路线 + 行程”角色图，这集变成 Maven 模块结构。
  • 上承 4-1 / 4-9：BOM 三件套（dependencyManagement + type=pom + scope=import），第二次套用，这次对象是 spring-boot-dependencies。
  • 平行对照 6-2：SpringBoot 整合 SAA 是同一件事在另一阵营的版本。两个 starter 命名风格不同（SAA：spring-ai-alibaba-starter-dashscope；AgentScope：agentscope-spring-boot-starter），思路一致。
  • 平行对照 6-7 / 6-8：SAA 1.1 的 ReactAgent.builder().subAgents(...) 是单进程组装，本集是 Maven 多模块为跨进程留口子——同目标不同方案。
  • 下启 9-x：后续会逐个填三个 Agent 模块的真实代码，预计先讲主管 Agent 的派单逻辑。
  • 下启 A2A：本集只搭模块边界，真正跨进程的 A2A 要等到后面才接。

6. 自测题（5 卡）

  1. 为什么这一集不用再写 <exclusion> 排除 AgentScope 自带的 Jackson？
  2. 根 pom 里用的是 spring-boot-starter-parent 继承，还是 dependencyManagement + import BOM？两者差在哪？
  3. AgentScope 整合 SpringBoot 一共需要引几个 starter？和 SAA 那边的写法有什么不同？
  4. 为什么明明引了 SLF4J 还要再补一个 logback-classic？不补会怎样？
  5. 四个 Maven 模块各自对应 5-1~5-5 里的哪个角色？为什么要单拎一个 commons 出来？

7. 关键词表

术语 一句话
AgentScope 1.0.8 本课主版本，相对 1.0.7 修复了自身 Jackson 冲突
agentscope-spring-boot-starter AgentScope ↔ SpringBoot 的唯一整合依赖，all-in-one
SpringBoot 4.0.2 BOM 模式 根 pom 用 dependencyManagement + type=pom + scope=import，不是 parent 继承
三版本变量 spring-boot.version / AgentScope.version / logback.version，properties 统一控制
Maven 多模块骨架 manager_agent / routeMaking_agent / tripPlanner_agent / commons 四模块
Jackson 冲突历史 1.0.7 必须 exclusion + 重引 jackson-databind，1.0.8 已自愈
logback-classic SLF4J 必配实现，不引就没日志
