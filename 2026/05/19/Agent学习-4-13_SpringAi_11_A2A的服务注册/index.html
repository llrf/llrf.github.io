SpringAi 1.1 A2A的服务注册

§1 一句话定位

Provider 端把工具 + ReactAgent + Nacos 三件套拼装起来，让 Agent 自己上注册中心。

§2 主体讲解

大图：Provider 内部其实是两半 + 一层胶水

⏱ 00:00–00:23 · 开场介绍 Provider 模块的两包结构

A2A Provider 这个模块拆开来看，包里只有两个东西：agents/ 和 tools/。这不是巧合——这正好对应你要写的两半代码：

  • 工具侧：tools/WeatherTool.java，一个普普通通的 Java 类，方法上贴 @Tool，类上贴 @Component。
  • Agent 侧：agents/AgentProviderConfig.java，一个 @Configuration，里面 @Bean 方法返回 ReactAgent 实例。

然后最外面一层胶水是 application.yml，把这个 ReactAgent Bean 推到 Nacos 上。

⏱ 00:00

工具侧：为什么这里不是 @McpTool

📺 00:25–02:42 · 现场创建 WeatherTool 并贴 @Tool/@Component 注解

上一集（4-12）你刚学完 @McpTool 这个 1.1 专属注解。然后这一集打开工具类，你会发现注解又变回了 @Tool：

我一开始的反应是：”不是说好 1.1 用 @McpTool 吗？” —— 这里就是 MCP 工具体系和 Agent 工具体系是两套不同注解的分水岭（取舍出现在 §2.工具侧）：

  • @McpTool（来自 mcp-annotations）：暴露成 MCP Server 给外部 MCP Client 用。
  • @Tool（来自 spring-ai-tool）：只给本进程内的 Agent 用，不暴露 MCP 端点。

这一集你只是要把工具喂给自己家的 ReactAgent，不需要让外面的 MCP Client 调，所以用 @Tool 就够了。

⏱ 01:22

还有个超容易忘的细节：@Tool 的 description 必须写。不写的话，LLM 看不懂这工具是干嘛的，规划阶段就会直接跳过它。这跟 4-5/4-6 教 MCP 工具时的规矩一样。

⏱ 02:30

Agent 侧：ReactAgent 不是前端那个 React

📺 02:42–09:18 · IDE 现场用 ReactAgent.builder 链式调用 + 报错演示

讲师在视频里口误一直念 “Weat Agent”，但你点进去一看类名其实是 ReactAgent：

Re-Act = Reason + Act，意思是这个 Agent 自带”先思考再行动”的循环。它的五大能力（自主规划 / 自主决策 / 执行工具 / 记忆 / 感知环境）就是 SAA 1.1 整个课程的”重点的重点”。

⏱ 05:24

创建它的咒语是固定的 Builder：

三个必填：name / model / tool。这里有个 IDE 直接给你报错的小坑（加工增量在 §2.Agent 侧）：视频里讲师在 .model("") 里传了个空字符串，IDE 立刻飘红 “cannot apply String to ChatModel”——说明 .model() 收的是 ChatModel 类型的 Bean，不是 API key 字符串。这一集没补全，下一集应该会补 dashscope ChatModel 的注入。

⏱ 08:06

注意工具是怎么进来的：

  1. 工具类有 @Component → Spring 容器里有一个 WeatherTool Bean。
  2. agentProvider 方法签名写 (WeatherTool weatherTool) → Spring 自动按类型注入。
  3. .tool(weatherTool) 把这个 Bean 塞进 Builder。

这条路径就是”装配胶水”的本体——你不需要在 Agent 里 new 工具，也不用手写 applicationContext.getBean(...)。

⏱ 09:09

装配胶水：yml 三件套把 Agent 推上 Nacos

📺 10:01–14:18 · application.yml 现场写 dashscope + nacos 三件套

到这一步，你只是创建了一个 ReactAgent Bean，它还躺在自己进程里。”A2A 服务注册”真正发生在 yml 这三行：

  • 第 1 行：dashscope 的 API Key，给 ChatModel 用。
  • 第 2 行：Nacos 3.1 注册中心地址（本地后面会启）。
  • 第 3 行：enabled: true 是触发器——只要打开，starter 就会扫描所有 ReactAgent 类型的 Bean，把它们写进 Nacos。

你不需要写 @Service 或者手动调 Nacos SDK，整个注册过程对你来说就是一行配置。

pom 里的 1.0 → 1.1 坑

⏱ 12:31–13:09 · 对比 1.0 / 1.1 BOM 管理范围差异，纯讲

1.1 BOM 管的是 spring-ai-alibaba-agent-framework 和 spring-ai-alibaba-nacos 这俩 A2A 相关依赖。但是 spring-ai-alibaba-starter-dashscope——它从 1.0 的 BOM 里挪出去了，1.1 里必须显式写版本号。这个跟 4-9 学到的”1.1 BOM 范围更窄”一脉相承。

§3 我一开始没 get 的点

  1. @McpTool 和 @Tool 是两套体系，不是新旧版本关系。上一集 1.1 用 @McpTool，这一集 1.1 又用 @Tool，看似矛盾——其实是看你这个工具暴露给谁：暴露给外部 MCP Client 用 @McpTool，只给本地 Agent 用 @Tool。

  2. 类名是 ReactAgent 不是 WeatAgent。讲师的口音让”React”听起来像”Weat”，但 Re-Act = Reason + Act，跟前端 React 也没关系。

  3. .model() 不收字符串。这里要传 ChatModel 实例，不是 API key 字符串。视频里那一帧 IDE 报错就是证据。

  4. A2A 注册不需要写代码。我以为还得加 @Service 或者 @EnableA2A 之类的注解——其实就一行 a2a.nacos.enabled=true，starter 帮你扫 Bean 推 Nacos。

§4 跟其他集的连接

上承

  • 4-9 给了 1.1 的 BOM 与 spring-ai-alibaba-agent-framework 依赖；本集是它的实操首秀。
  • 4-11 给了 A2A 三组件（Provider/Registry/Consumer）+ Nacos 3.1 + AgentCard 的概念图；本集落地 Provider。
  • 4-5 / 4-6 教过 @Tool 注解和 ToolCallbackProvider；本集复用 @Tool 但换了消费方（Agent 而非 MCP Server）。

下启

  • 下一集大概率讲 A2A Consumer 侧（服务发现 + 远程调用 Provider Agent），以及本地启 Nacos 3.1 跑通端到端。
  • 再往后会专门展开 ReactAgent 的五大能力（规划/决策/工具/记忆/感知），毕竟讲师明确说”这是重点的重点”。
  • .model() 怎么注入 dashscope ChatModel，应该会在 Consumer 或 ReactAgent 专章补上。

横向

  • 跟 MCP 暴露方式的对比：MCP 暴露的是”工具”（HTTP endpoint），A2A 暴露的是”Agent”（Nacos 服务实例）。
  • 跟 4-12 @McpTool 的对比：两者都是”定义即注册”的哲学，区别是注册介质不同——MCP 走 server scanner，A2A 走 Nacos client。
  • 跟 3-9/3-10 多 Agent 协作的呼应：A2A 协议就是给”主管 Agent + 专科 Agent”跨进程协作铺路。

§7 关键词表

术语 一句话解释
ReactAgent SAA 1.1 核心 Agent 实现，Re-Act = Reason + Act，具备规划/决策/工具/记忆/感知五能力
ReactAgent.builder() 工厂方法，必填 name / model / tool
@Tool spring-ai-tool 包的注解，把方法标记为 Agent 可用工具，description 必填
@Component 让工具类被 Spring 扫到，是后续按类型注入的前提
@Configuration + @Bean 把 ReactAgent 实例托管给 Spring，触发 a2a starter 的自动注册逻辑
spring-ai-alibaba-nacos 专为 A2A 设计的 Nacos 注册 starter，受 1.1 BOM 管理，无需写版本号
dashscope starter 1.1 BOM 不再管理它，必须显式写版本号，与 1.0 不同
application.yml 三件套 api-key / nacos.server-addr / a2a.nacos.enabled=true，最后一行是注册开关
工具注入路径 @Component WeatherTool → @Bean 方法参数注入 → .tool(weatherTool) 挂到 Agent
