4-01 以bom方式导入SpringAi Alibaba依赖

发表于2026-05-19|更新于2026-05-21|Agent学习第04章 SpringAi 1.1 实现 MCP+A2A
|浏览量:

§1 一句话定位

学会用一个 BOM 依赖锁住 Spring AI Alibaba 的版本，给后面所有 agent 代码起个干净的工程地基。

§2 主体讲解

BOM 是个版本字典，不是代码包

⏱ 09:25–10:08 · 解释 BOM 起到版本的统一管理，纯讲

整集真正的”技术点”压在一个容易被忽略的细节上：你往 pom.xml 里加了 spring-ai-alibaba-bom，然后点 Maven 刷新，结果 Maven 窗口里一个 SAA 的 jar 都没多——只有 JDK。

第一次看到这个现象，你大概率会怀疑是不是没刷新成功。其实没问题，BOM 本来就这样：它是 Maven 的”Bill of Materials”——只声明”一组 artifact 各自该用什么版本”，不真的把代码拉进来。

想让代码进来，得在 <dependencies> 里再写一个真正的 starter，比如 spring-ai-alibaba-starter-dashscope。注意这个 starter 不写 <version>——它自动从 BOM 里查。

⏱ 08:53

三件套缺一不可，写错位置就退化

⏱ 09:56–10:15 · 强调 BOM 必须放进 dependencyManagement，纯讲

BOM 要起作用，得满足三个条件同时成立：

如果你把这段直接塞进 <dependencies>（不套 <dependencyManagement>），Maven 会把它当一个普通 pom 类型依赖处理，版本统一管理直接失效——后面那些不带 version 的 starter 会找不到版本号而报错。

<type>pom</type> + <scope>import</scope> 这俩是固定搭配，专门用来”把另一个 pom 文件里的 dependencyManagement 段拷过来用”。这是 Maven 通用机制，不是 SAA 特有的。

把版本号抽到 <properties> 里做成 ${spring-ai-alibaba.version} 变量，是为了未来升级 SAA 时只改一处。

⏱ 12:07

版本下限是 1.0.0-M6，再低会埋雷

⏱ 07:26–08:30 · 强调最低版本必须 ≥ M6，纯讲

挑版本时只有一条硬约束：必须 ≥ 1.0.0-M6。M6 是 MCP 集成的起点版本，更早的 M3、M5 都没有 MCP 模块。本课程后面会做 MCP，挑早期版本就等于给后面几集挖坑。

截至课程录制（2025-06），最新是 1.0.0.2，直接用它就行。这里有个命名上的小怪味——1.0.0.2 不太像常规 GA 版本号（一般是 1.0.2 或 1.0.0-RELEASE），但它确实就是 1.0 GA 之后的小版本迭代。这点不展开，因为对”导入依赖”来说不影响。

⏱ 07:35

为什么是 SAA 而不是 SpringAI

⏱ 02:32–03:40 · SAA 是 SpringAI 之上的 agent 框架，纯讲

最后回头补一刀选型背景。这部分按时间顺序原本在开头，但放到这里讲反而更顺——你得先知道”BOM 锁的是什么版本”，再问”为啥要锁这个东西的版本”。

两者是分层关系，不是替代关系：

层级 谁 关心什么
底层原子能力 SpringAI ChatModel、Prompt、RAG、Memory、Tool、MCP
上层 agent 框架 Spring AI Alibaba Graph 编排、多 Agent、百炼集成、JManus

选 SAA 的真正理由是它提供的五大智能体能力：① Graph 工作流编排 ② 多 Agent 协作场景适配 ③ 阿里云智能体应用平台集成 ④ RAG 知识库方案 ⑤ 分布式 MCP 方案。本课程的目标就是开发 agent，所以走 SAA 比走 SpringAI 直接，少自己造一层封装。

“更好集成国内模型（千问 / DeepSeek）”和”深度集成百炼”是顺带的好处，不是核心理由。

⏱ 05:49

§3 我一开始没 get 的点

  1. 如果你以为引了 -bom 就拿到 SAA 能力，那你刷新 Maven 后会看到一个空的依赖树，得到一个”我是不是配错了”的错误结论。实际上 BOM 一行业务代码都不带进来——它只是”版本字典”。要拿能力，得再引 starter。

  2. 如果你把 BOM 直接写在 <dependencies> 里（漏了外层 <dependencyManagement>），后面那些不写 version 的 starter 会报”无法解析版本”。Maven 不会提示你 BOM 写错了位置，只会抱怨下游 starter。

  3. 如果你随手挑了 1.0.0-M3 这种早期 milestone，前几节代码能跑、后面做 MCP 那一集会直接卡住——没有 MCP 模块。这个雷在导入依赖的当下完全感知不到，等你回来排查时已经写了好几节代码。

  4. 如果你以为 SAA 是 SpringAI 的”中文版/汉化版”，那你会困惑”那为什么不直接学 SpringAI”。实际上 SAA 在 SpringAI 之上多了一整层 agent 抽象（Graph、多 Agent、JManus），是”做 agent 的人”的工具，不是”做翻译”的产物。

§6 自测题

Q1（概念回忆） Spring AI Alibaba 和 SpringAI 是什么关系？为什么本课程用前者？
A1：SpringAI 是底层 AI 应用框架（提供 ChatModel/Prompt/RAG/Tool/MCP 等原子能力），SAA 是构建在 SpringAI 之上的 agent 开发框架（提供 Graph 编排、多 Agent、百炼集成、JManus 等）。本课程目标是开发 agent，所以走 SAA 比直接用 SpringAI 少一层封装。详见 §2”为什么是 SAA”。

Q2（概念辨析） <dependencyManagement> 和 <dependencies> 这两个标签里都能放 dependency，区别是什么？为什么 BOM 必须放前者？
A2：<dependencies> 是”实际依赖”，列在里面的 jar 会被拉进 classpath；<dependencyManagement> 是”版本声明区”，只声明版本号不引代码。BOM 的本质是”用别人的 pom 当版本字典”，依赖的是它的 dependencyManagement 段，所以必须 import 进自己的 dependencyManagement 才生效。详见 §2”三件套缺一不可”。

Q3（反直觉陷阱） 你引入了 spring-ai-alibaba-bom，刷新 Maven 后 Dependencies 列表没有任何 SAA 相关 jar，是配置出错了吗？
A3：没出错，这是 BOM 的正常表现。BOM 本身不引代码，只声明版本号。要真正引入 SAA 类，需要在 <dependencies> 里再加 starter（如 spring-ai-alibaba-starter-dashscope），那个 starter 不写 version，会自动从 BOM 取。详见 §3 第 1 条 / 图 f122。

Q4（跨集连接） 本集为什么强调”版本必须 ≥ 1.0.0-M6“？这条约束对应后续哪一类内容？
A4：M6 是 SAA 集成 MCP 模块的起点版本。本课程第 3 章已铺垫过 MCP 概念（3-4 ~ 3-6），第 4 章后续必然有一集用 SAA 代码方式做 MCP 集成（呼应 3-6 的 JManus 图形化配 MCP）。挑早期版本会让 MCP 那一集无 jar 可用。详见 §2”版本下限”+ §4 下启 / 横向。

Q5（应用 / 推广） 你接手另一个 Spring Boot 项目，同时要用 Spring Cloud Alibaba 的若干组件（nacos / sentinel / seata），版本号写得到处都是、升级一次要改十几行。能不能套用本集结论？
A5：能，而且就该套。Spring Cloud Alibaba 也发布了 spring-cloud-alibaba-dependencies BOM（命名习惯不同但角色一样）。把它 import 进 <dependencyManagement>、用 <type>pom><scope>import</scope>，下游所有 nacos/sentinel/seata starter 都可以省掉 version 行。所有 Spring 系生态（Spring Boot 自己、Spring Cloud、Spring AI、SAA）几乎都走这个模式。BOM 是 Maven 通用机制，结论可直接推广。

§7 关键词表

关键词 一句话解释
Spring AI Alibaba (SAA) 阿里基于 SpringAI 做的 agent 开发框架，倾向 AI Agent
SpringAI vs SAA 分层 SpringAI 是原子能力层，SAA 是上层 agent 框架，二者非替代而是叠层
BOM (Bill of Materials) Maven 的”版本清单”依赖，artifactId 带 -bom，本身不引代码只声明版本
dependencyManagement + type=pom + scope=import 三件套 BOM 生效的固定搭配，缺一不可
1.0.0-M6 红线 SAA 集成 MCP 的最低版本，本课程用 1.0.0.2
spring-ai-alibaba.version 版本变量 放在 <properties> 内的版本号变量，方便统一升级
百炼 / dashscope starter 阿里云大模型平台，对应 starter 是 spring-ai-alibaba-starter-dashscope
SAA 五大智能体能力 Graph 编排 / 多 Agent / 阿里云智能体平台 / RAG / 分布式 MCP
