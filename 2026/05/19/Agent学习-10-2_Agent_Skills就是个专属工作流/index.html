10-02 Agent Skills就是个专属工作流

发表于2026-05-19|更新于2026-05-21|Agent学习第10章 Skills 让 Agent 按照专业流程工作
|浏览量:

1. 一句话定位

Skills 不是”会用工具”，是”一整套写死的 SOP + 每步该用哪个工具”的领域知识包；它反过来指挥 MCP 只吐你需要的那一两个工具，跟 SubAgent 区别在于 Skills 可移植可复用、SubAgent 用完即弃。

2. 主体

2.1 先把”为啥还要 Skills”这个疑问钉死

⏱ 00:00–03:20 · 回顾 MCP 痛点引出 Skills 必要性

听完前几集你大概率会冒出一个问题：有 MCP 就能调工具了，Skills 不就是多一层吗？ 这正是本集要回应的。

回顾纯 MCP 路径下你会踩的坑（见 f010）：

  • MCP 一股脑把所有工具描述塞进上下文 → 上下文先吃掉一大块。
  • Agent 自己不知道该用哪个 → 反复问 LLM”我该用哪个” → 烧 token、多轮往返。

第一层补丁（3-7 那集讲过）是：给 Agent 灌点领域知识，让它自己挑工具、让 MCP 按需返回。本集要在这层补丁上再加码——Skills 不止是”挑工具的脑子”，它装的是整套 SOP。

2.2 SOP 才是 Skills 的真身

⏱ 03:20–05:00 · 产品经理 5 步 SOP 举例拆解

加工增量：讲师在这里转折得很快，原话基本是”agent skills 它不只是调用工具，它是一个包含了一整套 SOP 流程”。你要把这句当作整集的 anchor——后面所有展开都是在解释这个”SOP”两个字。

讲师用产品经理画原型图的例子（f011/f012）拆这套 SOP：

  1. 跟老板对齐需求；
  2. 上网找竞品资料、找竞品界面；
  3. 调工具画线框（这一步选 Axure 还是墨刀，是 Skills 自己定的，不是甩给 LLM 现猜的）；
  4. 跟老板二次确认、定稿；
  5. 把界面/功能细化到数值（图标尺寸、页面功能列表）。

这 5 步是写死的顺序，每一步带工具选择策略。所以一句话：

Skills = 流程序列（怎么干）+ 每步用哪个工具的元知识（用什么干）。

MCP 只解决”工具存在”这件事，“怎么用、第几步用”是 Skills 才有的领域知识。

2.3 Skills 反向控制 MCP（容易被漏掉的点）

⏱ 05:20–05:34 · Skills 反向告诉 MCP 只回传需要的工具

加工增量：这是本集隐含的反直觉点，原话没明说但暗含。

传统脑图里 MCP 是工具的”分发员”，把工具表推给 Agent。Skills 进来以后方向倒过来了——Agent 因为知道流程，反过来对 MCP 说”这一步我只要墨刀和 Axure，其他别返回”（讲师 320-334s 的原话）。

收益就三件：

  • 上下文不爆：MCP 不再一次性推所有工具描述。
  • LLM 来回少：Agent 自己知道下一步用啥，不用反复请示。
  • Token 省：上面两件直接折算到费用上。

2.4 Skills vs SubAgent，差异点是”生命周期”

⏱ 06:29–07:15 · 用岗位说明书 vs 临时工类比拉开差异

f013/f014/f017 三张图把 Skills（左上一堆带”领域 Skills”标签的 Agent）和 SubAgent（右下”单个专业场景 + 独立上下文 + 不会影响主上下文”那一框）并排画在一张画布上。

很多人第一直觉去找”它俩做什么不一样”，但讲师强调的差异是”谁能复用、谁用完就丢”：

维度 Agent Skills SubAgent
类比 岗位说明书 临时工
生命周期 长期存在、可移植 任务完成即释放
复用性 换个人来照样按这份 SOP 干 一次性，不复用
上下文 嵌进主流程 独立上下文，出错不影响主线
并发 n/a（它是知识不是执行体） 多个并行跑专业场景

讲师那句”岗位人员离职了，下一个进来的人员照样按这份 SOP 干”——把”可移植”这点钉得非常死。

2.5 三件套画布全景（f001/f007/f008/f009）

⏱ 00:55–01:10 · 三件套全景图作为整章总锚点

Claude Code 一共提出三个前瞻概念，本集是第三块的深挖：

  • MCP：工具协议（应用落地的那一块）
  • SubAgent：任务隔离（10-1 已讲）
  • Skills：SOP 赋能（本集主角）

这张全景图（f001）出现在开场和”提出第三个前瞻概念”的转场处，是整章的总锚点，后面 10-3 大概率还会用它做引子。

3. 没 get 的点

  • Skills 在磁盘上长啥样？ 本集只讲概念，没看到 SKILL.md / markdown 模板 / 触发器机制。推测 10-3 会落地，但本集留白。
  • “让 MCP 只返回两个工具”是协议层支持还是 prompt 层过滤？ 讲师说得像 MCP 协议层能做工具过滤，但 3-4 MCP 协议 里没看到这个接口。也可能是 Skills 在 prompt 里直接筛掉了不需要的工具描述。需要回去对协议规范。
  • SOP 是死的线性 5 步，还是允许 ReAct 式分支？ 举例里”找竞品时发现没竞品”这种异常分支怎么挂进 Skills 没说。
  • Skills 跟 5-2/5-3/5-4 的”角色定义 + 能力清单”是不是一回事？ 还有 4-15 AgentCard.skills——名字撞车但层级不同（一个对外广播、一个内部 SOP）。等代码集对照。

4. 跟其他集连接

上承

  • 3-7 具有专业知识的 Agent Skills —— 那集只把 Skills 定义为”领域知识 + 工具按需加载”，本集升级成”整套 SOP 流程”。
  • 3-8 工具调用最强组合：Agent Skills + MCP —— “渐进式/元数据加载”就是本集”MCP 只返回墨刀和 Axure”的底层机制。
  • 10-1（同章节前一集，SubAgent）—— 本集开头当对照引子、结尾再做对比表。

下启

  • 10-3 大概率讲 Skills 的文件配置形态（SKILL.md / frontmatter / 触发条件），把 SOP 落到磁盘。
  • 后续可能演示 Skills × SubAgent 联动：主流程按 Skills SOP 走，某一步派 SubAgent 去独立上下文里执行。

横向

  • 3-9 多 Agent 协作 / 3-12 多 Agent 核心执行流程 —— 多 Agent 是横向切（不同专科），Skills 是纵向赋能（同一 Agent 怎么按 SOP 把活干完）。
  • 5-2 路线制定专员 Agent —— 那套”角色定义 + 能力清单”模板就是 Skills 的雏形书面化。
  • 4-15 AgentCard.skills —— 名字一样但语义错位：AgentCard.skills 是”对外广播我会啥”，Claude Code Skills 是”对内描述怎么干”。
