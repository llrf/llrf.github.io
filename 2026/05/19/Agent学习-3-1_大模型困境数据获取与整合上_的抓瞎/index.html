3-1 大模型困境：数据获取与整合上的”抓瞎”

§1 一句话定位

看完这一集，你应该能用一句话回答：”LLM 为什么需要外挂？”

§2 主体讲解

先把 LLM 的”世界”立起来

要看懂这一集后面所有的”反例”，你得先接受一个心智模型：

LLM 没有”现实世界”，它只有一个向量空间。

它学过的每一个概念——林黛玉、星巴克、卢浮宫的某幅名画——在这个空间里都对应一个唯一的点（一个上千维的向量）。它做的所有”思考”，都是在这个空间里做几何运算：找邻居、量距离、走向量加法。

这件事一旦想透，三个看上去很神奇的能力就立刻不神奇了：

  1. 百科全书 —— 红楼梦整本书早被嵌入进去了，林黛玉的”性格特征””结局””出现章节”都是她那个点周围的邻居。问到她，模型不过是在做一次邻域查询。
  2. 猜意图 —— “咖啡馆里来杯星巴克”，”星巴克”这三个字在向量空间里有好几个候选位置（品牌、咖啡馆、饮料），模型借助上下文里的”咖啡馆””来一杯”两个锚点，做概率运算选最近的那个。
  3. 迁就口吻 —— “用广东人语气回答”也是空间里的一个方向向量，把答案沿着这个方向偏移即可。

所以”智能”的本质是：对静态、公开、历史语料的高密度记忆 + 概率推断。注意这三个限定词——静态、公开、历史。这一集后面所有”打脸”，都是在某一个限定词上戳一刀。

第一刀：戳”静态” → 实时数据缺陷

现在你试着问它：”今天深圳气温多少度？”

它一定答不上来。

你可能会先想到一个流行的解释：”因为有 knowledge cutoff，训练数据有截止日期。”——这个回答只对了一半，而且是表层那一半。

更底层的回答是这样的：“今天深圳的气温值”在向量空间里，根本就没有一个唯一的点去指代它。

这个区别很关键，值得停一下：

  • 如果你信”截止日期论”，你会觉得：”那把模型再训练一次、加上今天的数据，问题就解决了。”
  • 如果你信”向量空间论”，你会立刻意识到：下一秒的气温永远不在空间里有点。再训练一次只能解决”昨天的气温”，下一秒它又坏了。这是结构性的，不是数据量的问题。

这就引出第一类系统性失败：实时数据缺位。凡是”当前时刻才存在”的数据——气温、股价、新闻、库存——都属于这一类。

第二刀：戳”公开” → 私人数据缺陷

接着你再问它：”帮我把公司的客户订单整理成季度销售报告。”

同样答不上来。原因走的是同一条路：你公司的订单表从未进过它的训练语料，向量空间里没有一个点指代”你的客户 A 在 Q3 下了多少单”。

这是第二类系统性失败：私人数据缺位。

关键加工：两个缺陷其实是同一个根因

到这里有一个很多人会漏掉的洞察：实时数据缺陷和私人数据缺陷，看起来是两个独立问题，其实是同一个根因的两种表现。

维度 戳的限定词 表现
时间维度 戳”静态” 此刻的数据没在空间里
权属维度 戳”公开” 你的数据没在空间里

根因都是同一句话：任何不在训练语料里、没被嵌入成向量的东西，模型就抓瞎。

把这件事记成一条公式更省脑子：

LLM 能答的范围 = 训练时被向量化过的范围

不是”LLM 无所不知”，而是”LLM 只在它的向量空间内无所不知”。空间外面的世界，对它来说不存在。

一处取舍

到这里我主动不展开两个相关的工程概念：context window 长度限制、tokenizer 的切词偏差。它们也会让模型”答不上来”，但根因不同——前两者是”空间里有点但拿不到/拿不准”，本集的两大缺陷是”空间里压根没点”。混在一起讲会冲淡主线。等到 3-2、3-3 讲解决方案时再回头看这两个，会更清楚它们各自对应的补丁。

这一集的真正意图

走到这里你应该能感觉到：这一集不是在介绍 LLM 多厉害，而是在给 LLM 立一个负面清单——把它办不到的事先摆上台面。

为什么要先摆问题？因为接下来的 3-2、3-3 都是解决方案：Function Calling 让模型去外面调函数拿实时数据；后面如果讲 RAG，就让模型去外面捞私人文档。没有”问题诊断”这一步，”解决方案”就成了无源之水。

所以这一集叫”抓瞎”——它故意先让你确信模型啥都懂，再用两个反例把你打醒，留你一个悬念：”那怎么办？”

§3 我一开始没 get 的点

  1. 如果你把”答不出今天气温”归因为”知识截止日期”，你会得到错的下一步推论——以为”重新训练模型”就能解决。正确推论是：再训练只能让”昨天”被空间收录，”明天”永远收录不了。这是结构性的、再训练救不了的问题。
  2. 如果你把”实时数据”和”私人数据”当成两个并列的缺陷去记，你会得到错的概念地图——以为后面会有两套独立的解决方案。正确视角是：它们是同一根因（向量空间外）的两个投影，所以解决方案的底层套路也只有一种——“既然空间里没点，那我把它从外面捞进来再问”。
  3. 如果你把”林黛玉性格特征”那段当科普听过去，你会错过本集的叙事钩子。那段不是科普，是”先让你信服 → 再打脸”的反例铺垫。意识到这一点，你才会理解为什么本集叫”抓瞎”。
  4. 如果你把”每个概念在向量空间里有唯一一个点”听成一个严谨的工程描述，你会在面试或复述时被打脸。实际上 LLM 是分布式表示，多个 token、多层共同编码一个概念。这是为了讲通而做的教学简化，记住它是教学版本，不是论文版本。

§4 跟其他集的连接

上承

第 2 章已经把 Transformer 架构和向量空间这套底层模型讲清楚了（”咖啡馆里要杯星巴克”那个例子就是从第 2 章带过来的）。本集做的事情很纯粹：复用第 2 章建立的向量空间模型，从中推导出两个必然的缺陷。如果你跳过第 2 章直接来本集，”向量空间里没点所以答不出”这个论证你会觉得突兀；反过来如果你看完第 2 章直接就接受”LLM 无所不能”，本集的两个反例会显得没必要——它正是来矫正这个过度乐观的。

下启

3-2《Function Calling》是本集两大缺陷里实时数据那一刀的解药；3-3《Function Calling 是大模型的跑腿小弟》是它的具体形象化；后面如果讲到 RAG，那是私人数据那一刀的解药。

本集和下一集的衔接逻辑非常清楚：

既然向量空间里没有 → 那让模型去外面调函数拿 → 这就是 Function Calling

所以本集结尾摆出的两个缺陷，本质上是在给 3-2 提问；3-2 才给答案。

横向

本集没明说 RAG，但值得在脑子里横向比一下：

  • Function Calling：解决”动作 / 实时数据”——模型主动调外部函数，把返回值塞进上下文。
  • RAG：解决”超大私人语料”——把外部文档先检索出来，再塞进上下文。

两者形式不同，底层套路其实是同一个：在向量空间静态性这堵墙上凿洞，把外面的东西临时搬进上下文窗口里去推理。本集是这堵墙的”病理报告”，FC 和 RAG 是两种不同的”绕墙路线”。

§5 知识地图

§6 自测题

Q1（概念回忆） 用一句话说出 LLM 能回答某个问题的充要条件是什么？

A：那个概念在 LLM 的向量空间里有一个被训练时嵌入过的点。空间外面的东西它一律答不了。
答案在 §2「先把 LLM 的世界立起来」+ understanding.md 关键概念清单第 1 条。

Q2（概念辨析） “知识截止日期（knowledge cutoff）” 和 “向量空间没有对应点” 这两个解释——它们是不是说同一件事？区别在哪？

A：不是同一件事，向量空间论更底层。知识截止只是”截止那一刻之前的语料被向量化了”这件事的时间侧切片；向量空间论解释了为什么再训练也救不了实时数据——下一秒的气温永远不会成为空间里的一个点。前者是表象，后者是结构性原因。
答案在 §2「第一刀」+ §3 第 1 条。

Q3（反直觉陷阱） 一个新人跟你说：”实时数据问题和私人数据问题是 LLM 的两大独立短板。” 你会怎么纠正他？

A：它们不独立，是同一个根因的两种表现——根因是”训练语料外的东西，向量空间里没有点”。一个戳的是”静态”维度（时间），一个戳的是”公开”维度（权属）。理解了这一点，你就会预期”解决方案的底层套路也只有一种：把外面的数据搬进上下文”——FC 和 RAG 只是两种搬法。
答案在 §2「关键加工」+ §3 第 2 条。

Q4（跨集连接） 本集和 3-2《Function Calling》的因果关系是什么？为什么必须先看本集？

A：本集摆问题（”向量空间外面的数据怎么办？”），3-2 给答案（”让模型调函数从外面拿”）。如果跳过本集直接看 3-2，你会知道 FC 是什么，但不知道为什么需要它——把它当成一个孤立的 API 用法去学，会错过它的设计动机。
答案在 §4「下启」。

Q5（应用 / 推广） 假设你想让 LLM 帮你回答”我刚刚收到的这封邮件，对方语气是友好还是敌意？”——按本集的框架，这个问题它能不能直接答？为什么？需要什么补丁？

A：不能直接答，因为”我刚收到的邮件内容”既不在训练语料里（私人 + 实时），向量空间里没有指代它的点——同时戳了”静态”和”公开”两个维度。补丁是把邮件正文塞进上下文（最朴素的形式就是直接粘贴；工程化的形式就是 RAG/FC 自动检索）。一旦邮件文本进入上下文窗口，模型就能在临时上下文里建立一次性的”语义邻居”，做情感分类。
答案推广自 §2「关键加工」+ §4「横向」。

§7 关键词表

关键词 一句话理解
向量空间 LLM 唯一的运算场所；每个学过的概念在其中是一个点
时效性问题（实时数据缺陷） 当前时刻才产生的数据在空间里没有点，模型答不出
私人数据缺陷 用户/企业内部数据从未进训练语料，空间里没点
“抓瞎” 本集口语术语：模型在空间外问题上无能的形象说法
知识截止 vs 向量空间论 前者是表象（时间侧切片），后者是结构性根因
Prompt → 语义分析 → 返回 本集反复出现的三步框架，是 3-2 给它”插入第四步”的底图
静态语料假设 LLM 智能的隐藏前提：训练语料是静态、公开、历史的
外挂动机 “为什么需要 FC/RAG”——本集留给下一集的钩子

摘要：取舍与加工

  • 取舍出现在 §2「一处取舍」段落：主动不展开 context window 和 tokenizer，因为它们的根因不同（”空间里有点但拿不到” vs “空间里没点”），混讲会冲淡主线。
  • 加工增量在 §2「关键加工」段落 + §5 知识地图：原始素材把”实时”和”私人”作为两条并列缺陷讲；本笔记把它们重写为同一根因的两个投影（”戳静态”和”戳公开”），并配了对照表格，让读者获得”一个公式覆盖两个缺陷”的统一视角。这一层归并在 transcript 和 understanding 里都没成型——understanding 里只是闪过一句”它们是同一根因的两种表现”，没展开成模型；本笔记把它升级为一张可记忆的对照表 + 知识地图节点。
