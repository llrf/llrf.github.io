8-02 多Agent设计思路 冲突协商

发表于2026-05-19|更新于2026-05-21|Agent学习第08章 Jmanus 懂思考、会规划、一步步动手完成任务。
|浏览量:

1. 一句话定位

把上集那张”主管 + 单 Agent 五步循环”的骨架图，往右边再挂两块大模块：角色分配算法（决定主管派单给谁）+ 冲突调解 / 共识形成模块（多 Agent 吵架了怎么收场）。

2. 主体

2.1 先回顾你已经知道的（来自 8-1 / 3-12）

你脑子里已经有这张图（见 frame f001，0:00 那张）：

  • 两个核心流程：主管 Agent 切任务派单 → 各专科 Agent 干活 → 主管整合（5 步骨架）；每个专科 Agent 内部走”规划 → 执行 → 监控 → 反馈 → 整合”的 5 步循环。
  • 两个全局类：Env（全局记忆、参数）和 Action（调工具 / 调 LLM），后者有两个子方法 _think()（规划）和 _act()（执行）。
  • 角色类：RoleSetting（存角色配置）+ RoleContext（存执行过程中的状态、步骤、中间结果）。

这集要在这张图上新加两个模块。先看完整后图（frame f008，8:53）：图右上挂”角色分配算法”，图右下挂”冲突调解模块（三抓手）+ 共识形成模块（WSLL）”，并把这两块进一步抽象成”冲突调解模型 / 多议题协商冲突网络模型”。

2.2 新模块一：角色分工 → 角色分配算法

问你一个问题：主管 Agent 凭什么把任务派给 Agent A 而不是 B？

讲师的回答两步：

  1. 主管必须先知道每个 Agent 的角色（研究分析师 / 技术研究员 / 产品经理）和擅长领域（Excel 工具 / 编程工具 / 原型图工具）；
  2. 然后跑一个角色分配算法——按”任务需求 ↔ 角色能力”做匹配。

这里讲师只给了名字，没给实现。取舍标注：这个名字听起来唬人，但本质就是”能力 - 需求”两侧打分匹配。它到底是 LLM Prompt 投票，还是经典的匈牙利算法 / 拍卖算法之类，本集没说，应该会在后续集展开。先把它当”派单的核心抽象”记下。

2.3 新模块二：协调工作

协调工作拆成两半。

(a) Agent 间通信 —— 这里有个容易踩坑的边界：

场景 通信方式
跨模型（A 跑 GPT，B 跑 Claude） A2A 协议（参见 3-10）
同模型多 Agent 结构化通信：RPC / WebSocket

讲师原话：”A2A 通信协议并不适用于基于同一个语言大模型的智能体。” 这条边界 3-10 那集没明说，本集是给 A2A 划红线的关键补丁。

加工标注：我自己的疑问是——“同模型 Agent 用 RPC/WebSocket”听起来像应用层 socket，但如果多 Agent 在同一个 Java 进程里，真的需要 RPC 吗？还是 in-process 的消息总线就够？讲师没区分”同进程”和”跨进程”两个边界，先打个问号留给后续。

(b) 冲突调解模块 —— 这是本集真正的肉。

2.4 冲突调解模块的”三抓手”

锚定 frame f005-f007（6:00 ~ 6:35），图右下的三个并列方框：多议题协商 / 动态角色转换 / 信用分配。三个抓手必须同时存在，少一个共识就形成不了。

抓手 1 · 多议题协商：冲突不会只发生一个。一次任务可能同时蹦出三五个分歧，调解模块要支持并行调解，不要串行排队等死锁。

抓手 2 · 动态角色转换 —— 反直觉的点：

  • Agent A（研究员）和 Agent B（经理）在某个决策点吵起来；
  • 主管 Agent 临时拉群，把 A、B 拽进调解会场；
  • 在这个群里，A、B 抛开原角色，临时变身为”辩论正方 / 反方”；
  • 角色不是终身制，是场景制。

加工标注：这个设计很像现实公司的”会议室角色”——你平时是研发，但一进季度评审会就变成”汇报人 / 质询人”。讲师用”拉群”这个词非常形象，记住这个比喻就抓住了。

抓手 3 · 信用分配：每个 Agent 有个历史信用分。冲突无法靠辩论收敛时，按信用分裁决——讲师用”老师傅经验丰富” 类比，信用高 = 大概率方案靠谱。待查：信用分谁来打？怎么累计 / 衰减？讲师没说，先留白。

2.5 共识形成模块 = WSLL 算法

三抓手后面必接一个共识形成模块，对应核心算法 WSLL。

讲师只口播了”WSLL”四个字母，没展开含义。待查：这是哪几个词的缩写？大概率是某篇多智能体共识论文里的算法名，需要回头查。先把”WSLL ≈ 多 Agent 共识形成算法”这条对应关系挂上。

2.6 模块到模型的抽象升级

最后讲师做了一次抽象升级（frame f008，8:53）：

  • 冲突调解模块 → 冲突调解模型；
  • 模型内部嵌一个子模型：”多议题协商冲突网络模型”；
  • 共识形成模块 → 内含 WSLL 算法。

“模块 → 模型”这一跳是工程视角到学术视角的切换——模型意味着有形式化定义、可论文化。后面集大概率会给具体形式。

3. 没 get 到的点

  • WSLL 到底是哪几个词？只听到字母没听到展开。需查”多智能体共识形成 WSLL”。
  • 角色分配算法的具体形式？是 LLM Prompt 匹配，还是匈牙利 / 拍卖之类经典算法？
  • 信用分如何累计 / 衰减？打分主体是主管 Agent 还是用户反馈？
  • “多议题协商冲突网络模型”里的”网络”指什么——博弈论的协商网络？还是 Agent 之间消息传递的图结构？
  • 同模型 Agent 同进程 vs 跨进程边界：讲师把 RPC/WebSocket 当默认答案，但同进程内是不是有更轻的方案？

5. 知识地图

6. 自测题（5 卡）

Q1：主管 Agent 派单给 A 不给 B，依据是什么？这个决策依靠的算法叫什么？

答主管必须先知道每个 Agent 的角色和擅长领域；依靠**角色分配算法**做"任务需求 ↔ 角色能力"匹配。具体实现本集未展开。

Q2：A2A 协议什么时候用？什么时候不该用？

答A2A 用于**跨模型**的多 Agent（A 跑 GPT，B 跑 Claude）。**同一个语言大模型**底座的多 Agent 不该用 A2A，回退到 RPC / WebSocket 这类**结构化通信**。

Q3：冲突调解模块的”三抓手”是哪三个？少一个会怎样？

答多议题协商（并行调多个冲突）/ 动态角色转换（拉群变辩论方）/ 信用分配（按信用分裁决）。三个必须同时存在，否则共识形成不了。

Q4：动态角色转换具体怎么运作？

答Agent A、B 冲突时，主管 Agent **拉一个群**把两位拉进去；在群里 A、B **抛开**原角色（研究员 / 经理），**临时**担任"辩论正方 / 反方"等新角色。角色是场景制不是终身制。

Q5：冲突调解之后接什么？核心算法是什么？

答接**共识形成模块**，核心算法是 **WSLL**（具体含义本集未展开，待查）。冲突不可能一直冲下去，必须有个收敛模块。

7. 关键词表

术语 一句话
角色分配算法 主管 Agent 派单依据，按”能力 ↔ 需求”匹配
结构化通信 同一 LLM 底座多 Agent 间通信方式（RPC / WebSocket）
A2A 适用边界 A2A 只适用于跨模型 Agent，同模型场景不用
冲突调解模块 三抓手并列：多议题协商 + 动态角色转换 + 信用分配
多议题协商 多个冲突并行调解，不串行排队
动态角色转换 冲突时主管拉群，Agent 临时抛开原角色担任辩论方
信用分配 按 Agent 历史信用分裁决方案采纳，老师傅优先
