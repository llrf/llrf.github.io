6-15 测试AgentScope的Agent运行

发表于2026-05-19|更新于2026-05-21|Agent学习第06章 多 Agent + ReAct架构，SpringAi迈入Agent新时代
|浏览量:

1. 一句话定位

把”AgentScope 引入 + WeatherTool 写完”这件事，从前两集的”零件准备好”，推进到”main 里把 Agent 真的跑起来，并且看到工具被调用”——这是 AgentScope 在本系列的第一次完整端到端跑通。

2. 主体

2.1 形态切换：没有 Controller 了

⏱ 02:23–03:20 · 对比 SAA 1.1，AgentScope 是纯 Java App

你前面整个 SAA 1.1 章节都是”写 Controller → 起 Web 服务 → curl/ApiFox 调”。这一集打开项目结构，HelloAgent 模块下只有一个 HelloAgent.java，里面就一个 public static void main，没有 @RestController，没有 @SpringBootApplication，pom 里也没有 spring-boot-starter-web。

⏱ 02:24

代码里那行注释写得很直接：”AgentScope 是以 Application 形式启动的 / 不是通过 web 接口访问的”。这不是降级，是 AgentScope demo 故意瘦身——它本身和 Spring Boot 没有强绑定关系，所以最小可运行形态就是一个 Java App。后果会贯穿后面所有讨论：没有 Spring Boot，就没有 yml 接管的配置、没有 IOC 注入的便利，所有东西要自己接。

同一个 ReActAgent.builder()、同一个 @Tool 注解定义工具（4-5 那一套），到了挂工具这一步 API 分歧。SAA 1.1 走 .tools(toolCallbacks...) 直接吃工具数组，AgentScope 走 .toolkit(toolkit) 吃一个 Toolkit 容器——容器里再 registerTool(...) 一个个塞。

加工增量在 §2.4：把这三处放在一起看才看出全貌——@Tool 注解层是跨框架复用的；”工具如何注册到 Agent”这一层每个框架都不同（MCP 用 MethodToolCallbackProvider、SAA 1.1 用 .tools(...)、AgentScope 用 Toolkit.registerTool()）。三套写法、同一个注解，是 4-5 → 4-13 → 本集的演化线。

sysPrompt 那段中文是验证工具的关键：明确指令”必须用提供的工具查”，跑出来如果看到 WeatherTool 的返回串，就证明工具确实被走到了，而不是大模型自己凭空编。

⏱ 05:55

.memory(new InMemoryMemory()) 是 Builder 链里一行就开了 Agent 的内存级会话记忆——这一行的含义先记住，多 Agent 协作时怎么共享会被后面回来 challenge（见 §3）。

2.5 调用 Agent：Reactor 流式三段式

📺 09:00–10:00 · agent.stream().doOnNext().blockLast() 三段式

⏱ 07:20

三段：

  1. agent.stream(msg) 返回的是 Reactor 的 Flux——异步流。
  2. .doOnNext(...) 每来一段就打印一段，效果就是控制台一句一句往外吐字。
  3. .blockLast() 阻塞 main 线程，直到流的最后一个元素到达。

第三段是这一集最容易被忽略的强制项。main 是同步线程，agent.stream(...) 返回 Flux 之后就立刻往下走；如果没有 .blockLast()，main 紧接着就 return，JVM 关掉，整个 stream 还在订阅状态就被掐掉了，控制台什么都看不到。这是 Reactor 编程模型的强制要求，不是 AgentScope 自己的事。

⏱ 08:23

Msg.builder 内容部分讲师写了两种写法：复杂版 .content(List.of(TextBlock.builder()...)) 支持多段（图片、文字、工具结果混着塞），简洁版 .textContent("...") 一句话搞定单段。本集只是 hello world，简洁版完全够用，但 List+TextBlock 这一套是为后面多模态/多段消息留口子的。

2.6 验证：工具到底被调到没

📺 09:26–10:26 · 控制台实跑 + 看到 WeatherTool 返回串

跑起来后控制台先打印 ############ 等待响应...，然后流式出来一段一段的回复。判定标准就一条：输出里要看到 WeatherTool 那个写死的返回串（比如”深圳温度值是 30 度”那种调试占位字符串）。看到 → 工具走到了；没看到 → sysPrompt 没起作用，大模型自己编了。

3. 没 get 的点

  • .blockLast() 阻塞主线程，那 5-5 那种多 Agent 协作（主管 + 专科 + 汇总）怎么阻塞？每个 Agent 都 blockLast 还是只阻塞最外层？是不是要切成 .subscribe(...) + CountDownLatch 之类的写法？
  • InMemoryMemory() 是按 Agent 实例独立，还是有办法做全局共享？多 Agent 之间会话记忆怎么传？
  • AgentScope 1.0.7 → 1.0.8 的差异讲师明说”还是用 1.0.7”，到底 1.0.8 改了什么？是不是 Builder API 有破坏性变更？
  • DashScopeChatFormatter 一笔带过——只说”返回结果的格式化”。格式化成什么？跟流式输出每段的拆分粒度有没有关系？
  • enableThinking(true) 被注释掉了，qwen3-max 的 thinking 模式打开后输出会变成什么样？是另起一个 <thinking> 块还是混在主输出里？
  • 左侧 Project 树里同级还看到 manager-agent / routeMaking-agent / tripPlanner-agent 三个兄弟模块——它们跟 demo 模块什么关系？是不是项目结构上已经在为后面多 Agent 协作铺路？

7. 关键词表

术语 一句话
Application 形态启动 AgentScope demo 没引 spring-boot，跑法就是 public static void main，没有 Controller 也没有 Web 端口
环境变量传 API Key 没了 yml，改用 System.getenv("DASHSCOPE_API_KEY")，值在 IDEA Run Config → Environment variables 里设
Jackson 冲突排除 AgentScope all-in-one 自带 jackson-databind，pom 里先 <exclusions> 干掉，再用 ${jackson.version} 统一引一份
AgentScope 三件套依赖 agentscope（排 jackson） + logback-classic（实现 slf4j） + jackson-databind（统一版本）
.toolkit() vs .tools() AgentScope 的 ReActAgent 用 .toolkit(Toolkit) 挂工具；SAA 1.1 用 .tools(...)——一字之差是两个框架的 API 分歧点
ReActAgent Builder 链 name → description → model(DashScopeChatModel.builder...) → toolkit → sysPrompt → memory → build 链式构造一个 Agent
Reactor 流式三段式 agent.stream(msg).doOnNext(打印).blockLast()——Flux 流 + 每段打印 + 阻塞 main 等流结束
sysPrompt 强制工具 用 prompt 而非代码命令 Agent “查天气必须用工具”，是验证工具有没有被走到的最直接钩子
