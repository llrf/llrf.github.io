6-13 RAG只是一个过渡阶段吗？

发表于2026-05-19|更新于2026-05-21|Agent学习第06章 多 Agent + ReAct架构，SpringAi迈入Agent新时代
|浏览量:

1. 一句话定位

这集是一份”为什么本课程不教 RAG”的取舍说明书——你要把 RAG 重新定性成”检索功能 + 强制 LLM 闭卷答题”，然后看着它对应的五个 LLM 缺陷一个个被新一代模型自己吃掉，最后你就明白为什么课程把篇幅留给了 MCP / Agent。

2. 主体

2.1 先把 RAG 从”三件套”祛魅成”一件套”

⏱ 04:46–07:40 · RAG 三模块定性，主体只是检索

你过去听到 RAG 大概率会下意识展开成”检索 + 增强 + 生成”三件平均分量的事，这集要把这个印象掰过来：RAG 主体只是检索，”增强”不过是把检索结果拼成一段上下文，”生成”不过是让 LLM 拿着这段上下文复述一遍。换句话说，RAG 自己不”增强”也不”生成”，它干的是一个数据库的活，只是出口接到了 LLM 的嘴上。

记住这个定性，下面所有讨论才站得住。

2.2 它对应的不是一个问题，而是一份”缺陷清单”

⏱ 01:28–04:40 · 逐条枚举 LLM 五大先天缺陷

⏱ 00:00

RAG 不是一个孤立技术，它是 LLM 五个先天毛病的集体补丁。你需要把这五条钉在脑里，因为下一节要逐个回收它们：

  1. 数据不是最新（训练截止日之后的事不知道）
  2. 不懂用户深层需求（”星巴克附近” vs “我想喝咖啡”）
  3. 胡说八道（幻觉，概率模型本质）
  4. 私人数据获取不到（公司内网文档、个人笔记）
  5. Token / 上下文长度上限——这里挂着一个伏笔节点：”基于注意力机制 → 计算量倍增”，这是 3-1 第一次提到、本集挂在脑图最末梢的物理约束

第 5 条很容易被略过，但它是后面”上下文窗口变大≠RAG 死掉”这个隐藏辩护的根。

2.3 三模块如何接到五个缺陷

⏱ 04:46–09:37 · 检索/增强/生成三模块逐一映射缺陷

⏱ 04:55

现在把脑图右半边长出来，三个模块挂上去：

  • 检索模块：把私人数据（Excel / Word / 图像 / 文件）分块 → 向量化 → 丢进向量数据库 → 拿到查询时做”精准定位相关知识”。这一步对应缺陷 ④（私人数据）和缺陷 ①（外挂能拉到新数据）。
  • 增强模块：把检索结果和”原始查询”融合，拼成一段”大模型可理解的上下文”。这一步对应缺陷 ②（把用户那句模糊的话补全成 LLM 能咬住的语境）。
  • 生成模块：把上下文发给 LLM，引导它”基于这段东西生成回答”——本质是闭卷考试改开卷考试，对应缺陷 ③（有据可查，幻觉收敛）。

注意脑图里没有任何一条线指向缺陷 ⑤（Token 上限）——RAG 解不了上下文窗口本身的物理约束，它顶多是”先筛后塞”，让进窗口的内容更精。

2.4 2026 年回头看：哪些缺陷已经死了

⏱ 09:46–11:30 · 用豆包/DeepSeek 反推哪些缺陷被吃掉

⏱ 09:43

这是这一集真正的”新意”——你不能再用三年前的眼光评估 RAG 的价值。取舍出现在 §2.4：老师把五个缺陷划成两堆。

已经被新一代 LLM 自己干掉的：

  • 意图理解（缺陷 ②）已死：豆包 / DeepSeek / 千问对”我想喝咖啡”这种模糊请求的处理已经不需要 RAG 帮你做”用户在问星巴克”这层翻译了。
  • 数据新旧（缺陷 ①）已死：实时联网 + 工具调用已经让 LLM 自己去拉最新数据，不再依赖你给它喂向量化的当日新闻。

还活着的：

  • 幻觉（缺陷 ③）：概率模型的本质决定它不会自愈，开卷答题仍然比闭卷靠谱。
  • 私人数据（缺陷 ④）：公司不会把内网文档交给公网 LLM，这条物理上无解，RAG 在这里还有刚需。
  • 上下文上限（缺陷 ⑤）：老师这集没明说，但 1M token 窗口下塞 10GB 文档仍然不现实（成本、延迟、lost-in-the-middle），所以”先筛后塞”的 RAG 思路并没死。

2.5 课程取舍声明

⏱ 11:30–12:32 · RAG 剩余价值被 MCP/Agent 切片瓜分

加工增量在 §2.5：消化稿里其实没明说，但你把 §2.4 摊开就能推出来——RAG 剩下的”私人数据 + 抑制幻觉”这两块价值，在课程的教学预算下被认为可以由 MCP（业务系统 API 调用）+ Agent Skills（固化领域知识进 prompt）+ 工具调用这套组合替代式覆盖。所以课程不教 RAG，不是因为它复杂，而是因为它的剩余价值在新一代架构下被切片瓜分掉了。

这句话是这一集的真正终点，也是 6-14 之后整条主线（MCP → Agent → 多 Agent）合法性的来源。

3. 没 get 的点

  • 这集没讲 RAG 自己的局限：分块策略选错、检索精度退化、向量空间漂移、多模态 RAG 的成本——老师一句”RAG 自己也有很多缺陷”带过，得自己去外部资料补。
  • “上下文窗口变大 ≠ RAG 死掉”没有量化论据，只有定性结论。1M token 窗口下塞 10GB 公司文档不现实这件事，你要自己脑补成本 + 延迟 + lost-in-the-middle 三个理由。
  • “私人数据 → RAG 仍有价值”和”MCP / Agent Skills 也能做私人数据”的边界没划——我自己的临时划法是：RAG 适合非结构化文档检索，MCP 适合调用业务系统 API，Agent Skills 适合把领域知识固化进 prompt，但这只是猜，等后面集数验证。
  • transcript 把所有 RAG 听成了 WEC / REC / Rack / VAC，全程音误。你以后看到 WEC 之类的奇怪缩写要先怀疑是 RAG。

4. 跟其他集的连接

  • 上承 3-1（大模型困境清单）：那集第一次列 LLM 缺陷，本集是把那张清单复用 + 升级，加上”注意力机制 → 计算量倍增”这两个新节点。
  • 上承 3-2 / 3-3（Function Calling）：FC 是困境的旧解，RAG 是同一个困境的另一种解。这集等于在说”同困境的 RAG 我们也不打算讲了”，显式确认 FC → MCP → Agent 这条主线。
  • 横向 3-4 / 3-5（MCP）：本集做的事就是”为 MCP 章节腾位置”。三段合起来 = 困境 → FC（旧）→ MCP（新）→ RAG（跳过）。
  • 横向 3-7（Agent Skills）：那集”该外挂的别让大脑硬算”这句话，正好接住 RAG 私人数据那部分——Skills + 文件赋能可以蚕食 RAG 的”个人知识库”用例。
  • 下启 6-14+：这集是承上型的总结片，后面继续讲 Agent / 工具调用最强组合，不会回头补 RAG 实现细节。

5. 知识地图

6. 自测题

Q1 RAG 的”增强”和”生成”是不是 RAG 自己干的？为什么这个定性很关键？

展开 不是。RAG 主体只是"检索"——它把私人数据分块向量化丢进向量库，查询时拉出相关片段。"增强"只是把片段拼成一段上下文，"生成"是 LLM 拿这段上下文复述。这个定性关键，因为它告诉你 RAG 本质上是个数据库出口，所以它的命运绑死在"私人数据 + 闭卷答题"这两个用例上，其他三个 LLM 缺陷一旦被新模型自己吃掉，RAG 的总价值就会被切走一大半。

Q2 五个 LLM 缺陷里，到 2026 年哪两个已经被 LLM 自己干掉了？为什么？

展开 ① 数据不是最新 —— 实时联网 + 工具调用让 LLM 自己拉最新数据。② 不懂用户深层需求 —— 新一代 LLM 对"我想喝咖啡"这类模糊请求的意图理解已经够用，不再需要 RAG 帮忙翻译。剩下的幻觉、私人数据、上下文上限仍然活着。

Q3 “基于注意力机制 → 计算量倍增”这个节点为什么挂在脑图最末梢？

展开 它是缺陷 ⑤（Token 上限）的物理原因——注意力机制让上下文长度的计算量随长度平方倍增，所以窗口不能无限大。这是个伏笔节点（3-1 出现过），本集挂在末梢但没强调；它构成了"上下文窗口变大≠RAG 死掉"这个隐藏辩护，因为 1M token 窗口下塞 10GB 文档仍然不现实。

Q4 课程跳过 RAG 的真正理由是什么？是因为 RAG 太复杂吗？

展开 不是因为复杂。真正理由是：RAG 解决的五个缺陷里，意图和数据新旧已经被 LLM 自己干掉；剩下的"私人数据 + 抑制幻觉"在课程的教学预算下被认为可以由 MCP（业务 API）+ Agent Skills（固化领域知识）+ 工具调用替代式覆盖，所以课程把篇幅留给 MCP / Agent / 多 Agent。

Q5 如果你的场景是”公司想让 LLM 回答 10GB 内部 Wiki”，RAG 和 MCP / Agent Skills 怎么分工？

展开 按消化稿里没明确划但能推出来的边界：RAG 适合**非结构化文档的语义检索**（Wiki / Word / PDF / 图像），先筛后塞；MCP 适合**调用业务系统 API**（工单系统、CRM、数据库查询）；Agent Skills 适合**把固定领域知识固化进 prompt**（流程规范、术语表）。10GB Wiki 主体还是 RAG 的活，但调单据用 MCP，公司术语用 Skills。这是 §3 留下的开放边界，等后续集数验证。
