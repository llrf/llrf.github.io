11-01 回顾AgentScope旅游规划的整体架构

发表于2026-05-19|更新于2026-05-21|Agent学习第11章 MCP+A2A，助力旅游规划团队协作
|浏览量:

1. 一句话定位

这是一集”回炉”——第 10 章把 Skills 插播完了，你回到旅游规划主线时已经断了一章，所以 11-1 先把”上一次（9-10）你看到旅游规划长什么样”完整刷一遍，再往里塞 Skills。

2. 主体

2.1 为什么会有这一集

第 9 章你已经把旅游规划项目的骨架搭完了：四个 Maven 模块、主管 Agent 会自主分解任务、远程 Agent 注册到 Nacos、主管把远程 Agent 当工具调。本来该接着往下走，但 AgentScope 这阵子刚出 Skills 这个新能力，作者临时把第 10 章整章塞进来讲 Skills（10-1 到 10-7）。所以 11-1 的位置非常微妙——它不是”新内容”，是给你的工作记忆做一次 reload，告诉你”接下来 11 章要做的事是：把第 10 章学的 Skills 嵌进第 9 章搭的远程 Agent 里”。

2.2 技术底座 + 四模块骨架

底座是 AgentScope 1.0.8 + SpringBoot 4.0.2。为什么是 Maven 多模块？因为每个 Agent 要单独打 Docker 镜像、跑在不同节点上——一个 Spring Boot 进程一个 Agent。

四个模块：

模块 角色
commons 公共工具类（不是业务模块，只放可复用代码）
manager_agent 主管 Agent，接 prompt、分解任务、派单
routeMaking_agent 远程 Agent 1，擅长自驾游路线制定
tripPlanner_agent 远程 Agent 2，擅长景点行程规划

加工增量：transcript 里第三个 Agent 一会儿叫”形成规划智能体”一会儿叫”行程规划智能体”——这是 ASR 把”行程”误识成”形成”。实际类名 TripPlannerAgent 对应”行程规划”，下面我都按这个写。

2.3 公共模块的三个工具类

commons 模块的 utils 包里有三个静态工具类，这三件套是后面 manager / route / trip 三个 Agent 模块都要复用的：

  • AgentUtils — 封装 ReActAgent.builder()，避免每个 Agent 模块都重写一遍构造链。
  • NacosUtil — 生成 Nacos 客户端，注册中心连接逻辑收敛在这里。
  • ToolUtils — getToolkit(...) 方法把任何 @Tool 标注的对象注册成 AgentScope 的 Toolkit。

2.4 主管 Agent 的三个槽位

主管 Agent 的 builder 链上一共挂三件东西，这三件正好对应”它为什么这么聪明”的三个原因：

槽位 1：PlanNotebook（plan 槽）

名字像草稿本，但它才是主管能”自主决策”的核心对象——别被命名骗了。它干这五件事：复杂任务分解 / 生成执行步骤 / 状态跟踪 / 动态调整 / 任务完成。

挂载方式有两种二选一：

  • .enablePlan() — 用默认 PlanNotebook 实例（内部调 builder 给你一个）。
  • .planNotebook(myInstance) — 传你自己 new 的实例，可以自定义”要不要人工确认执行计划”、”计划怎么存储”、”状态怎么跟踪”这些属性。

加工增量：这是 9-5 / 9-6 给出来的二选一，本集只是复述。如果你之后看到代码里 .planNotebook(plan.getPlan()) 而不是 .enablePlan()，那是因为本项目要自定义 PlanNotebook 行为。

槽位 2：Hook（hook 槽）

Hook 是”挂在 Agent 上的插件”——这一节的演示用法是把”计划和步骤的执行过程”打印出来。语义上它是 9-7 那种事件拦截器，但本集只用它做日志。

槽位 3：Toolkit（toolkit 槽）

主管的 Toolkit 里装了”远程 Agent 包装成工具”的那个 RemoteAgentTool 对象——这是整集的关键认知。下一节单独说。

2.5 反直觉：远程 Agent 是”工具”，不是”消息接收者”

按你的直觉，”主管派单给远程 Agent”应该是 Agent → Agent 的消息流转。实际不是。 AgentScope 的实现是：

  1. 主管端写一个 RemoteAgentTool 类。
  2. 类里两个方法 callRouteMakingAgent() / callTripPlannerAgent()，都用 @Tool(description="...") 注解修饰。
  3. 方法内部 A2aAgent.builder().name("TripPlannerAgent").agentCardResolver(new NacosAgentCardResolver(...)).build() 现场拿到远程 Agent 的句柄。
  4. 然后 agent.call().block() 同步执行。
  5. 这个工具类通过 ToolUtils.getToolkit(new RemoteAgentTool()) 塞进主管的 Toolkit 槽。

视角切换重点：对主管来说，远程 Agent 就是 Toolkit 里的一个 @Tool 方法，跟一个普通的 MCP 工具没区别。它不需要知道远程 Agent 在 192.168.x.x，也不需要管 A2A 协议细节——这些被 A2aAgent + NacosAgentCardResolver 屏蔽掉了。

2.6 主管怎么”发现”远程 Agent：Nacos 注册中心 + A2A 协议

A2A（Agent-to-Agent）需要一个”黄页”才能让 Agent 找到彼此，这个黄页就是 Nacos 注册中心。流程：

  • 远程 Agent 启动 → 自动把”智能体卡片（含 name + 擅长技能描述）”注册到 Nacos。
  • 主管 Agent 通过 NacosAgentCardResolver(NacosUtil.getNacos...) 按 name 查询，拿到卡片后构造 A2aAgent 句柄。

把上面所有东西串起来，就是这张图：

数据流（顺时针读）：

  1. 用户 WebApi → 输入 prompt

  3. 主管在 PlanNotebook 里做自主任务分解
  4. 主管通过 A2A 协议 + Nacos 发现路线 / 行程两个远程 Agent

  8. 远程 Agent 通过 MCP 协议调到 MCPServer 节点上的真工具

2.8 本集的盘点结论

主管侧的三件事已经完成：复杂需求分解（PlanNotebook） / 远程 Agent 发现（Nacos+A2A） / 远程 Agent 当工具调（Toolkit）。没完成的是远程 Agent 内部那个”按 Skills 专业流程执行任务”格子——这就是 11-2 开始要干的活。

5. 知识地图

6. 自测题（5 卡）

  1. 为什么旅游规划项目要做成 Maven 四模块而不是单模块？

    答因为每个 Agent 要单独打 Docker 镜像、跑在不同节点上，一个 Spring Boot 进程承载一个 Agent。多模块是"分布式部署"的工程前提。

  2. 主管 Agent 调用远程 Agent，本质上走的是”Agent 间消息”还是”工具调用”？

    答工具调用。远程 Agent 通过 `A2aAgent.builder().build()` 拿到句柄后被包进 `@Tool` 方法里，再通过 `ToolUtils.getToolkit(...)` 注册进主管的 Toolkit。对主管来说它就是一个普通工具。

  3. .enablePlan() 和 .planNotebook(instance) 这两个 builder 方法的区别是什么？什么时候选后者？

    答前者内部调 `PlanNotebook.builder()` 用默认实例。后者传入自定义实例，可以指定"是否需要人工确认计划"、"计划怎么存储"、"状态跟踪策略"等属性。需要这些自定义时用后者。

  4. 主管 Agent 怎么知道远程 Agent 的存在？要在主管代码里写死 IP 吗？

    答不写死。远程 Agent 启动时把自己的 AgentCard（含 name + 擅长技能）自动注册到 Nacos；主管通过 `NacosAgentCardResolver` 按 name 查询。整个机制靠引入 `agentscope-a2a-spring-boot-starter` + `agentscope-nacos-spring-boot-starter` 两个依赖自动接上。

  5. 本集架构图里哪一格”画了但代码还没接”？11-2 之后要补哪里？

    答远程 Agent 节点里的"按 Skills 专业流程执行任务"那一格。11-2 之后要把第 10 章讲的 Skills 嵌进 RouteMakingAgent / TripPlannerAgent 的 ReAct 执行环节里。
