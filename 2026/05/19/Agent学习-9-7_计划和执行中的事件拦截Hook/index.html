9-07 计划和执行中的事件拦截：Hook

1. 一句话定位

Hook 就是 AgentScope 给”黑箱 Agent”开的一条旁路监控口——不改事件、只读事件，让你看见 PlanNotebook 在内部”想了什么 / 调了什么”。

线索其实在 9-6 启动时一闪而过的日志里——PlanNotebook 自己注册了一堆工具（create_plan / finish_subtask / update_subtask_state / update_plan_info / finish_plan / view_subtasks / get_subtask_count …）。你想知道这些工具到底被谁、什么时候、按什么顺序调到，就得装个监听器。

2.2 Hook 这个名字会骗你

⏱ 01:49–02:59 · 介绍 Hook 拦截器概念，纯讲

讲师管它叫”攔截器”，第一直觉会让你想到 Spring 的 HandlerInterceptor——前置改请求、后置改响应、还能 short-circuit 掉整条链。

实际不是。 后面会看到，Hook 接口要求你把入参事件原样包成 Mono 返回（”並不更改他們的原來事件”）。所以本集的 Hook 更接近 AOP 里的 @After 旁路日志，不是拦截器。

加工增量：本集自始至终没演示”修改事件”。讲师把它叫”攔截器”是顺着 Spring 程序员的习惯，但接口语义上它是观测器。我建议你脑子里直接把它替换成”事件总线的只读订阅”——不然下集真的开始改事件时你会觉得跟本集矛盾。

2.3 Hook 接口长这样

源码就一个方法 + 一个默认 priority：

⏱ 03:03

三个细节值得停一下：

  • 泛型 <T extends HookEvent>：传进来什么类型的事件，必须把同类型的事件回传。你不能换种类型把 PreReasoningEvent 替成 PostReasoningEvent。
  • Mono<T> 而不是 T：因为 ReAct/PlanAct 循环本身就是响应式流，每个事件作为流里的一步处理。Hook 就是流上的一个 .doOnNext() 风格的钩子，跟 7-8 Flux 是 SSE 容器 的 Mono 是同一回事——只发一次的 Flux。
  • priority() default 100：多个 Hook 时按这个排序，本集只挂一个，所以没展开。

加工增量：sealed 是 JDK 17 的封闭类——子类列表是固定的，意味着 switch 上能做穷尽性检查；但反过来，你不能自己塞自定义事件类型。Hook 是观测器，不是事件总线，这是一个值得记住的边界。

2.5 Pre/Post 不是时序，是消息方向（讲师踩坑现场）

📺 08:18–08:40 · 讲师跑一遍后回来改口纠正自己的口误

视频 5:03 处讲师自己改口——这是本集最值得标记的反直觉点：

名字 直觉以为的 实际是的
PreReasoningEvent 推理前的事件 喂给推理的用户输入消息
PostReasoningEvent 推理后的事件 推理输出的思考结果消息
PreActingEvent 准备调工具 准备调工具（这个直觉对）
PostActingEvent 工具调完了 工具调完了（这个直觉对）

讲师先把 PreReasoningEvent 说成”Agent 推理思考事件”，跑了一遍发现打印出来是用户原始 Prompt，回来才改口。

⏱ 08:20

加工增量：与其记”Pre/Post 是输入/输出”，不如记消息方向——Pre* 是流进 Agent 大脑的消息（用户 Prompt / 工具调用准备），Post* 是流出 Agent 大脑的消息（思考结果 / 工具结果）。Acting 一族两个直觉对得上是因为工具调用的”前/后”刚好跟”调用计划/调用结果”对齐；Reasoning 一族的”前/后”对应的是”喂进去 / 吐出来”，跟时间没关系。

2.9 跑两遍对照：needUserConfirm 切换

📺 09:43–11:11 · 终端两次跑结果对照，看日志变化

第一遍：needUserConfirm = true（9-6 默认那种）。Agent 只规划不执行，等你按回车。日志里你能看到：

  • #### 用户的 Prompt: ...（原始需求）
  • #### 思考过程: ...（Agent 怎么拆任务的内心戏）
  • #### 调用工具: create_plan（只有这一个工具调用——因为只规划完就停下来等你）

第二遍：把 9-6 写的 TripPlan.getPlan() 里 needUserConfirm 改成 false，再把公共工具类里的 Stream 也设为 false（不再走流式输出，因为已经被 Hook 打印过一遍）。Agent 一路跑到底，这时候日志里能看到一连串工具调用：create_plan → update_plan_info → finish_subtask → update_subtask_state → … —— 把 9-6 启动日志里那些”自己注册的工具”全用上了。

加工增量：这俩跑法是一个隐性教学——Hook 看见多少事件 = PlanNotebook 配多深的执行。needUserConfirm=true 是断点，停在 PlanAct 阶段；needUserConfirm=false 一直跑到 ReAct 阶段每个子任务都完成。Hook 本身没变，”看见的”完全由 PlanNotebook 配置决定。

3. 没 get 的点

  • 多个 Hook 共存时的执行顺序：priority() default 100，数字大优先还是小优先？是过滤链（前 Hook 修改 → 后 Hook 看修改后版本）还是广播链（每个 Hook 都看到原事件）？本集只挂一个 Hook 没演示。
  • ReasoningChunkEvent / ActingChunkEvent：流式响应时的增量事件吗？跟 7-8 Flux + SSE 的 Flux<ServerSentEvent> 是同一回事吗？
  • SummaryEvent / ErrorEvent 触发点：多 Agent 协作（9-8 之后）里 SummaryEvent 是不是用来串汇总 Agent？ErrorEvent 跟 ReAct 的反思边怎么对应？
  • Hook 真的不能修改事件吗？ 接口签名 <T extends HookEvent> Mono<T> onEvent(T event)——返回类型允许是 T 的任意实现，理论上你能 new 一个新的 PreReasoningEvent 替换原 Prompt。本集刻意没演示这条路，但接口本身没禁止。需要看源码确认有没有 final / @Unmodifiable 之类的约束。下集大概率讲这个。
  • hook(Hook) vs hooks(List<Hook>) 在 builder 实现上是覆盖还是追加？ 多次 .hook() 调用会怎样？

4. 跟其他集的连接

  • 上承 9-6 自主分解任务的关键 PlanNotebook：9-6 把 PlanNotebook 搭起来跑出 5 个子任务的”成品”，本集给那个黑箱开旁路监控口。needUserConfirm 的两种值切换也直接复用 9-6 建好的 TripPlan.getPlan() 工厂方法。再往上承 9-5 主管 Agent 自主分解复杂任务 —— 那集第一次跑出 Should I proceed with this plan?，本集让你看见这个询问之前 Agent 在想啥。
  • 下启 9-8 主管 Agent 分发任务给相应 Agent：本集的 Hook 让”主管 Agent 调用了哪些工具”变得可观测，9-8 就是把那些工具调用真正路由到下属专科 Agent（routeMaking_agent / tripPlanner_agent）。再往后可能讲怎么用 Hook 修改事件而非只读（如 PreReasoning 阶段改写 prompt、PreActing 阶段做工具白名单过滤）。
  • 横向同位：
    • 6-6 ReactAgent.builder() 六件套 的 OutputType 四种事件——SAA 1.1 通过 OutputType.events() 流出”思考/行动/观察”事件，AgentScope 通过 Hook 接口被动接收。两者底层都是把 ReAct 循环事件化。
    • 7-8 Flux 是 SSE 容器——共用 reactor.core.publisher.Mono。Hook 返回 Mono<T> 而非 T，正是为了在 ReAct 循环里把每个事件作为响应式流的一步处理。
    • 8-13 不同的执行者调用不同的执行流程 互补——那集讲 JManus 怎么”自己写出”执行循环（AbstractPlanExecutor.executeStep + BaseAgent.run），本集讲 AgentScope 怎么”用 Hook 旁听”框架已经写好的循环。同一个目标（看见 ReAct 中间态）的两条路：自己写 vs 挂钩子。
    • 3-7 Agent Skills 提到的”工具调用三种范式”——Hook 不是新范式，是观测范式之上的元工具，记录”任意范式被触发时发生了什么”。
    • 4-3 MCP 通信的分层设计 同属”关注点分离”思想——Hook 把”观测/日志/审计”从 Agent 的核心循环里抽离出来，跟 MCP 把”协议层/传输层”分开是一脉相承的工程美学。

6. 自测题

  1. 为什么 onEvent 必须把入参事件原样 Mono.just(event) 返回？返回 Mono.empty() 会怎样？
  2. PreReasoningEvent 和 PostReasoningEvent 哪个里面装的是”用户原始 Prompt”，哪个装的是”Agent 的思考过程文本”？为什么名字容易让人搞反？
  3. 你在 case PreReasoningEvent e -> 这行写完 IDEA 报红——除了升级 JDK，最直接的两条解决路径是什么？
  4. 同样跑一次 PlanNotebook，needUserConfirm=true 时 Hook 能打到几条 PostActingEvent？改成 false 后大概能打到几条？为什么？
  5. 你想在 Agent 调工具之前拒绝某些危险工具（比如不让它调 finish_plan）——光靠本集的 Hook 接口能做到吗？如果不能，缺什么能力？

7. 关键词表

术语 含义
Hook 接口 io.agentscope.core.hook.Hook，单方法 <T extends HookEvent> Mono<T> onEvent(T event) + default priority()，AgentScope 给 ReAct/PlanAct 循环开的旁路观测点
HookEvent sealed 抽象类 六个直接子类（PreCallEvent / PostCallEvent / ReasoningEvent / ActingEvent / SummaryEvent / ErrorEvent），封闭继承不可扩展，switch 可做穷尽性检查
PreReasoningEvent 用户输入消息事件，getInputMessages() 取原始 Prompt；不是”推理前”的时序事件
PostReasoningEvent Agent 推理输出事件，getReasoningMessage().getTextContent() 取思考过程文本
PreActingEvent / PostActingEvent Agent 调用工具前/后的事件，含 Toolkit + ToolUseBlock
ReActAgent.builder().hook 单个 Hook 注入入口；同名 hooks(List<Hook>) 用于多个 Hook，按 priority() 排序
JDK 17 Preview Pattern Matching for switch case PreReasoningEvent e -> 类型模式的语言级前提，IDEA Project Structure 把 Language Level 设为 17 (Preview)
Mono 原样返回约定 Hook 不修改、不吞掉事件，必须 Mono.just(event) 包装原事件返回，框架后续链路才能继续用
