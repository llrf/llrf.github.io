4. 跟其他集连接

  • 上承 4-1：4-1 教 BOM + spring-ai-alibaba-starter-dashscope 的导入。本集就是”导入完之后 starter 白送了什么 Bean”的答案——ChatModel。
  • 上承 6-2：6-2 启动报错 DashScope API key must be set 留的尾巴，本集第一件事就是把这个 key 补上。
  • 下启 6-4（推测）：文档把 ChatModel 和 ChatClient 并列写”两个实例”。ChatModel 是底层 call(Prompt) 接口，ChatClient 大概率是更高层的 fluent API（prompt().user().call().content()）——下一集应该揭晓。
  • 横向 5-5（主管+专科+汇总 Agent）：那一集说”LLM 是 Agent 的大脑”，本集就是这个大脑在 Spring 里的具体握把。
  • 横向 4-13（ReactAgent.builder()）：1.1 版 ReactAgent 的构造参数要传 ChatModel，正是本集这个对象。本集是 1.0.0.2 入门，4-13 是 1.1 把它包了一层 Agent 抽象。
  • 横向 3-2/3-3（Function Calling）：FC 也要走 Prompt → 大模型 → 响应，本集的 Prompt 未来塞 tools 列表就在这一层叠加。

7. 关键词表

术语 一句话定义
ChatModel SAA 自动装配出来的”和大模型对话的握把”接口，方法 call(Prompt) 返回 ChatResponse。
UserMessage 用户输入的 Java 化封装，构造参数是字符串，属于 org.springframework.ai.chat.messages。
Prompt 提示词聚合对象，可装一条或多条 Message（User / System / Assistant），本集只塞一条 user。
ChatResponse 大模型返回的聚合对象，三层取文本：getResult().getOutput().getText()。
自动装配 引入 starter 后 Spring Boot 启动阶段就把 ChatModel / ChatClient 实例化好塞容器，开发者只伸手接。
构造方法注入 private final ChatModel chatModel; + 构造方法赋值；比字段注入更利测试、避免空指针。
dashscope 配置 namespace spring.ai.dashscope.api-key（不是 spring.ai.alibaba.*），starter 名和配置前缀不对称。
三层判空 取 getResult() / getOutput() 任一层都可能 null，超时/限流时要先判再取 getText()。
