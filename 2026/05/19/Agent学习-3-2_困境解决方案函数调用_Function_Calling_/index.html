3-02 困境解决方案：函数调用（Function Calling）

发表于2026-05-19|更新于2026-05-21|Agent学习第03章 MCP + Skills，Agent"工具+技能"的双轮驱动
|浏览量:

§1 一句话定位

Function Calling = LLM 自己写调用代码，去捞向量空间里没有的东西。

§2 主体讲解

2.1 先把名词钉死：Function Calling 是 LLM 内部的”一段程序”

⏱ 04:44–05:11 · 命名落地”一段程序”，纯讲

你大概率会把 Function Calling 翻译成”LLM 调用外部函数”，这其实只对了一半。

更准的理解是：它是 LLM 内部的一段程序，这段程序能根据用户问题，自己写出一段调用外部 API / 本地文件 / 数据库的代码，并把结果拿回来塞进回答里。

注意”自己写”这三个字——它不是”LLM 触发某个预先编排好的函数”，而是”LLM 现场组装一段调用代码”。这一点先记住，§2.3 会回来对照。

本集你只需要理解到”一段程序”这一层。”这段程序到底是 LLM 自己执行还是宿主跑”，这里先不展开，因为后面 3-4 MCP 才会正面回答（见 §4 下启）。

⏱ 04:44

2.2 它解决什么：3-1 留下的两个洞，一把锁住

⏱ 00:00–01:00 · 回顾 3-1 两大缺陷，纯讲

3-1 已经摆出 LLM 的两个致命弱点：

弱点 典型问题 为什么 LLM 答不上来
不能获取实时数据 “深圳现在多少度？” 向量空间里没有”当前温度”这种时变值
不能拥有私人数据 “根据我公司客户订单生成季度销售报告” 训练语料里根本没看过你的 Excel

⏱ 00:38

⏱ 05:34

Function Calling 一把同时锁住这两个洞——你会发现它根本不区分”对外打天气 API”还是”对内读本地 Excel / 查 MySQL / 拉阿里云数据库”，本质都是同一个动作：LLM 判断要去外部捞数据，然后自己写代码去捞。

把”实时数据”和”私人数据”想成两个解法，是没看穿这一点。

2.3 关键差异：跟 3-1 时代的”人工额外编写代码”差在哪

⏱ 02:25–03:00 · 砍掉”人工额外”，引出自主三步，纯讲

3-1 里有一张图，你应该还记得：在 LLM 答不上”今天多少度”之后，下方那条解决路径写着「人工额外编写代码 / 调用外部 API」。

这五个字”人工额外编写代码”就是 3-2 要砍掉的东西。

砍掉之后剩下什么？剩下 LLM 自主三步：

  1. 判断：用户这个问题，我答不答得了？要不要去外部？
  2. 匹配：要去外部，那调哪个 API / 哪个文件 / 哪个库？
  3. 生成：根据 API 文档，现场组装调用代码，发出去，拿回来，整合进回答。

⏱ 02:40

讲到”自主”，你可能会反问：LLM 凭什么知道有个叫”墨迹天气”的东西？

两个先决条件缺一不可：

  • 它的向量空间里，有一根向量指向第三方应用（比如墨迹天气）。
  • 它掌握最新的 API 文档，所以才能现场把”深圳”这个参数填到对的位置。

向量指针解决”知道找谁”，API 文档解决”知道怎么调”。两条腿都得有。

⏱ 03:27

2.4 走一遍天气例子（验证三步骨架）

⏱ 03:00–04:26 · 把自主三步套天气场景走一遍，纯讲

把 §2.3 的三步套到一个具体问题上，你就能反推这套机制是怎么运转的。

用户问：”深圳今天多少度？”

步骤 发生了什么 对应 §2.3
1 LLM 一看：”这是实时温度，我向量空间里没有” → 决定调外部 判断
2 顺着向量找到”墨迹天气”，调出它的 API 文档 匹配
3 把”深圳”作为参数填进 API 调用，墨迹天气返回温度，LLM 整合成自然语言回复 生成

⏱ 04:21

2.5 套同一模板：私人数据怎么走

⏱ 05:11–07:53 · 私人数据走同一三步模板，纯讲

私人数据这条线不需要单独学一套机制——它就是 §2.3 三步骨架的同一个模子换了个外挂目标。

实时数据场景 私人数据场景
调外部 API（墨迹天气 / 股票 / 湿度） 调本地文件（Excel / Word / PDF / Markdown）
参数：城市名 参数：文件路径 / 查询条件
返回：实时数值 返回：订单数据 / 文档内容
也可能：查数据库（MySQL / Access / Hadoop / 阿里云 / 腾讯云）

旧时代的解法是”人工把 Excel 喂给 LLM”——同样要被”人工额外”四个字砍掉。砍掉之后，LLM 自己判断”用户要的销售报告需要客户订单数据”→ 自己去读本地 Excel → 自己拼回答。

这就是为什么本集起名”困境解决方案”——一个 Function Calling，俩窟窿一起补。

2.6 一个口语化检验工具：”还叫人工智能吗？”

⏱ 02:25–02:30 · 视频反复出现的反诘口头禅

整集贯穿一句反诘：”这还叫人工智能吗？”——凡是要人工额外写代码、人工导数据、人工补 API 的方案，都不配叫 AI，最多算”员工智能”。

这句话听上去像段子，但它实际是一把尺子：以后看任何”Agent”方案，你都可以问一句”这套流程里有没有人工额外写代码 / 导数据这一步”——有，就退化成 3-1 时代的解法。没有，才是这条线在追的东西。

把这个尺子放进口袋里，后面 3-4 MCP / 3-7 Skills 你都会复用它。

§3 我一开始没 get 的点

  1. 如果你把 Function Calling 理解成”LLM 调用预先注册的函数”，你会以为 3-1 和 3-2 是同一件事换了个名字——其实差异在”自主”那三步。3-1 时代由人工编排”何时调、调哪个、传什么参”；3-2 是把这三步全交给 LLM。少了”自主”这层，看起来 3-1 的人工方案也”调用了外部 API”，但它不配叫 Function Calling。

  2. 如果你把”实时数据”和”私人数据”当成两条独立技术路线，你会以为本集要讲两套机制——其实是同一套 Function Calling 在两个目标上的复用，§2.5 那张对照表两栏走的是同一个模子。把它们想成”对外/对内两个出口、一个机芯”会更准确。

  3. 如果你以为 LLM 真的”运行”了那段调用代码，你会得到一个无法回答的问题：LLM 哪来的运行时？ 本集只让你停在”理解为 LLM 内部的一段程序”——谁真正按下执行键，本集刻意没说。这个坑要等 3-4 MCP 才填。先别在这里钻牛角。

  4. 如果你以为 LLM 能调任意第三方 API，你会忽略两个先决条件：① 向量空间里有指向那个应用的向量；② LLM 掌握最新 API 文档。少一条都不行——一个让它”知道有谁”，另一个让它”知道怎么用”。后面”API 文档怎么塞给 LLM”是 3-4 / 3-5 才解决的问题。

§4 跟其他集的连接

上承

3-1 把两个洞挖出来——不能取实时数据 + 不能拥有私人数据。本集就是直接对着这两个洞开药方。3-1 那张「人工额外编写代码 / 调用外部 API」的红框图，到本集开头 38 秒还在用同一张图，区别只在于：那个”人工额外”的红框，被替换成了 LLM 自己来。所以你可以把 3-2 看作 3-1 的下半句——3-1 是”问题陈述”，3-2 是”解决方案陈述”。

下启

本集刻意留了两个坑：① Function Calling 那段程序到底由谁执行？② API 文档以什么形式被 LLM “掌握”？这两个坑直接通向 3-4 更优的困境解决方案 MCP（标准化把工具列表 / 会话流程定死）和 3-5 对比 Function Calling 和 MCP 的不同（讨论分发方式、谁是小弟 / 中间人）。中间的 3-3 Function Calling 就是大模型的跑腿小弟 大概率是把”自主三步”再可视化成一次跑腿动作，给 3-4 引出”小弟之上还需要一层经纪人”的需求。所以本集那句”暂时先把它理解为是语言大模型内部的一个程序”是张明牌伏笔。

横向

“调本地文件 + 调数据库”这条线，3-7 Agent Skills 会重新捡起来——Skills 也是给 Agent 喂私人 / 领域知识，但它走的是”文件夹 + SKILL.md”的路，不走 API 调用。Function Calling / MCP / Skills 三条线都在解同一个外挂问题，切片不同：FC 是”现场写调用代码”，MCP 是”标准化协议层”，Skills 是”按需加载文档包”。看到任何”给 LLM 加外部能力”的方案，先归类到这三条线中的哪一条，理解起来会快很多。

§6 自测题

Q1（概念回忆） 用一句话说清楚 Function Calling 是什么，必须包含”自主”和”调用代码”两个要点。

A1: Function Calling 是 LLM 内部的一段程序，它能让 LLM 自主判断是否需要外部数据 / 自主匹配合适的 API 或文件 / 自主生成调用代码。见 §2.1 + §2.3。

Q2（概念辨析） “LLM 自己写调用代码”和”程序员预先注册函数让 LLM 触发”，差别在哪？这两种都属于 Function Calling 吗？

A2: 关键差异是自主性——前者三步（判断/匹配/生成）全归 LLM；后者保留了”人工额外编写代码”的环节，按本集口径它退化成 3-1 旧方案，不算 Function Calling。判断时套用 §2.6 那把尺子：”流程里有没有人工额外写代码 / 导数据”。见 §2.3 / §2.6。

Q3（反直觉陷阱） 既然 LLM 能”自己写调用代码”，那它是不是有 Python 运行时？这段代码到底在哪台机器上执行？

A3: 本集刻意不回答这个问题，只让你理解到”LLM 内部的一段程序”这一层。真正按下执行键的是谁，留到 3-4 MCP 才填。如果你纠结这一点，会卡死在 §2.1。见 §3 第 3 条 + §4 下启。

Q4（跨集连接） 3-1 里那张「人工额外编写代码 / 调用外部 API」的红框图，到 3-2 发生了什么变化？这变化在哪一帧能看到？

A4: 同一张图在本集 38s（f004）还原原样出现，然后到 §2.3 整套被”LLM 自主三步”（f006）替换——“人工额外”四个字被砍掉，调用代码由 LLM 自己出。这是 3-1 → 3-2 的核心交接点。见 §2.3 / §4 上承 / 图 f004 + 图 f006。

Q5（应用推广） 你给一个本地 LLM 接入了一个内部知识库 API，但每次问”我们公司 Q3 营收多少”，它都要程序员手动构造调用语句，LLM 只负责把 API 返回的数字读出来。这套方案算 Function Calling 吗？

A5: 不算。LLM 自主三步缺了 ① 判断和 ② 匹配，③ 生成也被人工接管——按 §2.6 那把尺子，”人工额外构造调用语句”这一步没被砍掉，所以它退化到 3-1 时代的”人工写 API”方案。要升级成真 FC，需要让 LLM 自己根据 API 文档生成调用语句。见 §2.3 / §2.6。

§7 关键词表

关键词 一句话定义
Function Calling LLM 内部的一段程序，能根据用户需求自主调用外部 API / 本地文件 / 数据库
LLM 自主三步 判断是否需要调外部 → 匹配 API 函数 → 根据 API 逻辑生成调用代码与回复
实时数据外挂 天气 / 湿度 / 股票等时变数据——LLM 训练数据永远过期，必须 FC 兜底
私人数据外挂 客户订单 / Excel / PDF / MySQL / 阿里云腾讯云数据库——LLM 训练时根本看不到
第三方应用向量 LLM 向量空间里那根指向外部应用（如墨迹天气）的指针，让它”知道有谁”
API 文档 LLM 必须掌握最新文档，才能现场拼出正确的调用代码，让它”知道怎么用”
人工额外编写代码 3-1 时代旧解法的标志性短语，3-2 要砍掉的就是这五个字
员工智能反诘 “还叫人工智能吗”——判断方案里有没有人工兜底环节的口语化尺子

摘要：取舍出现在 §2.1（”那段程序到底由 LLM 自己执行还是宿主代跑”本集不展开，留给 3-4 MCP）。加工增量在 §2.6（把分散在多处的”还叫人工智能吗”反诘提炼成可复用的判断尺子）+ §6 Q5（构造了一个”内部知识库 API + 人工拼调用语句”的全新检验场景，understanding.md 没有这条）。
