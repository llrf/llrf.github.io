1. 一句话定位

这一集是 SAA 1.1 的入门钥匙：你不再 ChatClient.prompt().call() 直接打 LLM，而是先用 ReActAgent.builder() 拼一个智能体出来，让它带着大脑、手脚、记忆、人设替你做规划和决策。

2. 主体

2.1 1.0 vs 1.1 心智模型差（B：是什么）

⏱ 01:47–04:16 · 1.1 文档目录变两核心，Agent 升级为一级抽象

1.0 时代你拿到的是一根电话线 —— ChatClient 上一头接你，一头接 LLM，你说什么它转什么。1.1 时代你拿到的是一个秘书 —— ReActAgent 帮你接电话、帮你决定要不要打、要不要查资料、要不要写下来。秘书内部仍然在用电话（ChatModel），但你不直接碰那根线了。

讲师特别强调了一句”1.0 的 ChatClient 在 1.1 里同样适用”。这话其实是给你台阶下：纯对话场景你完全可以继续用 ChatClient，ReActAgent 不是替代品而是升级品——它在 ChatClient 之上多包了规划和决策两层能力。

2.4 call vs stream：从「对话流」到「执行轨迹流」（B+C）

📺 17:37–19:35 · IDE 切 stream + subscribe + OutputType 判事件类型

1.0 的 stream 直接返回 Flux<String>，吐字符串就完事。1.1 的 stream 返回 Flux<NodeOutput> —— 因为 Agent 内部已经是 Graph，每个事件都是一个节点的输出，你拿到的不再是”答案的下一个字”，而是”Agent 执行轨迹的下一帧”。

方法 返回值 适用场景
agent.call(msg) AssistantMessage（一次性，.getText() 取文本） 简单一问一答
agent.stream(msg) Flux<NodeOutput>（流式 + 带事件类型） 需要看模型出字、工具调用、Hook 触发的全过程

stream 模式下，你 subscribe 之后要靠 instanceof StreamingOutput 判类型，再用 OutputType 枚举区分四种事件：

  • AGENT_MODEL_STREAMING —— 模型在出增量字（拼到 UI 上）
  • AGENT_MODEL_FINISHED —— 模型本轮推理完了
  • AGENT_TOOL_FINISHED —— 某个工具调完了（输出 output.node() 看是哪个工具）
  • AGENT_HOOK_FINISHED —— 某个 hook 跑完了（RAG/拦截器之类）

这就是为什么 stream 范型从 String 升级成 NodeOutput —— 你不再是观察一个 LLM 在打字，你是在观察一台 Agent 状态机在跑。取舍出现在 §3：讲师讲到这里没展开为什么需要这四种事件分开，但其实它对应了 ReAct 思维循环里 Thought/Action/Observation 的不同阶段，本集留白了。

2.5 工具注册三步走（C：怎么用）

📺 11:28–13:00 + 20:13–21:23 · IDE 写 WeatherTool 类 + FunctionToolCallback + 选包坑

这一段是最容易抄错的地方。流程是：

第 1 步：写一个工具类，implements BiFunction<String, ToolContext, String>，重写 apply(String city, ToolContext ctx)。

第 2 步：用 FunctionToolCallback 把它包成 ToolCallback。

第 3 步：塞进 .tools(weatherTool)。

坑在第 1 步导包：IDEA 会同时弹 java.util.function.BiFunction 和 fastjson 那个 @BiFunction，必须选 java.util.function，否则编译过不了。讲师在课里特意停下来强调了这一选——这种”小坑大堵车”的细节是视频对比文档的真实价值。

加工增量在 §2.5：讲师只演示了单参 String city，但工具真实需求往往是多参（经纬度查天气）。这种情况要把 BiFunction<String, ...> 的第一个泛型换成 POJO 类，同步把 .inputType(YourPojo.class) 改掉，Spring AI 会自动按 JSON Schema 解析 LLM 的工具参数。这个推断本集没讲，但顺着 inputType 这个名字能想通。

2.6 1.1 的真正新东西（B：是什么）

⏱ 21:45–26:35 · 1.1 比 1.0 多两个能力：规划 + 自主决策，引出 Agentic AI

1.0 的 Agent = 大脑 + 工具 + 记忆 + 环境感知（执行者）。1.1 的 Agent 在此之上多了两个能力：

  • 规划能力：复杂任务自动拆成子任务
  • 自主决策能力：自己挑工具、自己挑步骤、自己决定何时收尾

这两个能力在 builder 上没有对应的方法，没有 .planning() 也没有 .decision()。它们是隐藏在 ReAct 思维循环里的内置行为 —— 这也解释了为什么 stream 出来的是 NodeOutput：因为内部本来就是 Graph 在跑 Thought→Action→Observation→Thought→… 这个循环。

最后讲师抛了个词：”Agentic AI“ —— 26 年 AI 的方向不是把单个 Agent 做得多强，而是让多个 ReActAgent 像团队一样协同。这就接到了后面 A2A、多 Agent 框架那条主线。

6. 自测题

  1. 问：1.1 项目的 pom 里，spring-ai-alibaba-agent-framework 不用写版本号，但 spring-ai-alibaba-starter-dashscope 必须写版本号，为什么？
    答：因为 BOM（spring-ai-alibaba-bom）声明的版本管理范围里不包含 dashscope 这个 starter，所以必须用 ${spring-ai-alibaba.version} 显式指定。

  2. 问：agent.call(msg) 和 agent.stream(msg) 的返回类型分别是什么？取文本的方式有什么区别？
    答：call 返回 AssistantMessage，用 .getText() 一次性拿到完整答案；stream 返回 Flux<NodeOutput>，需要 subscribe 后判 instanceof StreamingOutput，再调 streamingOutput.message().getText() 拿到增量片段。

  3. 问：写一个 Agent 工具的最小流程是哪三步？
    答：(1) 写类 implements BiFunction<String, ToolContext, String> 并重写 apply；(2) 用 FunctionToolCallback.builder(name, instance).description(...).inputType(...).build() 包成 ToolCallback；(3) 在 ReActAgent.builder 里 .tools(callback) 注入。

  4. 问：OutputType 的四种事件是哪四种？分别表示什么？
    答：AGENT_MODEL_STREAMING（模型出增量字）、AGENT_MODEL_FINISHED（模型本轮推理完）、AGENT_TOOL_FINISHED（工具调完）、AGENT_HOOK_FINISHED（hook 跑完）。

  5. 问：1.0 的 Agent 和 1.1 的 Agent 在能力维度上差了什么？为什么 1.1 不在 builder 上加 .planning() 这样的方法？
    答：1.1 比 1.0 多了”规划能力”和”自主决策能力”两项。不加专属方法是因为这两项是 ReAct 思维循环内置的隐式行为 —— Agent 内部本来就是 Graph，循环执行 Thought→Action→Observation，规划和决策是循环自然涌现的产物，不是一个可配置的开关。
