5. 知识地图

6. 自测题（5 卡）

  1. Q：为什么 ParallelAgent.builder().subAgents(...) 能同时塞 ReactAgent 和另一个 ParallelAgent？
    A：源码里只校验 agent instanceof BaseAgent。ReactAgent 和 FlowAgent 都派生自 BaseAgent，所以混搭合法，”FlowAgent 嵌 FlowAgent + 叶子是 ReactAgent”的树形结构成立。

  2. Q：LlmRoutingAgent 的 description 跟 ReactAgent 的 description 写法上最大区别是什么？
    A：ReactAgent 的 description 写”你是谁”（自我角色），LlmRoutingAgent 的 description 写”业务怎么分发到哪个子 Agent”（路由规则，给 LLM 读）。

  3. Q：本集装配出的 SequentialAgent，能不能调用 .call("你好") 或 .stream("你好")？
    A：不能。FlowAgent 没有 call/stream，只有 .invoke(String)，返回 Optional<OverAllState>。controller 还要在签名抛 GraphRunnerException。

  4. Q：tools(AgentTool.getFunctionToolCallback(budgetAgent)) 和 ParallelAgent.subAgents(List.of(budgetAgent)) 让 budgetAgent 跑起来的机制有什么不同？
    A：前者把 budgetAgent 包成一个 FunctionTool，外层 ReactAgent 在 ReAct 循环里按需调用它一次或多次；后者是把 budgetAgent 作为 DAG 节点并行触发。前者强耦合复用，后者无依赖并跑。

  5. Q：同一个方法名 subAgents，分别塞进 ParallelAgent、LlmRoutingAgent、SequentialAgent 时，语义如何变？
    A：方法签名都是 List<Agent>，但 ParallelAgent 里 = 并行兄弟节点；LlmRoutingAgent 里 = LLM 候选分发目标；SequentialAgent 里 = 顺序执行节点。底层都走 super.subAgents(...)，执行语义由各自 doBuild 决定。

7. 关键词表

术语 含义
ReactAgent vs FlowAgent 前者 ReAct 思考-行动循环、能 call/stream；后者 BaseAgent 派生、只编排、只 invoke
AgentTool.getFunctionToolCallback 把 ReactAgent 包成 FunctionTool 的桥梁，实现 “Agent as Tool”
ParallelAgent FlowAgent 子类，多个 Agent 按并行流程逻辑协同
LlmRoutingAgent FlowAgent 子类，让 LLM 读 description 动态分发任务到 subAgents 之一
SequentialAgent FlowAgent 子类，按顺序串联多个 Agent，本集做总装外壳
subAgents 多态语义 同一方法签名 List<Agent>，宿主 FlowAgent 类型不同 → 并行兄弟 / 路由候选 / 顺序节点
OverAllState 工作流的 KV 状态包，invoke(...) 返回 Optional<OverAllState>
三层嵌套总装 Sequential(LlmRouting → Parallel)，FlowAgent 嵌 FlowAgent，叶子是 ReactAgent
