13-08 课程总结

课程总结

一句话定位

整门课就讲两件事：多 Agent 怎么一起干活（协同），和单个 Agent 怎么自己想清楚再干（自主思考执行）——所有知识点都挂在「旅游规划」这一个项目上演示。

主体

一张脑图收全课

把整张脑图压扁，就两根主轴：

加工增量：原讲述里”工作流编排两路”和”AgentScope 六要素”是平铺的，我重新把它折成上图——工作流编排 和 AgentScope 是「多 Agent 协同」的两种实现选型而不是并列功能。FlowAgent 三兄弟也不是三个独立 Agent，而是三种继承自同一基类的编排模板。

工作流编排：两种粒度

Graph 引擎 只看两个对象就够了：

对象 干啥的
StateGraph 编排引擎本体——加节点、连边
OverAllState 全流程的数据/状态总线，Agent 之间的传输都走它

FlowAgent 基类 走继承路线，子类即模式：

  • ParallelAgent：里面的 Agent 并行跑
  • LlmRoutingAgent：由 LLM 决定把任务派给哪个下游
  • SequentialAgent：按顺序一个个执行

AgentScope：六枝是怎么长的

这是本课的重点框，企业级工程化的六个抓手：

  1. Docker 分布式 Agent：每个 Agent 独立容器化部署
  2. 多 ReAct Agent 协同：每个节点本身都是会思考的 ReAct Agent
  3. MCP 服务部署为单独节点：本课用的远程百度地图 MCP，企业项目里要本地自部署
  4. Skills 工程化：把技能做成可装配模块
  5. 单独子任务执行：SubAgent 一个子任务一个 Agent
  6. A2A 协议 + Nacos 注册中心：分布式 Agent 之间靠 A2A 通信，靠 Nacos 做服务发现

取舍提醒：老师明确点名 Jmanus 非重点、AgentScope 才是重点——课程取向是”企业级工程化”而非”复用现成名牌框架”。这也是为什么 13 章整章在堆 AgentScope 的细节。

自主决策：分两层而不是一层

自主决策这块容易当成一个东西讲，但脑图明确把它拆两层：

上层是”组织者”的自主——把任务切开、派下去；
下层是”执行者”的自主——干一步就回头验一下，不对就改。
两层是上下嵌套关系，不是并列。

自主执行的三件套

最后这张图把”自主执行”具体落到三种能力上：

  • 思考：ReAct 思维框架
  • 工具使用：MCP & Function Calling
  • 专业技能：Agent Skills 系统

没 get 的点

  • “Skills 工程化”在脑图里只列了名字，没说它和 12-1~12-5 已经讲过的 Skills 系列具体差异——是不是特指”Skills 在分布式 Agent 间复用”那一面？
  • FlowAgent 三个子类（并行/路由/顺序）是覆盖了所有常见编排模式，还是只是”够用的三种”？老师没明说能不能再继承出第四种。
  • MCP「单独节点」 vs Skills「工程化」在 AgentScope 里其实是两种工具暴露方式，二者的取舍标准本集没展开。

知识地图

承载项目：旅游规划（贯穿 7-12、11、12、13 章的所有代码）

自测题

  1. 课程的两大主线是什么？分别用一句话概括。
  2. Graph 引擎要掌握的两个对象是哪两个？各自职责是什么？
  3. FlowAgent 基类下面有哪三个子类？分别对应什么编排模式？
  4. AgentScope 工程化的”六要素”里，分布式 Agent 之间通信靠的协议是？服务发现走的注册中心是？
  5. “自主决策两层”指的是哪两层？两层之间是并列还是嵌套？
参考答案
  1. 多 Agent 协同；Agent 自主思考执行。
  2. StateGraph（编排引擎，加节点连边）+ OverAllState（数据状态总线）。
  3. ParallelAgent（并行）/ LlmRoutingAgent（路由分发）/ SequentialAgent（顺序）。
  4. A2A 协议 + Nacos 注册中心。
  5. 整体计划层（拆任务+分发）+ 执行任务层（思考-行动-反思-调整）；上下嵌套。
