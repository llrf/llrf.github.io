12-02 有限预算内规划精彩旅行的Skills

发表于2026-05-19|更新于2026-05-21|Agent学习第12章 专属SubAgent, 处理旅游规划专业Skills
|浏览量:

1. 一句话定位

12-1 把两个 Skill 挂到了 TripPlannerAgent 上，这集把镜头推近，蹲在 Suggest-Sights/ 文件夹里看一个 Skill 内部长什么样——一个 SKILL.md 加两个可选目录，全部内容都是 Markdown 和提示词。

2. 主体

2.1 目录三件套

📺 01:15–03:47 · IDE 展示 SKILL.md+scripts+references 文件夹结构

走进 resources/skills/Suggest-Sights/，你只会看到三样东西：

  • SKILL.md —— 唯一必须存在的文件，文件名固定写死。
  • scripts/ —— 放可执行脚本，本集是一个 weather_check.py。
  • references/ —— 放静态知识文件，比如酒店清单、菜单。

后两个目录的”可选”是真的可选。讲师只在景点推荐技能里建了它们，下一集的表格制作技能就不一定有。这就是为什么模板复用率高：核心是 SKILL.md，附件按需挂。

加工增量：Java 项目里塞一个 Python 脚本，听起来违和。但 Skill 的本质是”一份带附件的提示词”——Agent 决定调脚本的时候，框架去 shell 出一个 python 进程跑就行，宿主语言和脚本语言完全解耦。这一点讲师没明说，但 scripts/ 目录的存在已经把这个设计意图露出来了。

2.2 frontmatter 两个字段

📺 03:47–04:07 · IDE 写 YAML name + description 字段

打开 SKILL.md，最顶上是 YAML frontmatter：

两个字段缺一不可，但真正容易翻车的是 name。这个字符串有三处必须完全相等：

  1. 文件夹名 Suggest-Sights/
  2. SKILL.md 里的 name: Suggest-Sights
  3. repo.getSkill("Suggest-Sights") 调用时传的字符串

任何一处不一致，FilesystemSkillRepository 加载时会找不到。description 则是给 Agent 的”路标”——主管 Agent 选哪个 Skill 干活，就看这一句”擅长 XXX”。

2.3 正文三段式

📺 04:07–08:02 · IDE 编写核心能力+工作流程+回答原则三段 Markdown

frontmatter 下面是 Markdown 正文，讲师按三段写：

## 核心能力 —— 这个景点推荐技能列了 4 条：

  1. 免费景点推荐（自然风光 / 历史古迹 + 最佳游览时间 + 避开人群技巧）
  2. 美食探索（特色小吃 + 性价比 + 当地人去的隐秘餐厅）
  3. 打卡点推荐（网红点 + 拍照圣地 + 小众但出片的秘密点）
  4. 住宿建议（经济型 + 舒适型两套方案）

每条能力底下挂 2-3 个 sub-bullet，写法是”做什么 + 用什么标准 + 输出什么”。

## 工作流程 —— 两步：

  1. 分析规划：把距离、时间、费用、景点分布这些因素都过一遍。
  2. 方案输出：吐出景点 + 美食 + 住宿的组合方案。

讲师在这里有个取舍：原本工作流程还应该包含”了解用户个人偏好”这一步，但那就要查数据库、要用户补信息，会把例子搞复杂——所以砍掉了，只留最干的两步骨架。

## 回答原则 —— 三条铁律，约束 LLM 不要漫无边际：

  • 务实优先（可行性 + 费用约束）
  • 信息准确（具体地址、价格区间、开放时间）
  • 因地制宜（看天气预报，下雨晴天不同建议）

2.4 心智模型校准

⏱ 05:57–06:06 · 强调 Skills 是固定流程而非单纯技能，纯讲

讲师在中段重复了一句话：”Skills 并不是一个单纯的技能，它是一整套的固定流程。“

这句话是这集的眼。如果你以为 SKILL.md 只是 name + description 两行 YAML，那你就漏掉了 90% 的信息——正文的核心能力 / 工作流程 / 回答原则才是真正在塑造 Agent 行为的提示词工程。frontmatter 决定”被不被选中”，正文决定”被选中后怎么干”。

3. 没 get 的点

  • references/ 里的酒店文档究竟怎么被读取？是要在 SKILL.md 正文里写路径硬引用，还是框架自动扫描注入？这集只说”放进去就能读”，没演示读取那一刻的代码。
  • weather_check.py 的触发权在谁手里？Agent 自己判断”该查天气了”还是 SKILL.md 工作流程里写死”这一步调脚本”？API key 怎么传也没讲。
  • “务实优先”这种抽象原则，LLM 真的能 buy 吗？还是说要写成”如果方案总价超过用户预算的 80%，需要降级到经济型住宿”这种可判定的规则才稳？这集没回答。
  • 正文三段式（核心能力 / 工作流程 / 回答原则）到底是 AgentScope 的协议要求，还是讲师个人的工程化约定？翻 10-5 应该写的是 SKILL.md 协议层，回头要去对一下。

4. 跟其他集的连接

  • 上承 12-1：12-1 是 SkillBox.registerSkill(...) 把两个技能挂到 TripPlannerAgent，本集把其中一个技能拆开看内部。
  • 上承 10-5：10-5 给的是”YAML frontmatter + scripts + references”的纯理论模板，本集是这套模板第一次落到真实业务场景上。
  • 上承 10-3：10-3 抽象出 Skills 三件套是”专业知识 / 工作流程 / 执行逻辑”，本集的”核心能力 / 工作流程 / 回答原则”就是它的具体化——专业知识 = 4 大核心能力。
  • 下启 12-3：用同一套 SKILL.md 写法去做”表格制作”技能，验证模板可复用。
  • 下启 12-4 / 10-4：description 只是路标这个直觉，对应渐进式加载——Agent 不会一次性把 scripts/references 全读进上下文。
  • 横向 3-8：scripts/weather_check.py 本可以由 MCP 顶替，作者选脚本是为了演示”Skill 自带工具”这条路线。
  • 横向 5-3：5-3 把”角色 + 能力清单”写在 prompt 里，本集写在 SKILL.md 里。本质都是给 Agent 写岗位说明书。

5. 知识地图

6. 自测题（5 卡）

  1. SKILL.md 的 frontmatter 里哪个字段有”三处一致”的强约束？还有哪两处必须等于它？
  2. scripts/ 里能放 Python 脚本吗？Java 项目里这样跨语言会不会有问题？为什么？
  3. 描述这集景点推荐 Skill 的 4 个核心能力，并解释每条能力下挂 sub-bullet 的写法套路。
  4. 工作流程段讲师为什么砍掉了”了解用户偏好”这一步？这反映了什么取舍？
  5. 回答原则段里”务实优先 / 信息准确 / 因地制宜”分别对什么 LLM 行为做了约束？举一个负面例子说明缺了哪一条会怎样。
